# 운영 한도·지원 조건과 후속 검증

2026-10-28 #239 인계 시점에는 #245의 후보군 CLI 구현·로컬 검증이 커밋 `a84b1fbe9eab6411f8372c3754ae3050b51649e0`에 반영돼 있다. [현재 인계와 조건별 평가](kis-data-validation.md#2026-10-28-239-후보군-구현-인계), [후보군 사용법·한계](candidate-universe.md)를 따른다. 이하 #251 보고의 후보군 런타임 구현·검증 대기 설명은 그 보고 당시 상태다. 운영값은 ADR 0014를 유지하며 통합 실연동·추천·제품 인수는 이번 문서 인계의 완료 범위가 아니다.

## 판단 범위와 결론

2026-10-28 [#251](https://github.com/mochafreddo/stock-scout/issues/251)의 종합 보고다. 검토 기준은 `554fdbec6ef5176d602ebd9600907f9406d57c06`과 같은 날 조회한 #237·#239·#243·#244·#245·#246·#248·#249·#250·#259·#261의 본문·댓글이다. 새 KIS·모델 호출 없이 저장된 공식 조사·실제 관측·현재 코드를 대조했다. 이 보고의 산출물은 운영 판단과 제약이며 후보군 CLI 구현이나 제품 인수가 아니다.

**2026-10-28 사용자는 후보군 단계의 첫 운영값을 합의했다.** N=1, H=20개 완료 정규장과 공통 마감·요청 예산의 권위 있는 결정은 [ADR 0014](adr/0014-candidate-runtime-budget.md)에 기록한다. 기존 상한과 작은 표본의 처리 시간으로 전체 후보군의 완료 가능성을 입증한 것은 아니다. 고정 시각의 지원 보장 대신 공식 일정과 실행별 일봉 준비 검사를 결합하며, 이를 구현·검증할 #245는 남아 있다. 보고서와 운영값 합의 완료를 #243·#239 및 후속 추천의 완료와 구분한다.

2026-10-28 조회한 #251 원격 본문은 과거 완료 세션 순위와 지원 시간의 사전 관측 조건을 보존하면서 최신 상태 절에서 후속 합의를 우선하도록 명시한다. 이후 합의한 [ADR 0011](adr/0011-ranking-discovery-and-runtime-data-readiness.md)이 해당 조건을 대체하고, [ADR 0012](adr/0012-bounded-official-calendar-notices.md)·[ADR 0013](adr/0013-llm-calendar-notice-assessment.md)이 공지 완전성의 선행 입증과 코드 전용 해석 조건을 대체한다. 이번 운영값 합의는 로컬 문서에 반영하며 원격 본문·체크 상태를 수정하지 않는다. 후속 원격 갱신에서 ADR 0014의 결정과 남은 런타임 검증을 구분해 반영해야 한다.

### 호출량 계산과 통합 한도

후보 수 U는 거래소·종목 코드 기준으로 중복 제거한 수이며 `0 ≤ U ≤ 6N`이다. 후속 구현에서 종목당 일봉 한 번을 조회한다면 정상 KIS 조회는 `6 + U`회다. 이는 설계 계산이며 측정값이 아니다. 각 조회가 한 번씩 명시적 만료 재조회를 사용할 수 있는 단순 상한은 `2 × (6 + U)`회다. 발급·유형 정보 조회·일정 HTTP·모델 요청은 이 식에 포함하지 않는다. 실제 발급은 공통 300초 정책에 막히면 즉시 실패하므로 모든 재조회가 완료된다는 뜻도 아니다.

| N 선택지 | 최대 U | 순위와 종목당 일봉 1회 | 각 조회에 재조회 1회까지 허용한 계산 |
| --- | --- | --- | --- |
| 1 | 6 | 12 | 24 |
| 5 | 30 | 36 | 72 |
| 10 | 60 | 66 | 132 |

조회 순서는 공식 일정 → 여섯 순위 → 중복 제거·유형 판단 → 포함 종목 일봉 검사 → 출력 직전 개장 경계 확인으로 합의했다. 일봉을 유형 포함 종목에만 조회하면 실제 호출은 줄 수 있으나 통합 경로를 구현한 것은 아니다. H를 한 응답으로 충족하지 못할 때 조용히 기간을 줄이거나 페이지를 늘리는 안도 승인하지 않았다. 순위·일봉 필수 자료가 부족하면 전체 자료 부족으로 종료한다.

후보군 경로는 단계 상한을 단순 합산하지 않고 전체 공통 마감의 남은 시간을 각 단계와 외부 요청에 전달한다. N=1의 최대 6종목에 순위 6회·유형 정보 도구 32회·일봉 최대 6회를 더하면 논리 KIS 조회는 최대 44회다. 각 조회의 명시적 만료 재조회 1회까지 계산한 88회에 발급 최대 2회를 더한 90회가 합의한 KIS 전송 상한이다. 이는 설계 계산이며 실측 호출량·허용 처리율이 아니다. 인증 간격이나 공통 마감에 막히면 더 일찍 실패할 수 있다.

[ADR 0014](adr/0014-candidate-runtime-budget.md)의 공통 마감과 분리된 요청 예산을 #245에서 강제한다. 기존 단계 한도와 새 통합 한도 중 먼저 도달하는 조건을 적용하며 새 재시도는 추가하지 않는다. 개장까지 남은 시간이 부족하면 자동 대기·불완전 성공 대신 실패하며 출력 직전 대상 개장 여부를 다시 판정한다. 추천 단계는 이 후보군 예산에 조용히 추가하지 않고 #240에서 필요 입력과 예산을 다시 결정한다.

## 지원 조건과 후속 인계

지원 정책은 정해진 KST 시각이 아니라 다음 조건의 교집합이다. 공식 일정에서 세 거래소의 직전 완료 세션·다음 대상 세션과 개폐장 시간이 일치하고, 장중이 아니며, 완료 세션까지의 필수 일봉 날짜·기간·필드가 준비돼 있어야 한다. 실행 도중 대상 개장에 도달하면 결과를 내지 않는다. 주말·휴장일도 같은 기준으로 다음 정규장을 판단하고 뉴욕 자정이나 토스증권 예약 접수 시간을 지원 경계로 사용하지 않는다.

이 정책은 [ADR 0011](adr/0011-ranking-discovery-and-runtime-data-readiness.md)의 합의이며 한국 낮 전체의 가용성 보장이 아니다. 준비 미확인이면 자동 대기·재관측 없이 종료한다. 거래소별 준비 시각·연속 가용성·예외일의 가용성은 미측정이며 고정 12:00·15:00 KST 관측이나 공급자 답변을 다시 필수 관문으로 요구하지 않는다. 일정 공지의 제한된 수집·의미 판단 위험도 결과에 전달한다.

| 필수 조건 | 현재 충족 범위 | 후속 작업·차단 여부 |
| --- | --- | --- |
| 보통주·ADR·제외 유형·개별 증권 연결 | #259 흐름과 #261 세 증권 표본은 완료. 전체 유형·실제 순위의 유용성은 미검증. | #245는 검증한 경로를 재사용하고 자료 부족·식별 미확인·유형 미확인을 보수적으로 처리한다. 작은 표본 완료를 전체 종목 적격성 보장으로 사용하지 않는다. |
| 정상 빈 응답·빈 후보군 | 정상 빈 응답의 공급자 의미는 미확인. ADR 0011이 여섯 순위 중 빈 응답의 전체 자료 부족 종료를 정했다. | #245의 CLI·외부 HTTP 회귀에서 빈 순위와 정상 유형 제외 후의 빈 후보군을 구분한다. 전부 미확인은 분석 불충분이며 정상 후보 없음으로 바꾸지 않는다. 빈 응답 실연동을 기다리는 관문은 추가하지 않는다. |
| 완료 세션·일봉 범위 | 공식 필드 사용 가정과 수정주가 미반영을 수용. 순위는 탐색 전용. 날짜·필수 필드의 런타임 검사는 미구현. | #245가 진행 중인 날짜를 제외하고 필요한 날짜·H·가격·거래량을 검사해야 한다. 미확인 단위 환산과 서로 다른 기준 비교를 금지하며 필수 자료 부족은 전체 실패다. |
| 공식 일정 | #244의 독립 도구 구현·모의·실제 작은 표본·전체 실행은 완료. 공지 완전성·의미적 신뢰도는 미검증 운영 가정. | #245에서 공통 세션·장중 거부·출력 직전 개장 경계와 한계 전달을 연결한다. 공지 완전성의 전수 입증을 새 선행 조건으로 추가하지 않는다. |
| N·H·통합 호출·시간 한도 | 후보군 첫 운영값을 ADR 0014로 합의했다. 실측 성능·품질 보장은 아니다. | #251의 값 합의는 완료했다. #245의 공통 예산·마감 강제와 런타임 검증은 남아 있으며, 추천 단계는 #240에서 별도 결정한다. |
| 최종 보고서·사용자 주문 | #239·#245는 후보군, #240은 추천, #242는 제품 인수의 후속 범위다. | 기준 종가·데이터 기준 세션·다음 판단 대상 세션·근거·관찰 기간·위험을 전달하고 소수점 거래 가능 여부는 미확인으로 표시한다. 사용자가 예약 전 확인하며 타입 적격성·일정 성공을 거래·체결 보장으로 확대하지 않는다. |

#239·#245는 합의한 후보군 운영값의 런타임 연결·검증이 남아 검증 완료가 아니다. 후속 추천의 입력·예산과 검증도 별도다. 이 보고로 부모 #243·#239를 완료 처리하거나 제품 인수를 통과시키지 않는다. 반대로 이미 완료된 #244·#249·#259·#261을 과거 미완료 문구만으로 다시 차단하지 않는다. #251의 보고와 후보군 운영값 합의는 완료했으나 원격 명세 반영·체크 평가·종료는 수행하지 않는다.

## 검증 범위

이번 합의의 검토 기준은 `6f6605b3284bf8b8e5e58d7a649ab250fead69e8`과 같은 날 확보한 #251·#237·#239·#243·#245 본문·댓글이다. 문서의 수치·호출량 산식·참조를 승인 내용·ADR·현재 소스와 대조한다. 실행 코드와 테스트는 변경하지 않으며 문구를 고정하는 테스트나 새 TDD·소스 변이는 추가하지 않는다. 공용 검증 경계는 기존 합의인 CLI 입력·stdout·stderr·종료 코드·외부 HTTP를 후속 구현에 유지한다. 새 KIS·모델·유료 호출과 전체 제품 인수는 수행하지 않는다. 이번 로컬 검사의 실행 결과는 커밋 시 작업 보고에 별도로 남긴다.
