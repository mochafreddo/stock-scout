# 후보군 조회 CLI

이 도구는 공식 거래 일정, KIS 탐색 순위와 일봉, 기존 LLM 증권 유형 판단을 연결합니다. 매수 후보 선정·추천은 하지 않습니다. [#245](https://github.com/mochafreddo/stock-scout/issues/245)의 현재 구현 계약은 [ADR 0011](adr/0011-ranking-discovery-and-runtime-data-readiness.md)부터 [ADR 0014](adr/0014-candidate-runtime-budget.md)까지의 후속 합의를 따릅니다.

## 실행하기

Node.js 24 이상, 설치된 잠금 파일의 의존성, `/usr/bin/xmllint`, `pdftotext`, 기존 KIS 자격 증명과 Stock Scout 전용 SIWC 인증이 필요합니다. 인증 준비는 [KIS 인증 안내](kis-auth.md)와 [SIWC 연결 안내](llm-security-probe.md#공식-구독-인증-연결하기)를 따르세요. 비밀 값을 명령 인수에 쓰지 마세요.

```sh
node scripts/candidate-universe.ts --auth-dir /absolute/private/stock-scout --model gpt-6.1-sol
```

모델과 인증 디렉터리를 명시하세요. 과거 시각 지정, 탐색 수·기간·예산 확대, 자동 재로그인과 유료 API 전환은 제공하지 않습니다. 기존 인증 정책에서 허용한 갱신과 KIS의 명시적 만료 재조회만 사용합니다. KIS 발급 간격 때문에 실행할 수 없다면 자동 대기하지 않고 실패합니다.

`--model`은 일정·유형 판단의 기본값입니다. 선택 인수 `--calendar-model`과 `--type-model`로 해당 단계만 덮어쓸 수 있습니다. 독립 일정·유형 CLI는 기존 `--model`을 사용합니다. 단계별 선택과 공용 도구 변경의 범위는 [보고서 완료 개선 설계](buy-candidate-completion-design.md)를 따릅니다.

## 자료 확인 순서

1. 공식 연간 일정과 제한된 공지를 읽어 세 거래소의 공통 데이터 기준 세션과 다음 판단 대상 세션을 정합니다. 장중에는 거부합니다.
2. NAS·NYS·AMS의 거래량·거래대금 여섯 순위에서 각각 첫 페이지의 상위 1개를 탐색합니다. 원래 순위·수치·조회 시각을 보존하고, 제외·중복 제거 뒤 다른 종목으로 보충하지 않습니다.
3. 상장 종목 단위로 중복을 제거하고 기존 유형 판단으로 보통주·보통주 성격 ADR을 포함합니다. 회사가 같아도 서로 다른 주식 종류·ADR은 별도 종목입니다. 미확인·비적격 종목은 이유와 함께 제외합니다.
4. 포함 종목의 KIS 일봉을 조회해 공식 일정상 최근 20개 완료 세션의 날짜·가격·거래량을 검사합니다. 진행 중인 날짜의 행을 분석에 사용하지 않습니다. 기간이 부족해도 페이지를 늘리거나 기간을 줄이지 않습니다.
5. 출력 직전에 공통 마감과 대상 개장 도달 여부를 다시 확인합니다.

순위는 조회 당시의 탐색 자료입니다. 완료 정규장 순위나 전체 시장 순위로 해석하지 마세요. 일봉은 공식 필드 정의에 따른 승인된 운영 가정으로 사용하며 수정주가를 반영하지 않습니다. 정규장 전용 집계를 독립적으로 입증한 결과가 아니고, 미확인 단위·배율을 환산하지 않습니다.

## 결과와 실패 확인하기

정상 결과는 stdout의 JSON 하나입니다. 데이터 기준 세션과 판단 대상 세션, 후보군·제외 이유, 원래 탐색 순위와 수치·시각, 필요한 일봉과 공식 일정의 출처·한계를 함께 확인하세요. 정상 조회 뒤 확인된 비적격 종목만 남으면 빈 후보군으로 정상 종료합니다. 모든 종목을 확인하지 못한 분석 불충분은 정상 빈 후보군과 구분합니다.

| 필드 | 의미 |
| --- | --- |
| `status` | 후보가 있는 `candidate_universe` 또는 정상 빈 후보군인 `empty_candidate_universe` |
| `dataSession`, `targetSession` | 직전 완료 정규장과 판단 대상인 다음 정규장의 날짜·개장·폐장 |
| `historyDates` | 공식 일정에서 정한 일봉 필수 날짜 |
| `securities`, `excluded` | 포함 종목의 유형 판단·원래 순위·일봉과 제외 종목의 근거·이유 |
| `observations` | 여섯 탐색 순위의 출처·요청 조건·조회 시각·행 수 |
| `calendar`, `typeAssessment` | 기존 일정·유형 도구의 판단과 미검증 한계 |
| `limits`, `usage` | 실행 상한과 실제 전송 시도 집계 |

여섯 순위 중 빈 응답, 필수 일봉 누락·잘못된 날짜나 필드, 세 거래소의 세션 불일치, 일정·인증·모델·통신 실패, 호출·실행 한도 초과는 전체 실패입니다. 실패 시 부분 후보군을 정상 결과로 출력하지 않습니다. stderr의 구조화 오류와 종료 코드를 확인하세요.

정상 후보군과 정상 빈 후보군의 종료 코드는 0, 분석 불충분은 2, 나머지 실패는 1입니다. `MARKET_ACTIVE`는 장중 시작, `TARGET_OPEN`은 실행 중 대상 개장 도달, `DATA_NOT_READY`는 필수 일봉 준비 실패를 뜻합니다. 오류에는 실패 단계와 전송 집계가 포함됩니다. 분석 불충분도 stdout에 부분 후보군을 출력하지 않습니다.

실패의 `diagnostic.elapsedMs`는 CLI 전체 경과 시간이며 `diagnostic.typeAssessment.statistics.elapsedMs`는 유형 판단에 걸린 시간입니다. 유형 판단을 시작하지 않았으면 상태는 `not_started`, 시간은 `null`, 호출 수는 0입니다. `typeAssessment`의 `cause`·`lastProgress`와 `requests`에서 관측한 중단 사유·마지막 진행 단계·모델 요청별 시간·HTTP 상태·완료 이벤트 수·종료 상태를 확인하세요. 요청 시간은 응답 헤더 수신에서 끝나지 않고 스트림 종료·중단까지 포함합니다. 확인하지 못한 상태는 `unknown` 또는 `null`로 남기며 요청 수를 완료 응답 수로 해석하지 마세요. 상세 의미와 한계는 [유형 판단 진단 안내](llm-security-probe.md#유형-판단의-요청별-진단-읽기)를 따릅니다.

공통 마감은 작업 시작부터 600초와 판단 대상 개장 중 이른 시각입니다. 실제 전송 시도를 KIS·공식 일정 HTTP·일정 모델·유형 모델·SIWC 갱신으로 나누어 제한하고 기존 단계별 한도도 적용합니다. 합의값의 권위는 [ADR 0014](adr/0014-candidate-runtime-budget.md)입니다. 실패한 전송과 허용된 재조회도 세며 서버 내부 웹 요청 수를 사전에 보장하지 않습니다.

실패의 `observation.summaries.stages`·`modelRequests`는 상세 기록이 잘려도 단계·모델 요청 요약을 보존합니다. 시작 시 `executionRemainingMs`·`stageRemainingMs`·`requestRemainingMs`를 함께 확인해 전체 마감과 공유 단계 제한을 구분하세요. 미관측 값은 `null`이며 단계·부모·자식의 중첩 시간을 합산하지 않습니다. 입력 규모와 요약의 자세한 의미는 [공통 요약 계약](rca-observability-design.md#2026-10-31-시간예산-요약-보강)을 따릅니다.

## 검증 범위와 한계

공식 공지 수집 완전성과 모델의 의미적 신뢰도는 계속 `unverified`입니다. 제한된 현재 공지 밖의 변경과 모델 오판을 놓칠 수 있습니다. 후보군 출력은 한국 낮 전체의 데이터 가용성이나 토스증권 거래·예약·체결을 보장하지 않습니다. 주말·휴장일도 공식 일정과 필요한 일봉이 준비된 경우에만 다음 정규장을 판단 대상으로 삼습니다.

공개 검증 경계는 CLI 인수·stdout·stderr·종료 코드와 외부 HTTP입니다. 외부 통신과 시간을 대체한 회귀 검사는 실제 공급자 의미·모델 정확도·실제 후보군 실행의 검증과 구분합니다. 선행 도구의 실연동 근거는 [KIS 검증 기록](kis-data-validation.md), [일정 검증 기록](market-calendar-validation.md), [유형 표본 평가](security-type-evaluation-samples.md)에 있습니다. 이 도구의 통합 실연동과 최종 매수 추천·제품 인수는 별도 검증 대상입니다.
