# 실제 구독 인증 갱신·재사용 검증 기록

2026-10-21 [#253](https://github.com/mochafreddo/stock-scout/issues/253)의 최종 소스에서 실제 갱신·모델 목록 조회 성공과 다음 별도 프로세스의 갱신 없는 재사용·조회 성공을 연속으로 확인했다. 정책과 범위는 [확정 설계](siwc-refresh-live-validation-design.md), 실행별 시각·출력·입력 지문은 [선별 증거](evidence/issue-253/live-validation.json)를 따른다. 아래의 수정 전 갱신과 수정 후 재사용 기록은 당시의 부분 검증으로 보존한다.

## 최종 소스의 연속 실연동 완료

커밋 `222b9d3c35c5781327d0453e3eb6964fefc993b6`의 인증 모듈과 실행 설정을 고정하고 기존 승인 보관소의 만료·서버 허용 시각을 다시 확인했다. 2026-10-21 16:09 KST 기준 액세스 토큰은 이미 만료됐고 서버의 갱신 허용 시각도 지났다. 만료 시각 조작·인증 복사·재로그인 없이 기존 `check` CLI를 두 별도 프로세스에서 연속 실행했다. 런타임 코드는 변경하지 않았다.

첫 프로세스는 갱신 요청 1회, 새 액세스·갱신 토큰 변경, 응답 검증·원자적 저장·저장값 대조 성공과 표시 모델 7개의 목록 조회 성공을 기록했다. 직후 두 번째 프로세스는 갱신 요청 0회, 저장된 토큰·만료 정보 유지와 표시 모델 7개의 목록 조회 성공을 기록했다. 두 실행 모두 종료 코드 0이며 stderr는 비어 있었다. 실행 전후 입력 지문이 일치했다. 세부 증거는 `finalSourceContinuousRefreshAndReuse`에 기록했다.

이는 최종 소스에서 구독 인증 갱신과 별도 프로세스 재사용을 확인한 결과다. 추론 모델은 선택하지 않았으며 추론·검색·유형 정확도나 전체 제품 인수로 확대하지 않는다. 실제 동시 회전·토큰 무효화·응답 유실·저장 장애·강제 종료도 유발하지 않았다.

## 실제 관측

승인된 기존 보관 위치에서 만료 시각을 조작하거나 인증을 다른 위치에 복사하지 않고 실행했다. 브라우저 재로그인은 없었다. 명령은 `node scripts/siwc-auth.ts check <approved-auth-dir>`이며 작업 디렉터리는 저장소 루트다. Node.js는 `v26.11.1`이고 추론 모델은 선택하지 않았다. 구독 요청은 공식 `GET /v1/models`다. 토큰 비교는 메모리에서 수행했고 증거에는 불리언과 시각만 남겼다.

| 단계 | 결과 | 입증 범위 |
| --- | --- | --- |
| 크기 수정 전 첫 CLI | 종료 코드 1, `siwc_invalid_response` | 갱신 요청 1회, 새 액세스·갱신 토큰의 변경, 응답 검증·원자적 저장·저장값 대조 성공을 관측했다. 이후 목록 조회는 실패했다. |

최종 두 실행은 2026-10-21 14:11:22~14:11:24 KST에 수행했다. 두 프로세스의 stdout은 각각 JSON 477바이트이고 stderr는 비어 있었다. 실행 전후 소스 지문이 일치했다. 최종 인증 모듈의 SHA-256은 `33f1b6a95513b67ba6bb7df272b604e5b925ee6415a260a3797b644cfff010f5`이며 나머지 검사 입력의 지문은 선별 증거에 있다. 계정 식별자·개인 보관 경로·토큰 원문·토큰 해시는 공유 증거에 포함하지 않는다.

## 수정과 모의 검증

모델 목록에만 1MiB 상한을 적용하고 기존 인증 응답은 128KiB 상한을 유지했다. 크기는 UTF-8 바이트로 검사한다. 정상 대형 목록의 회귀 검사는 수정 전 실패와 수정 후 통과를 확인했다. 기존 목록 크기 초과 사례의 입력은 실제 정상 응답이 옛 상한보다 컸다는 관측과 새 상한에 맞춰 1MiB 초과의 유효한 JSON으로 변경했다. 실패 기대값은 유지하며 인증 응답의 기존 크기 초과 검사도 유지한다.

최종 고정 소스에서 `npm run check`, `npm run typecheck`, 전체 모의 회귀 `npm test`의 155개가 통과했다. 실패·건너뜀은 0개다. 새 위험 로직의 음성 대조 13개는 갱신 횟수 누락, 저장값 대조의 각 필드 누락, 빈 목록 거부, 잘못된 목록 허용, 제한 시간·취소 신호 누락, 표시 필터 누락, 불필요한 중복 갱신, 크기 상한 누락, 문자 수로 잘못 계산한 크기와 옛 상한 복원을 모두 탐지했다. 요청 대기와 본문 수신의 제한 시간 검사를 독립 사례로 확인했다.

기준 `21a40607ac59638375bbca88c7b97505c4e48cd4`를 유지하고 이번 추가 변경을 Standards·Spec 두 축으로 검토했다. 시간 제한 테스트의 거짓 양성 지적을 수정한 뒤 최종 두 축의 남은 지적은 각각 0건이다. 리뷰어 역할 선택은 확인했지만 실제 모델·추론 수준·권한 강제는 독립 검증하지 않았다. 실제 목록 크기 문제 수정 후 필요한 전체 회귀와 음성 대조를 다시 실행했으며 수정 전 통과 결과만으로 최종 소스를 검증했다고 보고하지 않는다.

## 이전 실행의 미완료 조건과 재개 기록

14:11 KST 실행 당시에는 최종 소스의 자연스러운 갱신 1회, 같은 실행의 목록 조회 성공, 다음 별도 프로세스의 갱신 없는 재사용을 연속으로 확인하는 조건이 남았다. 관측한 액세스 토큰 만료는 2026-10-21 15:06:25.706 KST이고 서버의 갱신 가능 시각은 15:00:27 KST였다. 실행 전 5분 기준을 함께 적용한 다음 시점은 15:01:25.706 KST였다. 이는 당시 관측값이며 현재 재개 조건이 아니다. 장시간 대기·반복 조회·예약 실행은 추가하지 않았다.

재개 절차는 승인된 같은 보관 위치와 최종 실행 소스의 동일성을 확인하고 명령을 별도 프로세스에서 두 번 실행하는 것이었다. 위의 16:09 KST 연속 실연동에서 이 조건을 충족했다. 이전 실패를 재로그인이나 인증 초기화로 덮지 않았다.

실제 동시 회전·갱신 토큰 무효화·응답 유실·저장 장애·강제 종료는 이번 실제 검증에서 유발하지 않았다. 해당 조건의 모의 검사와 실제 서비스 검증은 구분한다. 추론·검색·종목 유형 정확도·KIS 데이터·일정·운영값·매수 보고서·유료 API 전환은 인수하지 않았고 기존 제품 차단을 유지한다. GitHub 이슈의 본문·체크 상태·열림 상태는 변경하지 않았다.
