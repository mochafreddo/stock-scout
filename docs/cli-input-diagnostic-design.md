# 유형 판단 CLI의 기본 진단과 입력 실패 범위

[#268](https://github.com/mochafreddo/stock-scout/issues/268)의 2026-10-21 설계 인터뷰 기록이다. 상위 [#265](https://github.com/mochafreddo/stock-scout/issues/265)와 [입력·초기 인증 설계](cli-input-auth-diagnostic-design.md), [공통 진단 설계](cli-failure-diagnostic-design.md)를 따른다. 사용자는 Q1·Q2의 추천안을 모두 수락하고 Q3에서 작업 범위·공개 검증 경계·리뷰 기준을 확정했다. 이어 `to-spec`으로 #268 명세 게시와 `ready-for-agent` 라벨 적용을 요청했다. 게시 요청과 실제 반영 성공은 구분한다.

## 확정 사항

Q1에서 인수 오류와 평가 파일 읽기·JSON 파싱·내용 검사 실패를 이번 티켓에서 세분화하지 않기로 했다. 기존 오류 코드 `USAGE`는 여러 조건을 묶으므로 해당 입력 실패의 진단은 `stage: "input"`, `reason: "unknown"`으로 제공한다. 예상하지 못한 입력 처리 예외도 확인된 `input` 단계를 유지하고 원인은 `unknown`이다. 기존 오류 코드·검증 순서·최초 실패 동작을 유지하며 상세 원인 구분은 후속 범위로 둔다.

Q2에서 이번 티켓의 입력 실패는 모두 `location: null`로 제공하기로 했다. 평가 파일의 잘못된 종목 위치를 알고 있어도 `securities[1].symbol` 같은 입력 경로나 인수 위치·파일 경로를 추가하지 않는다. 상위 계약의 안전한 응답 배열·필드 경로를 입력 위치 계약으로 확대하지 않는다.

## 유지하는 계약

유형 판단 CLI가 처리할 수 있는 모든 실패의 기존 stderr JSON에 별도 옵션 없이 `diagnostic`을 추가하고 `stage`·`reason`·`location` 세 필드를 항상 제공한다. 초기 인증과 순위·조회·판단·출력 경로의 실제 단계 전달은 이번 범위에 포함하지 않으며 그전에는 기본 `unknown` 단계를 제공한다. 초기 인증의 동적 import 실패를 `authentication`으로 전달하는 작업도 후속 티켓 범위다. #265의 전체 계약을 이번 티켓의 완료 조건으로 확대하지 않는다.

코드가 확인한 안전한 고정 원인만 제공하고 재사용하는 식별자의 철자를 유지한다. 여러 조건을 묶은 오류와 미등록 예외는 `reason: "unknown"`이다. 외부 메시지의 내용이나 접두사만으로 원인을 확정하지 않는다. 모델 원문·외부 메시지·인증 값·개인 경로·동적 필드명과 값을 진단에 넣지 않는다.

기존 stderr 필드·오류 코드·종료 코드·실패 stdout·성공 출력과 정상 분석 불충분, 인증 재시도 시각·로그인 안내를 보존한다. 독립된 인증·KIS 관측 CLI의 출력 계약은 변경하지 않는다. 기존 근거 검사·호출·시간 한도를 유지하며 진단을 위한 추가 모델 호출·조회·재시도를 하지 않는다. 실행 전 런타임·정적 모듈 로딩 실패·강제 종료·진단 출력 자체의 실패는 보장 범위 밖이며 별도 실행기를 추가하지 않는다.

## 최종 확정과 게시 범위

저장소는 stock-scout 한 곳이다. 이번 작업은 이 로컬 설계 문서와 #268 본문·`ready-for-agent` 라벨의 명세 게시 범위이며 구현·실연동·커밋·푸시·이슈 종료는 포함하지 않는다. 기존 미커밋 설계 작업은 별도로 보존한다. 입력 진단은 일반적인 프로그래밍 개념이므로 용어집에 추가하지 않으며 이번 세부 결정은 별도 ADR로 만들지 않는다.

2026-10-21 #268 명세를 게시하고 원격 본문과 제안 본문의 정확한 일치를 확인했다. 기존 `ready-for-agent` 라벨과 OPEN 상태를 유지했다. 기존 완료 조건 여덟 개의 문구·순서·미완료 상태를 보존하고 Q1·Q2를 구체화한 두 조건을 추가했으며 열 조건 모두 미완료다. 이번 작업은 설계·명세 게시에 한정하여 코드 테스트·실연동·커밋·푸시는 수행하지 않았다.

향후 구현의 공개 검증 경계는 CLI 입력·stdout·stderr·종료 코드와 외부 HTTP 요청이다. 기존 Node.js CLI 프로세스·외부 HTTP 모의 검사 선례를 재사용한다. 인수·평가 파일의 대표 실패와 미등록 예외, 외부 메시지의 식별자·접두사 흉내, 후속 경로의 기본 진단과 기존 성공·실패 계약을 확인한다. 입력 실패 뒤 외부 요청이 진행되지 않고 외부 부수 효과는 요청 인자까지 검증한다. 내부 함수 배치나 문서 문구를 고정하지 않는다.

향후 구현은 #268의 수정 전 회귀 실패·필요한 형식·린트·타입·전체 테스트·위험 로직 음성 대조와 고정 변경본의 Standards·Spec 리뷰를 따른다. 모의 검사와 실제 KIS·OpenAI 동작을 구분한다. 실제 실패 진단·고정 표본 평가·실연동과 #250·#262·#265 전체 완료 선언은 범위 밖이며 Actions는 비활성 상태를 유지한다.

인터뷰 시작 HEAD와 티켓상 리뷰 기준점은 `41a4188e0413a95dc6757658c1e4d99a492f8859`다. 이번 문서 검토 범위는 이 파일과 갱신 전 #268 원문이며 기존 미커밋 문서는 제외한다. 구현 시작 시 선행 티켓과 동시 변경을 구분하고 관련 변경을 고정한다.

## 확인한 현재 동작

소스 조사에서 `scripts/llm-security-probe.ts`의 인수·평가 파일 읽기·파싱·내용 검사 실패가 `USAGE`로 모이며 최상위 stderr에는 아직 진단 객체가 없음을 확인했다. 초기 SIWC 동적 import와 자격 증명 읽기는 입력 검사 뒤에 실행된다. 기존 공개 CLI 프로세스 검사는 입력 실패와 외부 HTTP 요청을 검증하는 경계를 제공한다. 이는 읽기 전용 소스 조사이며 코드 테스트나 실제 서비스 실행 결과가 아니다.
