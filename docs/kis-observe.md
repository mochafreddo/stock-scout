# KIS 관측 실행 기록

관측 응답과 해당 응답을 만든 프로세스의 실행 결과를 함께 남기려면 `scripts/kis-observe.ts`를 사용하세요. 기존 [관측 CLI](kis-probe-reference.md)를 한 번 호출하며, 후보군이나 추천을 만들지 않습니다. **기록 저장 성공은 KIS 데이터 의미·종목 유형·장전 지원의 검증 완료가 아닙니다.**

## 실행하기

```text
node scripts/kis-observe.ts <new-directory> <volume|amount> <NAS|NYS|AMS>
node scripts/kis-observe.ts <new-directory> <daily|info> <NAS|NYS|AMS> <symbol>
```

첫 인수는 아직 존재하지 않는 전용 디렉터리입니다. 부모 디렉터리는 미리 준비하되 대상 디렉터리 자체는 만들지 마세요. 기존 파일·디렉터리·심볼릭 링크는 덮어쓰지 않습니다. 모드·거래소·종목 입력은 기존 CLI의 범위와 같으며 임의 명령이나 추가 옵션을 실행하지 않습니다.

실제 조회에는 프로세스 환경의 `KIS_APP_KEY`와 `KIS_APP_SECRET`이 필요합니다. 이 도구는 `.env`나 다른 자격 증명 파일을 읽지 않습니다. 기존 [공용 인증과 복구](kis-auth.md)를 사용하므로 캐시·발급 제한·명시적 만료 복구 정책도 같습니다. 프로그램 구현·모의 검사 승인을 실제 인증·조회 승인으로 취급하지 마세요.

실제 서비스 관측이 승인된 경우에만 다음과 같이 실행하세요. 이름의 시각은 구분용 예시이며 데이터 기준 세션이 아닙니다.

```sh
node scripts/kis-observe.ts /private/tmp/stock-scout-observation-20261019 info NAS AAPL
```

기록 디렉터리는 저장소 밖의 동기화되지 않는 위치에 두세요. 한 호출에서 모드 하나만 실행하며, 순위 페이지 반복·표본 순회·추가 재시도·자동 대기는 하지 않습니다. 기존 CLI 내부의 승인된 인증 복구는 유지합니다.

## 저장 결과 확인하기

성공하면 stdout에 `receipt`와 `response`의 절대 경로를 담은 JSON 하나를 출력하고 종료 코드 0으로 끝납니다. 디렉터리는 700, 파일은 600 권한입니다.

| 파일 | 내용 |
| --- | --- |
| `response.json` | 기존 관측 CLI가 출력한 응답 바이트입니다. `validation: unverified`, `dataSession: null`을 유지하며 시장 데이터를 해석하거나 재분류하지 않습니다. |
| `receipt.json` | 실행 조건·결과와 응답 파일의 해시를 연결한 기록입니다. 응답 저장 뒤 마지막에 확정합니다. |

실행 기록은 다음 항목을 포함합니다.

| 항목 | 의미 |
| --- | --- |
| `schemaVersion`, `status` | 기록 형식 버전과 `success` 또는 `failure` |
| `args` | 검증한 모드·거래소·선택적 종목 인수 |
| `startedAt`, `endedAt` | UTC 실행 시작·종료 시각이며 데이터 기준 세션과 다릅니다. |
| `child.exitCode`, `child.signal` | 기존 관측 CLI 프로세스의 종료 결과 |
| `source.revision`, `source.files` | 실행 도구의 Git 리비전과 관측 도구·probe·인증·공통 실행 소스의 SHA-256 |
| `runtime.node` | 실행한 Node.js 버전 |
| `response` | 성공 시 `response.json` 경로와 SHA-256, 실패 시 null |
| `error` | 실패 시 허용한 오류 코드 |

probe와 인증·공통 실행 소스는 전용 임시 디렉터리에 복사한 바이트를 해시하고 실행합니다. 해당 임시 사본만 종료 시 정리하며 인증 캐시나 잠금에는 손대지 않습니다. 리비전과 파일 해시를 함께 보관하므로 커밋 번호만으로 소스가 같다고 추정할 필요가 없습니다. 해시는 이후 파일 변경을 대조하는 수단이며 공급자 응답의 진실성이나 기록의 위조 방지를 보장하지 않습니다.

환경 변수 전체·앱 키·시크릿·토큰·원문 인증 헤더·원문 stderr·원문 예외는 저장하지 않습니다. 응답에 포함된 관측 필드만 공유할 수 있는지는 별도로 검토하세요.

## 실패와 제한

실패하면 stdout은 비어 있고 stderr에 허용한 오류 코드와, 안전한 실패 기록을 저장한 경우에만 그 경로를 출력하며 종료 코드는 1입니다. 디렉터리·기록 파일을 안전하게 만들지 못하면 기록 없이 오류 코드만 반환할 수 있습니다.

| 오류 | 의미 |
| --- | --- |
| `USAGE` | 디렉터리·모드·거래소·종목·추가 인수가 입력 조건에 맞지 않음 |
| `OBSERVATION_STORAGE` | 디렉터리·파일의 안전한 생성 또는 저장 실패 |
| `SOURCE_FAILED` | 소스·리비전을 확인하거나 실행 소스 사본을 준비하지 못함 |
| `CHILD_TIMEOUT` | 바깥 실행 제한 90초 초과 |
| `CHILD_FAILED` | 자식 프로세스의 비정상 종료 등 허용 코드로 설명할 수 없는 실행 실패 |
| `CHILD_OUTPUT` | 자식 출력이 허용한 성공·오류 형식에 맞지 않음 |
| 기존 관측·인증 오류 | [관측 CLI 레퍼런스](kis-probe-reference.md)의 허용 코드 |

90초 제한을 넘으면 자식 프로세스를 종료합니다. 발급 중 종료되어 인증 잠금이 남을 수 있으므로 기존 인증 복구 안내를 따르세요. 기록 도구가 잠금·캐시·발급 기록을 자동 삭제하거나 발급 제한을 초기화하지 않습니다.

서비스 조회가 성공해도 응답이나 최종 기록 저장에 실패하면 전체 수집은 실패입니다. 최종 성공 기록이 없거나 실패 기록인 디렉터리의 `response.json`만 보고 성공으로 판단하지 마세요. 기존 디렉터리를 재사용하지 말고 원인을 확인한 뒤 새 경로로 실행하세요.

모의 검사는 관측용 CLI의 인수·입출력·종료 결과·생성 파일과 외부 HTTP·프로세스·저장 실패를 확인합니다. 실제 KIS 호출과 장전 지원·종목 유형 판별 검증은 별도이며, 이번 도구 구현의 검증에는 포함하지 않습니다.

## 실제 장전 관측의 확인 범위
