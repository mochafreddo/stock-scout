# 로컬 조회 준비 점검 구현 기록

2026-11-16 [#335](https://github.com/mochafreddo/stock-scout/issues/335)의 합의에 따라 [#336](https://github.com/mochafreddo/stock-scout/issues/336)의 복구 인계, [#337](https://github.com/mochafreddo/stock-scout/issues/337)의 로컬 점검 명령, [#338](https://github.com/mochafreddo/stock-scout/issues/338)의 합성 소비 흐름을 연결했다. 사용자가 전달한 dots 오류 보고가 출발점이며, 해당 원본 실행이나 실제 보호 상태를 직접 관측했다는 뜻은 아니다.

현재 명령·출력·오류의 기준은 [CLI 레퍼런스](toss-cli.md), 소비 순서와 실행 예시는 [에이전트 사용 지침](toss-agent-usage.md), 운영 복구의 전제와 승인 절차는 [복구 안내](auth-recovery.md)에 있다. 이 기록은 별도의 사용 계약을 유지하지 않는다. 용어는 [용어집](../GLOSSARY.md)을 따른다. 기존 책임 경계를 유지하는 확장이므로 새 ADR은 추가하지 않았다.

## 구현과 검증 경계

공통 클라이언트의 기존 설정·저장소·상태·시계 검증을 재사용하는 `readiness` 명령을 제공한다. 외부 에이전트가 점검 결과와 실제 조회 결과를 각각 해석하며, CLI 내부에 예약 실행·서버·투자 판단을 추가하지 않는다. 상태 형식 변경이나 자동 전환은 없다.

기존 합성 실행기는 실제 CLI 인수·stdout JSON·stderr·종료 코드와 외부 HTTP 경계를 사용한다. 준비 통과 후 가격 조회 성공, 전환 필요 시 중단, 준비 통과 후 공급자 오류, 점검과 조회 사이의 합성 상태 변경을 실행한다. 준비 통과가 이후 조회의 검증을 생략하지 않으며, 오류의 빈 자료·안전한 오류 세부 정보·종료 코드를 보존하는지 검사한다. 점검의 파일 부작용 검사는 합성 보호 디렉터리의 목록·내용·권한·명시적 변경 시각을 비교하며, 읽기로 갱신될 수 있는 접근 시각은 제외한다.

합성 결과는 공급자 인증·권한·IP 허용, 계좌 유효성과 조회 범위, 자료 최신성·가용성 또는 dots의 실제 준수를 검증하지 않는다. 점검은 원자적 전체 상태 스냅샷이 아니며 동시 실행으로 이후 상태가 바뀔 수 있다. 조회 실패의 기본 보고는 자료 부족에 따른 종목별 판단 보류이고, 관망 권고에는 별도의 투자 근거가 필요하다.

## 운영 보류와 재개 조건

실제 보호 상태 열람·변경, 운영 복구, 토스 시장·계좌 조회와 dots 관측은 이번 합성 구현에서 수행하지 않았다. 해당 작업의 승인과 운영 전제 확인이 없으므로 성공으로 표시하지 않는다. 재개하려면 복구 안내에 따라 관련 구형·신형 실행기 종료, 공급자 대기 완료, 대상과 최소 변경안에 대한 별도 승인을 확인한다. 대기를 확인할 수 없으면 전환과 조회를 보류한다.

승인 후 복구는 예약 필드만 최소한으로 전환하고 나머지 보호 상태를 보존한다. 이후 별도로 승인된 시장 조회 한 건의 성공을 보유·미체결 주문 조회 검증으로 확대하지 않는다. 실제 소비 검증은 해당 소비 환경의 접근·자료 전달 범위를 확인한 뒤 명령 발견, 실행, 종료 코드와 중단 안내를 각각 관측해야 한다. dots 설정 변경이나 새 예약 실행은 이 구현에 포함하지 않았다.
