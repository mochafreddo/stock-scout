# 매수 후보 보고서 실행하기

공식 거래 일정과 기존 후보군 검사를 통과한 종목을 ChatGPT 구독 모델로 검토합니다. 직전에 끝난 미국 정규장까지의 KIS 일봉을 바탕으로 다음 정규장의 매수 검토 후보를 최대 5개 출력합니다. 검토할 후보가 없으면 후보 없음으로 표시합니다. 주문과 예약 등록은 직접 하세요.


## 준비와 실행

[실행 환경과 인증 준비](getting-started.md#매수-후보-보고서-준비하기)를 마치세요. 이미 승인한 저장소 밖 SIWC 인증 디렉터리와 해당 계정에서 이용할 수 있는 모델을 지정하세요. 기존 계정의 `gpt-6.1-sol`을 첫 모델로 선택했습니다. 일정 판단에서 전체 공지 입력을 처리한 기존 실연동 근거가 있으며, 이 선택이 추천 품질을 보장하는 것은 아닙니다. 모델 접근은 실제 실행 계정에 따라 달라질 수 있습니다.

```sh
node --env-file=.env scripts/buy-candidates.ts --auth-dir /absolute/private/stock-scout --model gpt-6.1-sol
```

`--model`은 모든 단계의 기본 모델입니다. `--calendar-model`과 `--type-model`을 지정하면 각각 일정·유형 판단에만 적용합니다. 후보 선정과 별도 의미 검토는 `--model`을 사용합니다. 지정한 모델을 사용할 수 없어도 자동으로 교체하지 않습니다. 실제 모델은 `sourceUniverse.calendar.noticeAssessment.model`, `sourceUniverse.typeAssessment.model.id`, 보고서의 `model.id`에서 각각 확인하세요.



KIS 환경 변수가 이미 있으면 `--env-file=.env`를 생략하세요. 토큰·키를 명령 인수에 넣지 마세요. 새 로그인·운영 한도 확대는 제공하지 않습니다. 유료 전환 범위는 아래 안내를 확인하세요. 기존 인증 정책이 허용한 갱신·명시적 KIS 만료 복구와 아래 `EGW00316` 조회 재시도만 사용하며, 그 밖의 자동 대기·재실행은 하지 않습니다.

장중에는 실행을 거부합니다. 주말·휴장일에는 공식 일정과 필요한 데이터가 준비된 경우 다음 정규장을 대상으로 검토합니다. 한국 낮 전체의 데이터 가용성을 보장하지 않습니다.

## 구독 한도 소진 시 유료 전환

후보 선정·의미 검토에서 공식 구독 한도 소진을 확인하면 같은 모델의 OpenAI API로 전환합니다. 승인된 저장소 밖 보관소에서 별도 API 키를 `OPENAI_API_KEY` 환경 변수로 제공하세요. 키를 인수에 넣지 마세요. 키가 없으면 `PAID_CREDENTIALS_MISSING`과 설정 안내를 출력합니다. 인증·통신 오류나 일반 속도 제한은 유료 전환하지 않습니다.

일정·유형 단계는 구독만 사용합니다. 이 단계에서 구독 한도가 소진되거나 비용을 보장할 수 없으면 실행이 끝나며 유료 API로 보고서 전체를 완성했다고 보지 마세요. 새 로그인이나 한도 확대는 제공하지 않습니다.

전환 후 `model.authentication: openai_api`, `paid.switched: true`와 `paid.requests`, `paid.reservedUsd`, `paid.limitUsd: 1`을 확인하세요. 실패 출력에도 비용 집계가 남습니다. 확보한 비용은 실제 청구액이 아니며, 실패하거나 사용량을 알 수 없어도 반환하지 않습니다. 구독 실패 요청을 포함한 전체 모델 요청 수와 완료 수는 전환 시 서로 다를 수 있습니다.

공식 토큰 계수·알려진 모델 가격·출력 상한으로 다음 요청의 최대 비용을 확보합니다. 알려지지 않은 모델, 계수 실패·입력 32,000토큰 초과는 `PAID_BUDGET_UNPROVABLE`, 남은 요청과 의미 검토까지 예산이 부족하면 `PAID_BUDGET_EXCEEDED`로 실패합니다. 입력을 줄이거나 모델·상한을 자동 변경하지 않습니다. 기존 시간·요청·개장 경계와 완료 판정을 그대로 적용합니다. 자세한 비용 근거와 범위는 [ADR 0016](adr/0016-bounded-paid-recommendation.md)을 확인하세요.

## 보고서 확인

정상 결과는 stdout의 JSON 하나이며 종료 코드는 0입니다. `status`가 `buy_candidates`이면 후보를, `no_candidates`이면 후보가 없는 이유를 확인하세요. 충분한 근거가 없으면 억지로 후보 수를 채우지 않습니다.

| 필드 | 확인할 내용 |
| --- | --- |
| `dataSession`, `targetSession` | 완료된 데이터 기준 세션과 다음 판단 대상 세션 |
| `candidates` | 거래소·종목 코드·회사명·선정 이유·근거 수치·관찰 기간과 이유·주요 위험 |
| `referenceClose` | 각 후보의 데이터 기준 세션 종가·원자료 출처·조회 시각 |
| `evidence` | 각 후보의 완료 일봉 관측 ID·날짜·필드·실제 값·조회 시각·출처와 모델의 설명 |
| `observation` | 각 후보의 관찰 기간을 정규장 개수로 표시한 `sessions`와 그 이유 |
| `noCandidatesReason` | 후보 없음의 이유. 후보가 있으면 `null` |
| `fractionalTrading` | 소수점 거래 미확인과 예약 전 직접 확인 안내 |
| `semanticReview` | 원자료와 서술의 의미 검토 결과 및 정확도 미검증 표시 |
| `sourceUniverse` | 기존 후보군·제외 사유·탐색 순위·일봉·공식 일정과 검증 한계 |
| `model`, `limits`, `usage` | 선택 모델·추천 단계 요청과 완료 수·운영 상한·실제 전송 시도 집계 |

기준 종가는 매수 후보를 분석할 때 사용한 가격입니다. 예약 주문의 예상·보장 체결가격으로 사용하지 마세요. 표시한 다음 정규장을 대상으로 한 검토이므로 개장 후 새 판단으로 재사용하지 마세요. 관찰 기간은 자동 보유·청산 조건이 아닙니다. 예약 전에 토스증권에서 소수점 거래 가능 여부를 직접 확인하세요.

## 실패 확인

실패 시 stdout에 부분 보고서를 출력하지 않습니다. stderr의 `error`, `stage`, `usage`와 종료 코드를 확인하세요. 정상 빈 후보군은 후보 없음과 그 원인을 함께 표시합니다. 모든 종목을 확인하지 못한 `ANALYSIS_INSUFFICIENT`는 종료 코드 2이며 정상 후보 없음과 구분합니다. 그 밖의 실패는 종료 코드 1입니다.

실패 JSON의 `observation`에서 공통 실행 기록을 확인하세요. `recommendation` 아래의 `recommendation.model`은 후보 선정, `review`는 별도 의미 검토입니다. 각 `recommendation.model.http`·`review.model.http`의 `parentId`는 해당 작업을 가리킵니다. `recommendation.tool`은 일봉 읽기를 요청한 HTTP 요청에 연결되고 `recommendation.validation`은 후보·관측 근거 검증을 나타냅니다. 일봉 도구는 이미 검증한 자료만 읽으며 진단에 KIS 원자료를 복제하거나 추가 시세 조회를 하지 않습니다.

상세 `operations`가 잘렸다면 `summaries.stages`와 `summaries.modelRequests`를 먼저 확인하세요. 완료한 단계와 모델 요청도 요약에 남으므로 실패 전 시간을 어디에 썼는지 확인할 수 있습니다. 요약과 상세 기록은 같은 작업을 가리키며 별도 실행이나 추가 호출이 아닙니다. 부모·자식 작업의 시간은 겹칠 수 있으므로 모두 더하지 마세요.

각 기록의 `executionRemainingMs`, `stageRemainingMs`, `requestRemainingMs`는 작업 시작 시 남은 전체·단계·개별 요청 시간의 밀리초 값입니다. 유형 요청들과 추천·의미 검토는 각각 기존 단계 예산을 공유하며 요청마다 180초를 새로 받지 않습니다. `inputBytes`는 전송하는 모델 요청 본문의 바이트 수, `securityCount`와 `rowCount`는 해당 작업에 전달하는 종목과 행의 수입니다. 관측하지 못한 값은 `null`이며 0과 구분하세요. 독립 CLI에는 통합 600초 예산을 새로 적용하지 않으므로 전체 잔여 시간이 `null`일 수 있습니다. 이 수치로 공급자 내부 검색·추론·대기 시간을 추정하지 마세요.

요청의 `headersAt`, `firstEventAt`, `lastEventAt`, `completionEvents`, `errorEvents`, `streamEnd`를 함께 확인하세요. 헤더 수신이나 정상 JSON만으로 완료한 요청으로 해석하지 마세요. `eof`는 자연 종료이며 명시적 완료 이벤트와 구분합니다. `cancelled`와 `cancellationSource`는 직접 관측한 취소와 출처를 나타내며 확인되지 않은 출처는 `unknown`입니다. 요청 시간에는 헤더를 받은 뒤 스트림이 끝나거나 중단될 때까지 걸린 시간도 포함됩니다. `firstFailure`는 최초 관측 실패이고 근본 원인을 확정하지 않습니다. `finalError`는 기존 공개 오류와 연결된 작업을 나타냅니다. 검증 실패가 이미 EOF로 끝난 HTTP 요청을 통신 실패로 바꾸지는 않습니다.

`responseFormat`은 응답 Content-Type을 원문 없이 분류한 `event_stream`, `json`, `other`, `missing`이며 미관측이면 `null`입니다. 모델의 성공 HTTP 응답은 이 분류와 무관하게 SDK와 동일하게 SSE 관측을 시도합니다. LF·CRLF·CR 줄바꿈과 청크 경계를 처리하며 SDK에 전달하는 원래 바이트와 완료 판정은 바꾸지 않습니다. 바이트 수가 양수여도 이벤트가 없다면 정상 모델 이벤트를 읽었다고 단정하지 마세요.

실패하거나 명시적 만료로 거부된 `kis.http` 작업의 `kis`에서 요청 종류 `kind`·거래소 `exchange`·종목 `symbol`, JSON 해석 성공 여부 `bodyParsed`, 공급자 오류 코드 `providerCode`를 확인하세요. 종목은 허용된 종목 코드만, 공급자 코드는 영문 대문자·숫자 1~20자만 보존하며 알려진 비밀값이 포함되면 `null`로 남깁니다. 순위처럼 종목이 없는 요청도 `symbol: null`입니다. `bodyParsed: true`는 JSON 해석 성공이며 객체 형태·업무 성공을 보장하지 않습니다. 코드 부재·형식 거부·비밀값 제외는 모두 `providerCode: null`이므로 이를 공급자 오류 없음으로 해석하지 마세요. 응답 원문·오류 메시지·헤더·인증값은 이 기록에 저장하지 않습니다. 인증 처리·운영 한도는 유지하며 과거 실패에서 누락된 정보는 복원하지 않습니다.

KIS 조회의 구조화된 `EGW00316`에는 같은 요청을 1초 뒤 최대 한 번 재시도합니다. 명시적 만료 복구와 별도로 논리 조회 전체에서 한 번만 허용하며, 토큰을 이 코드만으로 재발급하지 않습니다. 대기와 재전송도 기존 단계·600초·개장 마감 및 KIS 전체 90회 상한 안에서 처리합니다. 예산이 없거나 공통 잔여 시간이 1초 이하이면 대기하지 않습니다. `kis.retry_wait`와 실패 요청의 복구 표시를 함께 확인하세요. 이 수치는 로컬 정책이며 실제 복구 성공은 미검증입니다. 상세 조건은 [KIS 관측 레퍼런스](kis-probe-reference.md#요청과-제한)에 있습니다.

`eventCounts`는 파싱한 JSON 이벤트를 `reasoning`, `output_text`, `lifecycle`, `other` 네 범주로만 집계합니다. 추론 항목이나 관련 이벤트, 출력 텍스트 이벤트, 고정된 생성·진행·항목·완료·실패 이벤트, 그 밖의 이벤트를 구분하며 이벤트 종류 원문과 내용은 보관하지 않습니다. `other`가 곧 SDK 미지원이나 프로토콜 오류라는 뜻은 아닙니다. 미관측 또는 계수 신뢰도를 잃은 경우는 `null`이며, 이벤트 수를 토큰 수나 생성된 텍스트 양으로 해석하지 마세요.

`degraded`, `truncated`, `omittedOperations`가 있으면 관측 실패나 생략 여부를 확인하세요. 공통 기록의 상한과 필드 의미는 [공통 관측 계약](rca-observability-design.md#273의-공통-구현-계약)을 따릅니다. 관측 상태는 원래 보고서 판정·완료 조건·취소·요청 집계를 바꾸지 않습니다. 추천과 의미 검토는 기존 합산 4회·180초와 통합 마감을 유지합니다. 성공 stdout에는 관측 기록을 추가하지 않습니다.

기존 `diagnostic.elapsedMs`와 `diagnostic.typeAssessment`도 유지합니다. 유형 판단의 필드 의미는 [유형 판단 진단 안내](llm-security-probe.md#유형-판단의-요청별-진단-읽기)를 따릅니다. 이 구현의 검사는 CLI·외부 HTTP·시계 목업이며 실제 공급자 호환성이나 과거 실패의 원인을 입증하지 않습니다.

| 오류 | 의미 |
| --- | --- |
| `DATA_NOT_READY` | 필요한 완료 일봉의 날짜·필드가 준비되지 않음 |
| `MODEL_OUTPUT` | 형식·필수 항목·종목·근거 연결·전체 일봉 읽기 조건을 충족하지 않음 |
| `REPORT_UNSUPPORTED` | 의미 검토에서 근거 없는 설명이나 허용하지 않은 매매 지시 등을 발견함 |
| `MODEL_INCOMPLETE` | 중간·최종·검토 응답의 미완료, 스트림 오류 또는 단계 시간 초과 |
| `MODEL_LIMIT`, `MODEL_INPUT_LIMIT`, `REQUEST_LIMIT` | 모델·입력 크기·요청 상한 도달 |
| `SUBSCRIPTION_LIMIT` | 명시적인 구독 한도 소진. 일정·유형은 중단하며 후보 선정·의미 검토의 전환 조건은 [유료 전환 안내](#구독-한도-소진-시-유료-전환)를 따릅니다. |
| `PAID_CREDENTIALS_MISSING`, `PAID_BUDGET_UNPROVABLE`, `PAID_BUDGET_EXCEEDED` | 별도 API 인증 부재, 최대 비용 산정 불가 또는 실행 예산 부족. 추가 유료 생성을 보내지 않습니다. |
| `AUTH_FAILED`, `siwc_*` | 공통 인증 실패. 기존 인증 안내의 복구 절차를 따름 |
| `MARKET_ACTIVE`, `TARGET_OPEN`, `EXECUTION_LIMIT` | 장중 시작·실행 중 개장·전체 실행 마감 도달 |

## 한도와 신뢰 범위

2026년 11월 3일 한국 낮 통합 실행에서 완료 일봉을 사용한 정상 후보 없음 보고서를 확인했습니다. 후보가 있는 보고서의 실연동, 한국 낮 전체의 가용성, 추천 품질은 미검증입니다. [첫 버전 인수 기록](first-version-acceptance.md#2026-11-03-한국-낮-통합-실행)에서 실행 근거를 확인할 수 있습니다.

[ADR 0015](adr/0015-subscription-buy-candidate-report.md)의 합의대로 최근 20개 완료 세션과 전체 600초·다음 개장 마감을 유지합니다. 추천과 의미 검토는 별도 모델 전송 최대 4회·180초에 함께 포함됩니다. 후보 선정은 최대 3회, 의미 검토는 1회입니다. KIS 일봉을 읽는 모델 도구는 이미 검증한 자료를 반환하며 추가 외부 요청을 보내지 않습니다. 원래 순위별 상위 1개 정책은 유지하므로 최대 5개 후보를 확보하지 못할 수 있습니다.

코드는 가격·거래량 값을 원자료에서 복원하고 종목·날짜 연결을 검사합니다. 모델이 선택한 근거가 실제로 선정 이유를 뒷받침하는지, 뉴스·사건을 만들어 내지 않았는지는 별도 모델이 의미 검토합니다. 두 모델 판단 모두 오판할 수 있으며 독립 정답 표본으로 추천 정확도를 입증한 결과가 아닙니다. 실패한 의미 검토를 자동으로 고쳐 재시도하지 않습니다.

순위는 조회 당시의 탐색 자료이며 완료 세션 순위가 아닙니다. 일봉의 정규장 범위는 승인된 KIS 필드 운영 가정이며 수정주가를 반영하지 않습니다. 공식 일정 공지 수집 완전성과 모델의 의미적 신뢰도는 계속 미검증입니다. 가격만으로 뉴스·사건의 원인을 설명하지 않으며 계좌·보유 내역·매도·유지·금액·비중·주문 연동은 다루지 않습니다.

모의 CLI·HTTP 회귀 검사는 실제 구독·KIS 실행, 추천 유용성, 토스증권 거래 가능 여부와 제품 인수를 입증하지 않습니다.
