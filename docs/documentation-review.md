# 2026-11-14 문서 개편 검토 기록

## 범위와 기준

사용자·소비 에이전트·개발자가 설치와 조회, JSON 해석, 수정과 검증에 필요한 정보를 찾을 수 있도록 문서별 책임과 탐색 경로를 정리한다. 전체 저장소의 문서 표면을 목록화하고 현재 구현의 계약과 흐름을 조사했다. 모든 과거 문서와 테스트 본문을 한 줄씩 재심사하거나 공급자 동작을 재검증한 작업은 아니다.

기준은 `1170ad4ce19991c591bf7e339d22c613730a8df6`이다. 인터뷰에서 확인한 `3714f59e0ef1edef20c9b63b833d8114f5ef755a` 이후 원격 변경을 읽고, 승인된 문서 수정 12개가 최신 기준과 모두 일치함을 확인했다. 후속 테스트 보강과 안전한 계좌 오류 진단 변경을 보존한 기준에서 개편했다. 제품 요구사항은 [#278](https://github.com/mochafreddo/stock-scout/issues/278)과 [#283의 계약](https://github.com/mochafreddo/stock-scout/issues/283#issuecomment-6686267791), 전환 뒤의 적용 관계는 [ADR 0019](adr/0019-toss-query-tools-transition.md)를 따른다.

모든 명령은 위 기준의 별도 작업 트리 루트에서 실행했다. 아래 검증 중 문서 11개의 내용 지문이 유지됐고 런타임·테스트·설정의 추적 변경은 없음을 확인했다. 이후 이 기록의 결과 절만 갱신했다.

독립 읽기 전용 검토에서 심볼 단독 가격의 식별 한계, 거래 제약 오류와 부분 결과의 구분, 중복 모듈 설명, 파일별 문체, 공급자 대기 기록의 잠금 경계를 보완했다. 수정 부분 재검토에서 남은 차단 사항은 없었다. 과거 용어 정의가 원문과 일치하는지 비교했고, 원래 작업 트리의 승인된 문서 12개와 제외한 감사 문서도 시작 지문과 대조했다. 이는 해당 파일 범위의 보존 확인이며 모든 미추적·무시 파일의 불변성을 주장하지 않는다.

## 작업 기록

- 저장소 지침·현재 문서·요구사항·소스·검사 위치를 조사하고 개편 전 영역별 대응표를 작성했다.
- 요구사항 이슈의 첫 읽기는 네트워크 연결 오류로 실패했고 권한 경로의 읽기로 본문·댓글을 확보했다. 이슈는 수정하지 않았다.
- 원격을 갱신하고 별도 작업 트리를 만들었다. 복사한 문서 12개가 최신 원격과 일치해 해당 복사 패치를 역적용한 뒤 최신 기준으로 작업 트리를 옮겼다. 원래 작업 트리는 수정하지 않았다.
- 기존 개발 의존성을 작업 트리에 복사하고 오프라인 목록을 확인했다. 패키지 설치·업데이트·정리는 수행하지 않았다.
- CLI 문서 담당은 첫 실행 안내와 레퍼런스의 명령·공통 계약 배치를 개편했다. 자체 검토에서 도움말 객체의 설명을 명확히 했다.
- 에이전트 문서 담당은 조회 선택과 해석·예제·인수 절차를 정리했다. 첫 패치는 문단 불일치로 변경 없이 실패했고 정확한 문단을 지정해 적용했다.
- 구조 설명과 개발자 수정·검사 안내를 추가하고 README·문서 색인·ADR 색인의 경로를 정리했다.
- 이전 용어 정의를 그대로 분리하고 원래 제목 앵커를 유지했다. 과거 관측과 증거 본문은 재작성하지 않았다.
- 독립 검토의 다섯 사항을 문서에 반영하고 수정 부분의 재검토를 마쳤다.
- 문서·도움말·합성 흐름·형식·타입 검사를 실행했다. 전체 테스트의 환경 중단과 권한 경로 통과는 위 표에 따로 기록했다.
- 지침과 기존 스킬·코드 주석·CLI 도움말·소비 예제 코드는 조사 후 유지했다. 설명을 추가할 실익이 없는 주석과 새 ADR은 만들지 않았다.
- 커밋·푸시·이슈 게시·배포는 요청 범위에서 제외했다. 결과 검토를 위해 이번 작업 트리를 유지한다.

## 남은 한계와 제외

- 실제 토스 API·계좌·자격 증명 설정·외부 모델 전달·공급자 문의는 수행하지 않는다. 기존 승인과 관측의 범위를 새로 확대하지 않는다.
- 외부 URL과 고정 리비전의 모든 원격 링크를 전수 호출하지 않는다. 로컬 링크·앵커 검사와 요구사항 이슈 읽기는 구분한다.
- 과거 KIS·내장 모델 명령은 제거된 제품의 기록이므로 재실행하지 않는다. 과거 증거의 의미·금융 결과·정책 최신성을 새로 입증하지 않는다.
- 실제 dots의 명령 발견·호출은 실행하지 않는다. 합성 실행기와 소비 예제의 성공은 해당 소비 환경의 성공과 구분한다.
- 설정·런타임·테스트·예제 코드를 변경하지 않는다. 새 문서의 표현을 고정하는 테스트나 별도 문서 생성 체계를 추가하지 않는다.
