# 거래소 일정의 공통 기준 세션과 장전 범위

[#244](https://github.com/mochafreddo/stock-scout/issues/244)의 설계 인터뷰에서 2026-10-18 합의한 결정이다. 일정상 장전 범위는 뉴욕 현지 거래일 00:00부터 정규장 개장 직전까지이며, KIS 데이터 준비 여부를 반영한 실제 지원 시간과 구분한다. 직전 완료 세션은 확인된 폐장 시각이 판정 시각 이하인 가장 최근 정규장이다.

NAS·NYS·AMS의 일정을 각각 확인하며, 기준 세션이나 정규장 개장·폐장 시각이 서로 다르면 전체 판정을 실패시킨다. 거래소별로 다른 세션의 데이터를 허용하는 대신, 부모 명세 [#239](https://github.com/mochafreddo/stock-scout/issues/239)의 단일 데이터 기준 세션을 유지한다. 거래소별 기준 세션을 지원하려면 후보군 결과와 근거의 세션 계약을 다시 결정해야 한다.

공식 일정은 실행마다 조회하고 조회·해석 실패 시 오래된 자료나 추정 일정으로 대체하지 않는다. 독립 일정 도구는 휴장일·장중·장 종료 후에도 일정을 확인할 수 있으면 정상 결과와 장전 대상 여부를 출력한다. 일정 조회 성공과 후보군 CLI의 실행 적격 여부는 별도 판정이다.

연간 일정과 별도로 발표되는 돌발 휴장·개장 지연·시간 변경도 공식 공지로 확인한다. 공지 확인 경로의 적용 범위와 최신성을 검증하지 못하면 운영 검증은 미완료로 남긴다. 공지 조회 실패나 해석 불가는 실패이며, 공지가 보이지 않는다는 사실만으로 변경이 없다고 확정하지 않는다. 이는 연간 일정만으로 운용하는 편의보다 확인되지 않은 세션으로 진행하지 않는 쪽을 선택한 결정이다.

지원 범위는 임의의 연도로 고정하지 않는다. 현재 날짜·직전 완료 세션·다음 개장과 그 사이의 휴장 처리를 공식 자료로 모두 확인할 수 있어야 한다. 연초·연말에 필요한 인접 연도 자료가 없으면 현재 날짜의 자료만으로 성공시키지 않는다.

현재 시각 실행은 공식 자료를 받은 뒤 판정하고 출력 직전 시각으로 전체 판정을 맞춘다. 조회 중 날짜나 자료 적용 범위가 바뀌어 필요한 일정을 확인할 수 없으면 실패한다. 독립 일정 도구의 검증용 `--at`은 `Z` 또는 UTC 오프셋이 있는 시각을 고정해서 사용하며, 최종 후보군 CLI의 과거 시각 지정 기능으로 확장하지 않는다.

다음 개장 시각은 판정 시각보다 뒤에 있는 첫 정규장 개장 시각이다. 정확히 개장 시각인 경우 현재 개장을 다음 개장으로 다시 표시하지 않는다. 공용 검증 경계는 CLI의 인수·표준 출력·표준 오류·종료 코드이며, 검토 기준점은 `86af4dbe2f0fe204de5a738ac3345246396fe341`이다. 이번 설계의 용어집·ADR 변경과 이후 #244 변경을 검토 범위에 포함하고 기존 미추적 인증 ADR은 별도 작업으로 보존한다.

이 문서는 설계 합의를 기록하며 일정 도구의 구현이나 실연동 검증을 완료했다는 뜻은 아니다. 설계 조사에서 공식 연간 일정과 별도 공지 채널의 존재를 확인했으나, 변경 공지를 빠짐없이 자동 확인하는 경로의 적용 범위와 최신성은 입증하지 못했다.
