# 구독 한도 소진 뒤 추천 요청의 최대 비용을 먼저 확보한다

#241은 공식 `subscription_sharing_usage_limit_exceeded` 신호가 확인된 경우에만 별도 API 인증으로 전환한다. HTTP 오류는 상태 429와 해당 코드를 함께 요구하며 스트림에서는 공식 오류 이벤트의 코드를 확인한다. 인증·네트워크·일반 속도 제한·불명확한 사용량은 전환 조건이 아니다. 후보 선정과 의미 검토의 실패한 실행은 중간 출력을 버리고 다시 시작하며, 이미 완료한 단계는 유지한다. 선택 모델은 바꾸지 않는다.

일정·유형 단계는 ADR 0014의 구독 전용 정책을 유지한다. 특히 유형 단계의 서버 내부 웹 도구 비용은 사전에 보장할 수 없어 유료 전환하지 않는다. 이 단계에서 중단되면 보고서가 완성되지 않으며 #241의 전 구간 전환 성공으로 보고하지 않는다. ADR 0015의 추천 단계 구독 전용 조건은 이 결정의 범위에서만 대체한다.

추천 경로는 기존 전체 600초·다음 개장과 단계 180초, 추천 전송 시도 4회·선정 최대 3회·일봉 도구 12회를 공유한다. 유료 전환으로 시간·횟수를 초기화하지 않으며 유료 실패는 자동 재시도하지 않는다. 같은 후보·일봉 읽기·근거·명시적 완료·별도 의미 검토·종가·두 세션·소수점 거래 미확인 계약을 적용한다. `model.authentication`과 `paid.switched`가 전환을 표시한다.

별도 인증은 실행 환경의 `OPENAI_API_KEY`만 사용하며 새로운 비밀 저장소를 만들지 않는다. 인증이 없으면 설정 안내와 함께 실패한다. 요청은 공식 전역 Responses API에만 보내며 리디렉션을 금지하고 Standard 처리, 저장 비활성화·스트리밍, 출력 최대 8,192토큰을 강제한다. 출력 상한은 추론 토큰을 포함한다. 네임스페이스 안의 로컬 함수만 허용하여 별도 과금되는 호스팅 도구를 사용하지 않는다.

각 유료 생성 요청 전에 공식 `POST /v1/responses/input_tokens`로 모델·메시지·도구 정의·출력 스키마 등 실제 입력의 토큰 수를 확인한다. 생성 전용 매개변수는 이 계수 요청에서 제외한다. 계수가 실패하거나 정수가 아니거나 32,000토큰을 넘으면 생성하지 않는다. 장문 할증 기준보다 작은 입력만 허용하며 할인·캐시 적중·실제 사용량 반환에 의존하지 않는다. 알려진 모델의 공식 Standard 입력·출력 가격과 12시간 캐시 쓰기 가격 중 보수적인 입력 상한으로 계산한다. 계수 뒤 실제 요청까지 동일한 입력을 유지한다.

2026-10-31에 확인한 100만 토큰당 달러 기준의 입력 상한·출력 단가는 Sol `5 / 10`, Luna `0.25 / 0.5`, Astra `25 / 50`이다. 입력 상한은 Standard 입력 가격의 2.5배로 12시간 캐시 쓰기를 덮는다. 가격의 권위는 [공식 가격표](https://developers.openai.com/api/docs/pricing)이며 이 값은 실제 청구액이 아니다. 알려지지 않은 모델은 전환을 거부하며 가격 변경 시 코드와 근거를 함께 검토한다. [Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol)·[Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)·[Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)의 모델 문서와 [토큰 계수 명세](https://developers.openai.com/api/reference/resources/responses/subresources/input_tokens/methods/count)를 함께 사용한다.

요청별 최대 비용은 정수 마이크로달러로 올림하여 실행 전체에 누적한다. 현재 요청뿐 아니라 남은 추천 요청과 의미 검토의 최대 비용도 잔여 1달러 안에 들어가야 전송한다. 정확히 1달러는 허용하며 이를 넘으면 차단한다. 실패·중단·사용량 불명확 요청도 이미 확보한 비용을 되돌리지 않는다. `paid.reservedUsd`는 보수적으로 확보한 누적 최대 비용이며 청구액·환급액·남은 계정 크레딧이 아니다.

비용 제어 순서는 OpenAI의 [실행별 지출 제어 예제](https://developers.openai.com/cookbook/articles/per_run_spending_controller_responses_api)를 따른다. 이 공식 예제는 토큰 계수를 먼저 하고 생성 요청의 입력·최대 출력 비용을 확보한다. 계수 API가 무료라는 별도 문구를 확보한 것은 아니며, 계수 비용을 별도 항목으로 더하지 않는 근거는 이 공식 제어 예제다. 계정 청구 내역을 독립 대조한 결과로 확대하지 않는다.
