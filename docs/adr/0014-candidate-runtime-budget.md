# 후보군 경로에 공통 마감과 분리된 요청 예산을 적용한다

2026-10-28 [#251](https://github.com/mochafreddo/stock-scout/issues/251)에서 사용자는 후보군 단계의 첫 운영값을 승인했다. 큰 N의 처리 시간을 외삽하거나 단계별 시간을 단순 합산하는 대신, 작은 탐색 범위와 실행 전체의 공통 마감·요청 예산으로 자원 사용을 제한한다. 이는 설계 정책이며 공급자 한도·완료율·추천 품질이 입증된 값이 아니다. 선행 근거와 한계는 [종합 보고](../operating-limits-and-support.md)를 따른다.

| 항목 | 합의한 후보군 운영값 |
| --- | --- |
| 탐색 N | NAS·NYS·AMS × 거래량·거래대금 여섯 순위의 첫 페이지에서 각각 최대 1개. 원래 순위·조회 시각을 보존하고 제외·중복 제거 뒤 미보충한다. 비어 있지 않은 짧은 페이지는 실제 행 수만 사용한다. |
| 일봉 H | 데이터 기준 세션을 포함한 최근 20개 완료 정규장. 한 달 안팎의 입력 창을 고른 설계값이며 추천 품질에 충분하다는 실측 근거는 없다. 공식 일정으로 필요한 날짜를 정하고 진행 중 날짜를 제외하며 기간·가격·거래량을 검사한다. 부족하면 실패하고 자동 페이지 확장·기간 축소는 하지 않는다. |
| 조회 순서 | 공식 일정·분석 가능 여부 → 여섯 탐색 순위 → 상장 종목 중복 제거·기존 유형 판단 → 포함 종목 일봉 조회·준비 검사 → 출력 직전 개장 경계 확인. |
| 공통 마감 | 프로세스 작업 시작부터 600초와 판단 대상 개장 시각 중 이른 시각. 인증·수집·조회·모델·검증을 포함하며 단계와 외부 요청에 남은 시간을 전달한다. |
| KIS 요청 | 발급·조회·명시적 만료 재조회의 실제 전송 시도를 합쳐 최대 90회. 발급은 그 안에서 최대 2회이며 기존 최소 300초 간격·60초 만료 여유·대기 없는 실패 정책을 유지한다. |
| 공식 일정 HTTP | 실제 전송 시도 최대 100회. 기존 수집 범위·크기·시간 제한도 유지한다. |
| 모델 요청 | 실제 전송 시도 최대 13회. 일정 판단 1회와 유형 판단 최대 12회이며 서로 예산을 빌리지 않는다. |
| SIWC 갱신 | 실제 갱신 전송 시도 최대 2회. 기존 인증 정책이 허용하는 경우만 사용하며 추가 재시도·재로그인을 도입하지 않는다. |
| 유형 웹 도구 | 기존 관측 이벤트 최대 32개. 서버 내부 HTTP 요청 수의 사전 보장으로 표시하지 않는다. |
| 단계별 한도 | 일정 전체 300초·수집 120초·개별 수집 요청 15초·모델 최대 180초·모델 입력 256KiB, 유형 판단 180초·정보 도구 32회, KIS 개별 조회 15초를 유지하며 통합 잔여 시간과 함께 적용한다. |
| 비용 | 후보군은 기존 구독 흐름만 사용하고 유료 전환은 하지 않는다. #237의 향후 추천 유료 API 합산 최대 1달러 계약은 유지한다. |

각 상한은 다음 요청을 보내기 전에 검사한다. 실패한 전송과 허용된 재조회도 센다. 90회는 발급을 포함하는 KIS 전체 상한이며 정보 도구 32회는 논리 호출 상한으로 함께 적용한다. 일정 HTTP·모델·SIWC 갱신은 각각 별도 계수한다. 서버 내부 웹 호출은 관측 이벤트와 구분하며 모든 외부 호출을 사전에 합산 제한한다고 주장하지 않는다. 기존 인증 정책이 갱신을 허용하지 않으면 남은 횟수와 관계없이 실패한다.

600초는 각 단계의 최악 시간을 모두 보장하는 값이 아니다. 단계별 한도와 공통 예산·마감 중 먼저 소진되는 조건에서 전체 실패로 종료하며, 부분 결과를 정상 후보군으로 출력하거나 자동 한도 확대·대기·재관측을 하지 않는다. 인증 지연을 단계 밖으로 빼지 않으며 출력 직전 개장 시각에 도달한 경우도 실패다.

이 결정은 #245 후보군 경로의 첫 운영 기준이다. #251은 보고서와 결정 기록을 남기며, #245에서 공통 예산·마감 전달·일봉 준비·개장 경계를 구현하고 CLI 입력·stdout·stderr·종료 코드·외부 HTTP에서 검증한다. N=1은 최대 5개 매수 후보 확보를 보장하지 않으며, H=20은 추천 전략·관찰 기간이나 검증된 분석 충분성이 아니다. #240의 추천 입력 요구가 달라지면 H와 통합 예산을 명시적으로 재합의하고, 추천 요청을 이 13회에 조용히 추가하지 않는다.

ADR 0011·0012·0013의 탐색 전용 순위·실행별 일봉 준비 검사·제한된 일정 공지·완전성 및 의미적 신뢰도 미검증·장중 거부 정책은 유지한다. 고정 KST 지원 시각이나 한국 낮 전체의 가용성을 보장하지 않는다. 이번 결정 기록은 #245 구현·실연동·#240 추천·#242 제품 인수의 완료가 아니다. 검토 기준은 `6f6605b3284bf8b8e5e58d7a649ab250fead69e8`과 확보한 이슈 원문 및 사용자의 권고안 전체 승인이다. 승인 범위는 로컬 문서 반영·검토·검증·현재 main 커밋이며 푸시·원격 이슈 변경·종료·실제 호출은 포함하지 않는다.
