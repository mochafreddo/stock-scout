# 조회 근거에 따른 종목 유형 판단을 LLM에 맡긴다

[#250](https://github.com/mochafreddo/stock-scout/issues/250)의 2026-10-20 설계 인터뷰에서 범용 코드 분류기를 추천 구현의 필수 선행 산출물로 삼는 대신, LLM이 조회 근거로 종목 유형과 추천 여부를 판단하는 방향에 합의했다. KIS 순위에서 자동으로 종목을 찾는 목표와 보통주·적격 ADR만 추천하는 조건은 유지한다. 분류 규칙을 먼저 완성하는 비용을 줄이는 대신 모델 판단의 오분류 가능성을 받아들이고, 증권별 근거 기록과 독립적인 정답을 가진 실제 평가로 확인한다.

LLM은 해당 거래소·종목 코드에 대응하는 유형 근거와 출처를 남긴다. 명확한 근거 하나면 충분하지만 확인된 반대 근거는 해결해야 하며 ADR은 보통주 성격까지 확인한다. 이름·티커·모델의 기억이나 검색 요약만으로 확정하지 않는다. 자료의 기준일·적용일과 확인 가능한 후속 변경을 살피고 현재 적용 여부가 불확실하면 제외한다. 모든 기업행동의 실시간 반영을 보장하지 않는다.

코드는 조회 실행·입력 검증·호출 제한·비용 제한·출력 검사를 담당한다. 추천 종목의 입력 순위 소속, 최대 후보 수, 필수 근거 항목을 검사하되 근거 항목의 존재만으로 내용의 타당성이 입증됐다고 보지 않는다. 같은 회사의 별도 증권은 합치지 않으며 원본 거래소·종목 코드를 보존한다.

자료 부족·종목별 유형 조회 실패·현재 적용 여부의 불확실성은 해당 종목을 제외하고 사유와 분석 범위 축소를 표시한다. 모든 종목의 유형 확인이 실패하면 정상 후보 없음과 구분한 분석 불충분으로 알린다. KIS 순위 수집 실패, 증권 식별 자체의 모호함, 모델 실행 실패, 인증 실패·검색 서비스 전체 장애·호출 한도 도달로 필요한 확인을 계속할 수 없는 경우는 전체 실패한다. 이는 ADR 0005의 코드 기반 유형 판별과 필수 유형 자료 조회 실패의 전체 실패 계약을 해당 범위에서 대체한다. ADR 0005·0006의 허용 출처 범위와 시세·거래량·거래대금·순위의 KIS 공급자 원칙은 유지한다.

첫 검증 흐름은 KIS 순위, LLM의 정보 조회·유형 판단, 포함·제외 결과와 근거 출력이다. KIS 조회 함수와 OpenAI 웹 검색을 우선 구성 후보로 삼고 실제 구독 인증 경로의 호환성을 확인한다. MCP 서버는 필수가 아니다. 검색 미지원 시 별도 검색 API와 MCP 필요성을 비교하며 새 서비스 가입·키 발급·결제나 유료 모델 API 전환을 자동으로 승인하지 않는다. 기존 보통주·ADR·제외 유형과 증권 연결·자료 충돌·부족 사례로 평가하고 잘못된 포함과 근거 없는 유형 확정이 없어야 통과한다. 보통주와 적격 ADR의 실제 포함도 확인하며 전부 제외한 결과나 모의 검사만으로 성공을 선언하지 않는다.

이 결정은 실제 호환성·유형 판단의 검증 완료나 후속 차단 해제를 뜻하지 않는다. 구현·실연동·원격 명세 게시·커밋·푸시는 별도 요청 범위다. 매수 추천 연결은 작은 검증 흐름을 확인한 다음 작업으로 둔다.
