# 커밋 대상 스냅샷을 검사한다

2026-10-18 개발 환경 설계 인터뷰에서 stock-scout의 push 직전 검사에 커밋 단계 검사를 추가하기로 합의했다. 작업 디렉터리의 미커밋 수정이 오류를 가리지 않도록 staged 스냅샷에서 문서의 공백과 로컬 링크를 검사하고 코드의 형식·린트·타입 검사도 실행한다. 검사에 실패하거나 검사를 실행할 수 없으면 자동으로 수정하지 않고 커밋을 차단한다. 중간 커밋의 편의보다 커밋 대상이 최소 검사 기준을 충족하는 것을 우선한다. 전체 테스트는 최종 검증과 pre-push에서 계속 실행하며 다른 저장소의 훅과 Actions 정책은 바꾸지 않는다. 이는 설계 결정이며 구현·설치 완료를 뜻하지 않는다. 현재 검사 범위와 설치 방법은 [개발 안내](../development.md#커밋푸시-검사)를 따른다.

## 설치 훅의 검사기 일치 조건

2026-11-23에 설치 훅이 검사기 내용과 검사 대상 스냅샷을 고정하고, 대상에 포함된 검사기와 내용이 일치할 때 고정한 검사기로 검증하기로 합의했다. 검사기 부재나 내용 차이로 동일한 규칙을 적용할 수 없으면 차단하므로, 검사기 버전이 다른 ref를 한 번에 푸시할 수 없다. 실제 검사 대상이 없는 ref 삭제는 기존대로 처리한다. 설치 시점에 훅에 담은 검사기 원문을 사용하며, 커밋과 푸시 검사는 Git 트리의 검사기 blob과 원문을 바이트 단위로 비교한다. 기존 훅의 이전과 검사기 갱신은 [개발 안내](../development.md#기존-훅-이전과-검사기-갱신)를 따른다.

2026-11-24 기준 `main`의 `da14062`에서는 설치 훅이 작업 트리의 `scripts/pre-push.ts`를 실행한다. 그 방식에서 고정한 검사기로 바꾸는 범위와 검증 조건은 후속 이슈에 기록했다. [#351](https://github.com/mochafreddo/stock-scout/issues/351)

## 추적 링크의 스냅샷 경계

2026-11-25에 staged·push 검사가 완성된 스냅샷의 모든 추적 심볼릭 링크를 확인하기로 합의했다. 링크의 최종 대상이 같은 스냅샷에 속해야 커밋에 포함되지 않은 파일이 검사 결과에 영향을 주지 않는다. 외부·끊긴·순환 링크는 품질 검사 전에 차단하고 기존 내부 스킬 링크는 허용한다. 적용과 검증 범위는 [검토 후속 결정](../review-remediation.md#2026-11-25-전체-코드베이스-검토-후속-결정)에 기록한다.
