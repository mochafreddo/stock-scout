# 커밋 대상 스냅샷을 검사한다

2026-10-18 개발 환경 설계 인터뷰에서 stock-scout의 push 직전 검사에 커밋 단계 검사를 추가하기로 합의했다. 작업 디렉터리의 미커밋 수정이 오류를 가리지 않도록 staged 스냅샷에서 문서의 공백과 로컬 링크를 검사하고 코드의 형식·린트·타입 검사도 실행한다. 검사에 실패하거나 검사를 실행할 수 없으면 자동으로 수정하지 않고 커밋을 차단한다. 중간 커밋의 편의보다 커밋 대상이 최소 검사 기준을 충족하는 것을 우선한다. 전체 테스트는 최종 검증과 pre-push에서 계속 실행하며 다른 저장소의 훅과 Actions 정책은 바꾸지 않는다. 이는 설계 결정이며 구현·설치 완료를 뜻하지 않는다. 현재 검사 범위와 설치 방법은 [개발 안내](../development.md#커밋푸시-검사)를 따른다.

## 설치 훅의 검사기 일치 조건

2026-11-23에 설치 훅이 검사기 내용과 검사 대상 스냅샷을 고정하고, 대상에 포함된 검사기와 내용이 일치할 때 고정한 검사기로 검증하기로 합의했다. 검사기 부재나 내용 차이로 동일한 규칙을 적용할 수 없으면 차단하므로, 검사기 버전이 다른 ref를 한 번에 푸시할 수 없다. 실제 검사 대상이 없는 ref 삭제는 기존대로 처리한다. 기존 훅의 보존과 이전, 검증 범위는 [이번 검토의 후속 결정](../review-remediation.md#2026-11-23-전체-코드베이스-검토-후속-결정)에 기록했다. 이 절은 합의한 설계이며 구현과 설치는 별도다.

2026-11-24 기준 `main`의 `da14062`에서는 설치 훅이 작업 트리의 `scripts/pre-push.ts`를 실행한다. 검사기 내용 고정, 대상 스냅샷과의 일치 확인, 기존 훅의 이전 절차는 후속 이슈에 남아 있다. [#351](https://github.com/mochafreddo/stock-scout/issues/351)
