# 종목 유형 판단은 완성된 작은 흐름부터 검증한다

## 현재 기준: 실행 흐름과 판단 품질을 분리한다

2026-10-26 사용자는 #259의 목표를 실제 실행 흐름 검증으로 한정하고, 유용한 유형 판단과 제출 근거의 타당성은 #261의 작은 독립 표본 점검에서 확인하기로 합의했다. 실제 여섯 순위에서 여러 종목을 수집해 최종 종목별 결과와 집계를 출력한 실행은 이미 확보했지만, 전부 미확인이라는 이유로 실행 흐름의 완료까지 막고 있었다. 실행 완료와 판단 품질을 나누어 같은 순위 실행을 반복하는 부담을 줄인다.

#259는 실제 NAS·NYS·AMS 거래량·거래대금 여섯 순위를 수집하고, 여러 종목에 대해 하나의 도구 사용 모델 흐름을 명시적으로 완료해 원본 거래소·종목 코드·순위, 출처 ID·실제 열람 출처·짧은 근거 설명, 포함·제외 사유와 범위 집계를 출력하면 실행 흐름 기준을 충족한다. 유형을 확정하지 못한 종목에는 그 사유를 남기며, 모든 종목이 미확인이어도 분석 불충분을 정확히 알렸다면 실행 흐름 검증의 근거로 사용할 수 있다. `analysis_insufficient`와 종료 코드 2는 유지하며 이를 유용한 유형 판단이나 정상 후보 없음으로 바꾸지 않는다. 중단·공통 장애·입력 및 출처 무결성 오류·한도 도달은 계속 전체 실패다.

[2026-10-22의 실제 여섯 순위 실행 두 건](../llm-security-probe.md#2026-10-22-식별-미확인-종목의-개별-제외)은 종목별 결과와 집계를 출력했으므로 이 실행 흐름 기준의 근거로 사용할 수 있다. 당시의 포함 0·제외 6·미확인 6, 종료 코드 2와 판단 품질 미검증은 그대로 남는다. 완료 판단에 사용하는 실행의 원본 입력·명령·소스·모델·설정·종료 결과·안전한 진단·집계·처리 시간은 보존해야 한다. 복구할 수 없는 과거 실패 입력의 누락은 당시 결론의 한계로 기록하되 #259의 종료를 막지 않으며, 나중 입력으로 소급 복원하지 않는다.

#261은 실제 순위에서 유용한 유형 결과가 나올 때까지 기다리지 않고, 기존 평가 입력 경로로 실행 전에 고른 작은 독립 정답 표본을 점검할 수 있다. 잘못된 포함과 근거 없는 유형 확정, 개별 증권 연결·현재 적용 가능성·ADR 기초 권리를 심사하며 적격 종목 누락은 사유와 함께 개선 대상으로 기록한다. 표본과 평가자용 정답·근거의 분리, 보수적 제외와 기존 출처·실패·인증·비밀·비용 제한은 유지한다. #259의 완료는 판단 품질·다른 시장 데이터·일정·운영값 검증이나 매수 추천 제품 인수의 완료가 아니다.

이 결정은 아래 이력 중 #259의 종료에 유용한 유형 판단을 요구한 조건, 과거 실패 입력 누락을 종료 차단으로 둔 조건과 #261의 유용한 순위 결과 선행 조건을 대체한다. 이번 작업은 로컬 문서와 #237·#250·#259·#261의 이슈 수정안 작성까지다. 코드 변경·추가 실연동·커밋·푸시·원격 이슈 갱신·종료는 포함하지 않는다. 공개 검증 경계는 CLI 입력·stdout·stderr·종료 코드와 외부 HTTP이며, 문서 검토 기준은 `dcfe4f6bfcd738346e6a84f187dfb3e53c4fc697`과 이번에 확보한 이슈 원문이다.

## #261 첫 표본과 점검 범위

2026-10-26 후속 인터뷰에서 첫 품질 점검은 기존 AAPL과 BBD·BBDO 두 사례·세 증권으로 확정했다. 보통주·보통주 성격 ADR의 근거 있는 포함과 우선주 성격 ADR의 확인된 제외를 통과 기준으로 삼고, 보수적 미확인은 부분 충족, 오분류·근거 없는 확정·실행 오류는 실패로 기록한다. 전체 표본 반복 대신 선택한 작은 표본의 유용한 판단과 근거를 먼저 확인하는 선택이다. 최초 두 사례와 관측한 문제의 최소 수정 후 영향받는 사례 재확인을 합쳐 최대 4회로 계획하며, 공통 변경이면 두 사례를 모두 재확인한다. 기존 개발 모델과 실행별 한도·안전 계약을 유지한다. 세부 판정·중단·기록·검증 경계는 [첫 점검 계획](../security-type-evaluation-samples.md#261-첫-점검-계획)을 따른다. 이번 확정은 두 로컬 설계 문서 반영까지이며 구현·실제 호출·커밋·푸시·원격 이슈 변경이나 종료를 포함하지 않는다.

후속 `implement` 요청에 따라 기존 실행 코드와 모델·한도로 두 사례를 실제 평가했고, AAPL 보통주 포함·BBD 우선주 성격 ADR 제외·BBDO 보통주 성격 ADR 포함과 제출 근거의 타당성을 확인했다. 최대 4회 중 2회를 사용했으며 관측한 코드 결함이 없어 실행 코드는 수정하지 않았다. [첫 점검 결과](../security-type-evaluation-samples.md#261-첫-점검-결과)는 선택 표본의 통과이며 전체 시장·실제 순위 판단 품질이나 매수 추천 제품 인수의 완료를 뜻하지 않는다. 후속 요청의 현재 브랜치 커밋과 원격 게시·이슈 종료는 구분한다.

## 이전 합의와 실행 이력

현재 구조는 Q1~Q6 후속 합의에 따른 단일 모델 흐름이며, 식별 미확인의 실패 범위는 문서 끝의 개별 제외 후속 합의를 따른다. 앞선 합의의 조회·판단 분리와 조회 전용 시간 제한은 해당 범위에서 대체하며, 당시 관측과 실패 기록은 유지한다.

2026-10-22 사용자는 개인용 매수 검토 CLI의 규모에 비해 첫 완료 전 검증 요구와 진행 절차가 무거워졌다는 검토를 수락하고 반영을 요청했다. 실제 여러 종목 실행은 조회 120초 제한으로 실패했고 단일 AAPL은 현재 적용 여부 미확인으로 제외됐다. 이 관측은 시간 초과의 세부 원인이나 특정 설정의 성공을 입증하지 않는다. 모든 유형·반례와 전체 표본 3회 통과를 먼저 요구하는 대신, 완성된 작은 흐름을 확인한 뒤 검증 범위를 넓힌다.

첫 완료 기준은 실제 KIS의 NAS·NYS·AMS 거래량·거래대금 여섯 순위에서 여러 종목을 수집하고, 조회부터 추가 도구 없는 최종 판단까지 마쳐 원본 거래소·종목 코드·순위, 근거 ID·열람 출처, 포함·제외 사유와 분석 범위를 출력하는 것이다. 자료가 부족한 종목의 보수적 제외는 허용한다. 모든 유형 확인 실패는 계속 `analysis_insufficient`이며, 이를 유용한 유형 판단 성공으로 표시하지 않는다. 확인된 비적격 유형만 있어 전부 제외된 정상 결과와 구분한다. 적격 종목의 최소 포함 수나 포함률 목표는 첫 완료 조건으로 두지 않고, 포함·제외·미확인 수와 처리 시간을 실제 측정값으로 남긴다.

현재 적용 가능성은 해당 증권을 연결할 수 있는 확인 가능한 최신 자료와 알려진 후속 변경을 검토하는 것으로 판단한다. 자료 기준일·적용 범위·확인 시점을 구분하고, 오래된 자료뿐이거나 구체적인 권리 변경·반대 근거가 해결되지 않아 적용 여부가 불확실하면 제외한다. 확인 범위 이후의 모든 기업행동과 무변경을 전수 입증할 필요는 없다. 조회 시각·티커·이름·모델의 기억·검색 요약만으로 유형이나 현재성을 확정하지 않는다. 명확한 근거 하나면 충분하며 ADR의 보통주 기초 권리와 같은 회사의 별도 증권 구분은 유지한다.

후속 정확도 점검은 실행 전에 고른 작은 독립 정답 표본으로 잘못된 포함과 근거 없는 유형 확정을 우선 확인한다. 정답·근거를 모델에 제공하지 않고 결과와 제출 근거를 함께 심사한다. 적격 종목 누락은 자료 부족·현재성 불확실성 등 사유와 함께 개선 대상으로 기록한다. 전체 8개 사례·11개 증권의 매회 전부 포함, 전체 3회 통과와 수정 후 전체 3회 재시작은 첫 완료와 초기 정확도 점검의 필수 조건에서 제외한다. 기존 표본·정답·입력 해시는 참고 자산으로 보존하며 더 넓은 평가가 필요한 때 사용한다. 알려진 오포함·근거 없는 유형 확정·실행 오류를 숨기거나 통과한 결과만 합치지 않는다. 수정 후에는 영향받는 회귀 검사와 사례를 다시 확인한다.

유형 판단 흐름은 다른 시장 데이터·거래 일정·운영값 검증과 독립적으로 구현·점검할 수 있다. 해당 검증의 미완료를 유형 판단 단계 전체의 착수·완료를 막는 일괄 조건으로 두지 않는다. 그러나 이 단계의 성공으로 완료 세션·가격·일정의 미검증을 해소하거나 매수 추천 제품 인수를 선언하지 않는다. 실제 매수 후보 보고서에 사용하는 데이터·일정·운영 조건은 해당 기능에서 계속 검증한다.

실제 조회한 출처와 종목의 연결, 자료 부족의 제외, 식별 모호함·공통 장애·모델 중단·호출 한도의 전체 실패, 인증·비밀 보호·유료 비용 제한은 유지한다. 현재 모델·강제 시간·호출 한도를 이번 결정으로 변경하지 않으며 시간 초과를 정상 완료로 바꾸지 않는다. #259의 기존 진단 3회는 이미 소진됐고 이 결정은 횟수를 초기화하거나 추가 실제 호출을 승인하지 않는다. 재개 시 필요한 실행 범위나 모델·한도 변경은 실제 관측을 바탕으로 별도로 정한다.

2026-10-22 후속 인터뷰에서 개인용 CLI의 목적에 맞춰 개별 근거 부족의 실패 범위를 줄이기로 합의했다. 모델이 `unknown` 이외의 유형을 제출했지만 근거 목록이 비었거나 인용 근거가 모두 원본 KIS 유형 코드 `01`뿐이면, 코드는 해당 유형 확정을 거부하고 그 종목을 유형 미확인으로 제외한 뒤 나머지 종목을 처리한다. 원래 제출한 유형과 거부 사유를 비밀 값·원문 모델 응답 없이 남겨 모델 오류를 숨기지 않는다. 정상적인 유형 확정이나 확인된 비적격 유형으로 바꾸지 않으며, 모든 종목의 유형 확인이 실패하면 계속 분석 불충분으로 알린다. 존재하지 않는 근거 ID·다른 종목의 근거 연결·식별 모호함과 공통 장애는 전체 실패로 유지한다. 근거 목록을 비우거나 유형을 미확인으로 바꾸어 참조 무결성 오류를 숨기지 않는다. 이 변경은 근거 없는 포함을 허용하지 않으면서 한 종목의 근거 부족으로 전체 결과가 사라지는 비용을 줄이기 위한 선택이며, 기존 두 조건의 전체 실패 계약만 대체한다.

같은 인터뷰에서 실제 점검은 다음 구현 작업의 범위·가설과 함께 최대 3회를 한 묶음으로 승인받기로 합의했다. 개발 모델 `gpt-6-luna`와 기존 실행별 시간·호출·비용 한도를 유지하며, 근거 없이 같은 실행을 반복하거나 3회를 모두 채우기 위해 호출하지 않는다. 각 실행의 입력·안전한 진단·실패 결과는 즉시 보존하되 문서 정리·최종 리뷰·전체 테스트는 구현 작업 끝에 모은다. 중간에는 변경에 영향받는 검사를 수행하고, 최종 검사 후 수정이 생기면 해당 결과를 무효화하고 필요한 검사를 다시 수행한다. 문서만 변경한 작업에서는 전체 코드 테스트를 반복하지 않는다. 과거에 소진한 횟수와 실패 기록은 유지하며 이번 설계 합의가 추가 실제 호출을 승인하지는 않는다.

기존 #259의 진단 기록, #260의 표본 준비 완료와 과거 체크 상태는 당시 근거로 보존한다. #259는 첫 흐름 완성, #261은 작은 독립 표본의 정확도 점검을 담당한다. 새 범용 평가 프레임워크·세부 티켓·반복 문서 작업을 필수 산출물로 추가하지 않는다. 변경한 동작에 맞는 공개 CLI·외부 HTTP 회귀 검사와 필요한 검토·검증만 수행하며 문구를 고정하는 검사는 만들지 않는다.

이 결정은 [ADR 0007](0007-llm-security-type-judgment.md)과 [이전 평가 재개 설계](../security-type-live-evaluation-design.md)의 평가 횟수·전부 포함·일괄 선행 조건과 위 두 근거 부족 조건의 실패 범위를 해당 범위에서 대체한다. 개별 제외 처리의 구현·검증 현황은 [CLI 안내](../llm-security-probe.md)를 따르며 기존 실제 실패를 성공으로 다시 기록하지 않는다. 문서·명세 반영의 승인과 실제 구현·추가 실연동·제품 인수는 구분한다.

2026-10-22 추가 설계 인터뷰에서 사용자는 조회와 유형 판단을 하나의 모델 흐름으로 합치고 별도 조회 산출물과 두 번째 판단 호출을 없애기로 합의했다. 모델은 필요한 도구를 사용한 뒤 유형·포함 여부·근거를 제출한다. 코드는 입력 소속·출처 연결·출력 구조·명시적 완료·실행 한도를 검사하고, 의미 판단의 정확도는 작은 실제 표본으로 확인한다. 이 선택은 두 단계 구조가 실제 실패 원인으로 입증됐기 때문이 아니라 개인용 CLI의 구현과 모델 간 전달 부담을 줄이기 위한 것이다.

종목별 유형·포함 및 제외 사유·실제 읽은 출처·짧은 근거 설명을 필수로 남긴다. 증권 연결·기준일·적용일·후속 변경·현재성 설명을 모든 근거의 개별 필수 필드로 요구하지 않는다. 날짜와 변경 정보는 판단에 영향을 줄 때 기록하며 다른 증권의 자료, 오래된 자료의 알려진 충돌과 ADR의 기초 권리는 계속 확인한다. 확인이 부족하면 제외한다. 실제 열람과 출처 연결이 내용의 타당성을 입증한다는 의미는 아니다.

다음 구현은 변경·영향받는 회귀 검사·최대 3회의 실제 점검·최종 검증을 한 작업으로 확정한다. 실행 기록은 즉시 보존하고 문서 정리·최종 리뷰·전체 검사는 작업 끝에 모은다. 개발 모델은 `gpt-6-luna`를 유지한다. 후속 응답에서 사용자는 전체 모델 흐름의 180초 한도와 모델 요청 12회·KIS 정보 32회·관측 웹 호출 32회 상한을 유지하고, 별도 조회 단계의 120초 제한을 제거하는 데 합의했다. 제한 도달이나 명시적 완료 없는 모델 중단은 계속 전체 실패다.

실행 명령과 종목별 결과·원본 순위·출처·제외 사유·범위 집계는 유지한다. 별도 조회 산출물과 조회·판단 단계별 통계는 제거하고 실행 전체의 시간·호출 수를 남긴다. 폐기한 필드를 채우는 호환 계층은 만들지 않는다. 모델 단계의 진단도 통합한 흐름에 맞추며 입력·인증·순위 단계의 진단과 기존 오류·종료 코드의 의미는 유지한다. 근거 부족의 개별 제외, 잘못된 출처 참조·식별 오류·공통 장애의 전체 실패와 전부 미확인일 때의 분석 불충분은 유지한다.
