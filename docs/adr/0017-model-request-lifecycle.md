# 모델 요청 생명주기는 공통 모듈이 소유한다

일정 영향 판단·증권 유형 판단·매수 후보 선정과 의미 검토가 각각 명시적 완료·오류·스트림 종료를 관리하면 같은 실행 규칙을 바꿀 때 여러 판단 흐름을 함께 수정해야 한다. 요청별 생명주기를 공통 모듈이 직접 소유하고, 각 판단 흐름에는 입력·도구·도메인 검증·인증·예산·공개 오류 매핑·유료 전환 정책을 남긴다. 완료 횟수와 요청 연결을 호출자가 계속 관리하는 얕은 유틸리티 대신, 작은 인터페이스 뒤에 요청별 상태와 스트림 처리를 모아 상태와 처리 규칙의 변경을 한곳에 모은다.

이 결정은 동작을 유지하는 리팩터링이다. 정상 성공은 중간 도구 요청을 포함한 각 요청의 명시적 완료가 정확히 한 번 확인되고 스트림 소비가 끝난 뒤에만 인정한다. 실패를 발견한 뒤 중단하는 시점은 기존 흐름에 맞춘다. 일정은 원시 공급자 오류·중복 완료를 기록하며 계속 읽되 SDK 오류에서는 중단한다. 유형은 공급자·SDK 오류를 기록하고 소비가 끝난 뒤 실패하며, 추천·의미 검토는 공급자·SDK 오류·중복 완료와 완료 없는 EOF에서 즉시 실패한다. 이 차이를 통일하면 취소·후속 도구 실행·오류 우선순위가 달라질 수 있어 공통 모듈 안에 제한된 종료 정책으로 보존한다.

요청 연결과 완료·오류·종료 판정은 공통 모듈이 담당한다. 도구·웹 출처 처리와 기존 유형 진단은 요청에 연결된 사실을 사용하되 생명주기 상태의 소유자가 되지 않는다. HTTP 본문 종료와 SDK 스트림 종료는 구분하며 취소·읽기 실패·후속 정리 실패와 기존 오류 우선순위를 보존한다. 관측은 기존 실행별 소유자를 재사용하고, 관측 저하·생략·직렬화 실패가 정상 완료의 판정을 바꾸지 않도록 실행 상태와 분리한다.

[ADR 0013](0013-llm-calendar-notice-assessment.md)·[ADR 0015](0015-subscription-buy-candidate-report.md)·[ADR 0016](0016-bounded-paid-recommendation.md)의 단계별 정책은 유지한다. 공개 검증은 기존 CLI의 입력·stdout·stderr·종료 코드와 외부 HTTP·시계 mock을 사용한다. 완료 누락·중복·완료 뒤 오류·요청 귀속·관측 실패·유료 전환의 회귀와 음성 대조로 구조 변경의 계약 보존을 확인하며 실제 공급자 호환성이나 판단 품질의 검증으로 확대하지 않는다.
