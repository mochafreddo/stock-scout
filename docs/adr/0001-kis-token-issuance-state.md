# KIS 발급 기록이 없는 실행의 대기와 공통 발급 제한

[#247](https://github.com/mochafreddo/stock-scout/issues/247)의 설계 인터뷰에서 2026-10-18 합의한 결정이다. 토큰과 발급 제한 상태는 [부모 명세 #243](https://github.com/mochafreddo/stock-scout/issues/243)에 승인된 전용 캐시에서 관리한다.

발급 시도 기록이 전혀 없으면 첫 실행과 기록 삭제를 구분할 수 없으므로 현재 시각을 안전하게 기록하고 발급 없이 종료한다. 최초 실행의 불편을 감수하고 최소 5분 뒤 재실행하도록 안내하여, 기록 삭제 직후 즉시 재발급하는 경로를 막는다. 이때 기록하는 시각은 실제 발급 요청을 보냈다는 증거가 아니다.

첫 버전은 현재 앱 키와 시크릿 조합에 연결된 토큰 하나만 보관한다. 조합의 해시로 연결을 확인하며 원문 앱 키·시크릿은 저장하지 않는다. 어느 쪽이든 달라지면 기존 토큰을 재사용하지 않으며, 5분 발급 시도 제한과 발급 잠금은 같은 캐시를 사용하는 CLI 전체에 공통으로 적용한다. 여러 앱 키의 토큰을 동시에 관리하는 편의보다 단순한 상태 관리와 자격 증명 변경을 통한 제한 우회 방지를 우선한다. 해시 일치는 입력 조합이 같다는 뜻이며 시크릿의 실제 유효성을 입증하지 않는다.

기록된 마지막 발급 시각이 현재보다 미래이면 기록을 초기화하지 않고 그 시각에서 5분이 지난 시점까지 발급을 거부한다. 시스템 시계가 뒤로 이동했을 때 성급하게 발급하는 대신 시계 확인 안내와 남은 시간을 표시하며, 잘못된 먼 미래 시각은 수동 복구가 필요할 수 있다.

토큰만 손상된 경우에는 정상적인 발급 시도 기록과 제한을 지켜 새 토큰을 확보한다. 발급 시도 기록 자체가 손상된 경우에는 자동 초기화하지 않고 실패한다. 수동 복구 후에도 새 기록을 안전하게 남기고 최소 5분 뒤 재실행하도록 하여, 기록 손상을 즉시 재발급의 근거로 사용하지 않는다.

비정상 종료 뒤 남은 발급 잠금은 자동 삭제하지 않는다. 수동 복구 절차는 이 CLI의 모든 실행이 종료됐는지 확인한 뒤 잠금만 제거하며 토큰과 발급 시도 기록은 보존한다. PID가 존재하지 않는다는 사실만으로 잠금을 자동 삭제하거나 발급 제한을 초기화하지 않는다.

이 결정은 같은 캐시와 시스템 시각을 사용하는 CLI의 운영 정책이다. 다른 프로그램의 호출이나 공급자 전체 제한을 통제한다는 의미가 아니며, 인증 구현과 실제 발급·재사용 검증은 아직 수행하지 않았다.
