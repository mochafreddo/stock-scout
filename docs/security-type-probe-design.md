# 종목 유형 자동 검증 CLI 설계

2026-10-19 [#250](https://github.com/mochafreddo/stock-scout/issues/250)의 후속 설계 인터뷰에서 합의하고 최종 확인한 범위다. [외부 공식 자료 조사](official-security-type-validation.md)와 [ADR 0005](adr/0005-official-security-type-sources.md)를 바탕으로 한다. 이 문서는 조사 결과나 구현 완료 기록이 아니며 실행·게시 승인을 뜻하지 않는다.

## 합의한 범위

다음 단계는 자료 수집, KIS 증권 연결, 유형과 ADR 기초 권리 확인, 근거와 미검증 사유 출력을 재현하는 작은 자동 검증 CLI다. NYSE 매핑과 SEC 공시를 우선 검증 후보로 삼으며 이용 조건을 확인한 범위에서 진행한다. 후보군 본 구현과 후속 차단 해제는 별도로 판단한다.

현재성은 출처별 기준일·적용일·갱신 방식·후속 변경 확인 범위를 명시하고 실행 시 검사한다. 오늘 내려받은 파일이나 최신 연차보고서라는 사실만으로 현재 권리를 확정하지 않으며 모든 변경의 지연 없는 반영을 보장했다고 주장하지 않는다. 확인할 수 없는 조건은 미검증으로 남기고 임의 유효기간으로 통과시키지 않는다.

첫 CLI는 저장된 KIS 관측 자료의 거래소·원본 종목 코드·선택적 식별자를 입력받고 외부 공식 자료는 새로 수집한다. KIS 신규 호출과 인증 변경은 제외한다. 결과에는 KIS 관측 시각을 표시하며 현재 KIS 순위와의 실연동 성공으로 취급하지 않는다.

SEC 자동 해석은 티커·거래소·증권 종류·ADR 기초 권리를 같은 증권의 구조화된 문맥으로 연결할 수 있는 형식부터 지원한다. 회사 단위 값이나 자유 문장의 키워드만으로 권리를 추정하지 않는다. 정상 문서에 지원하는 권리 근거가 없으면 유형 미확인으로 남기고, 문서 수집·파싱 자체의 실패는 조회·해석 실패로 구분한다. 기존 식별 모호함과 필수 자료 실패의 전체 실패 계약은 유지한다.

AAPL·SHOP·GOOG/GOOGL, BBD/BBDO·TSM, ACONW/ADSEW, SPY/VXX, BAC/B·BAC/L은 검증 표본으로 사용한다. 종목별 정답을 코드에 넣지 않으며 다른 입력에도 같은 규칙을 적용한다. 근거가 부족하면 미확인 또는 실패를 출력한다. 표본의 성공을 전체 시장 정확도 보장으로 확대하지 않는다.

SEC 공시는 입력 종목에서 공식 식별 자료로 발행사를 찾고 관련 공시의 증권별 문맥까지 자동으로 연결한다. 발행사 발견과 개별 증권 식별을 구분한다. 사람이 미리 지정한 종목별 공시 URL은 검증용 입력으로만 허용하며 자동 발견의 증거로 취급하지 않는다. 지원할 공시 종류와 후속 변경 확인 범위는 공식 자료로 확인한 뒤 명시한다.

검증 완료에는 보통주와 적격 ADR의 실제 자동 확인을 모두 요구한다. 같은 회사의 서로 다른 권리를 구분하고 우선주·워런트·ETF·ETN의 제외 근거를 확인하며, 미해결 충돌의 유형 미확인 처리와 식별 모호함·필수 자료 장애의 실패 처리를 검증한다. 모든 입력을 미확인으로 제외한 결과만으로 목적을 달성했다고 판단하지 않는다. 필수 유형이나 현재성 조건이 미검증이면 부분 완료로 남기며 모의 검사와 실제 자동 판별 성공을 별도로 보고한다.

## 검증 단계에서 확정할 항목

출처별 채택 조건, 지원 공시와 후속 변경 확인 범위, 현재성 검사 방법, 유효기간과 호출·시간 제한은 공식 자료와 실제 검증 근거로 확정한다. 미확정 값을 검증된 운영값으로 취급하지 않는다. 기존 유형 검증과 일정·장전 데이터·운영값의 미충족 조건 및 후속 차단은 유지한다.

## 검증 경계와 검토 기준

최소 TypeScript CLI의 입력·stdout·stderr·종료 코드를 공용 검증 경계로 사용한다. 모의 검사와 실제 외부 자료 검증을 구분하며, 내부 함수 배치나 문서 문구 자체를 고정하는 검사는 만들지 않는다.

저장소는 `stock-scout`이며 기존 검토 기준점 `835bebed44de81a821660370428101b931953e05`를 유지한다. 이번 설계의 시작점은 `195454d8b7f03a2087292d78762087d3fb66299a`다. 시작점 이후 이 작업의 변경과 설계 문서를 구분하여 고정 변경본을 Standards·Spec 두 축으로 검토한다. 시작 전에 존재한 `GLOSSARY.md`와 `docs/kis-data-validation.md`의 미커밋 수정은 별도 작업으로 보존한다.

## 작업 승인 경계

사용자는 최종 작업 범위·공용 검증 경계·검토 기준을 함께 확인했다. 설계 인터뷰는 완료했으며 구현·실연동·이슈 게시·커밋·푸시는 별도 명시적 요청 후 진행한다. 이번 설계 확정으로 기존 이슈의 완료 조건이나 후속 차단을 해제하지 않는다.

## SEC 관측 CLI 이후의 추가 설계 인터뷰

2026-10-19 SEC 관측 CLI 구현 이후 다시 시작한 인터뷰에서 다음 단계의 목표를 합의했다. SEC 접근 조건·HTTP 403과 NYSE 자동 이용 조건을 먼저 확인하여, 공식 자료를 지속적으로 자동 수집할 출처의 채택 여부를 판단한다. 채택 가능한 경로를 확보하면 증권 연결·권리·현재성의 세부 설계를 진행하고, 확보하지 못하면 기존 제약을 재논의한다. 이 단계에서 후보군 분류기를 확장하거나 후속 차단을 해제하지 않는다.

조사는 이미 검토한 SEC와 NYSE 두 출처에 한정한다. 다른 공식 출처의 탐색은 이번 결과에 따른 별도 결정으로 남긴다. 공개 공식 문서와 허용된 최소 실제 요청으로 접근·자동 이용 조건을 확인한 뒤에도 조건이 불명확하면 채택 보류로 조사를 끝낸다.

출처별 결과는 채택 가능·채택 보류·채택 불가로 구분하고 근거와 재개 조건을 남긴다. 접근 성공만으로 자동 이용이 허용됐다고 판단하지 않으며 HTTP 403만으로 출처를 사용할 수 없다고 단정하지 않는다. 이 판정은 수집 경로의 채택에 한정하며 증권 연결·권리·현재성의 검증 완료를 뜻하지 않는다.

사용자는 다음 최종 작업 범위·공용 검증 경계·검토 기준을 함께 확인했다. 조사 결과는 출처별 채택 판정·근거·재개 조건으로 기존 조사 문서에 남긴다. 다른 출처 탐색, 파서·분류기 확장과 후속 차단 해제는 별도 결정으로 남긴다.

검증에서는 실제 요청 조건·HTTP 결과와 공식 이용 조건을 구분한다. 기존 CLI를 실행하면 입력·stdout·stderr·종료 코드를 공용 검증 경계로 사용한다. 코드 변경 없이 문서·증거의 정합성을 검토하며 모의 검사와 실제 수집 결과를 구분한다.

저장소는 `stock-scout`이며 기존 검토 기준점 `835bebed44de81a821660370428101b931953e05`를 유지한다. 이번 변경의 시작점은 `374607aea1f0c151728191e59944e2d896257f06`이다. 이번 책임 범위의 고정 변경본을 Standards·Spec 두 축으로 검토하고 시작 전에 존재한 `GLOSSARY.md`와 `docs/kis-data-validation.md`의 미커밋 수정은 제외하여 보존한다.

추가 설계 인터뷰는 완료했다. 설계 합의와 조사·실연동 실행, 이슈 게시, 커밋·푸시는 구분하며 실행과 게시 작업은 사용자의 별도 요청 후 진행한다. 이번 합의로 기존 완료 조건이나 후속 차단을 해제하지 않는다.

## 수집 경로 채택 보류 이후의 설계 인터뷰

2026-10-19 SEC·NYSE 수집 경로의 채택 보류 이후 다시 시작한 인터뷰에서, 사용자는 다른 무료·공개 공식 출처로 조사 범위를 넓히는 방향을 선택했다. 무료·무로그인, 공식 출처, 매일 수동 판정 없는 자동화, 개별 증권의 유형·권리·현재성 확인 조건은 유지한다. SEC·NYSE의 기존 경로는 채택 보류로 둔다. 사용자는 최종 확인 제안 뒤 `implement`를 요청하여 이 범위의 조사 실행과 커밋을 승인했다. 이슈 게시와 푸시는 이번 요청에 포함하지 않는다.

출처마다 접근·자동 이용 조건을 먼저 확인하고, 통과한 출처만 기존 반례에 대조한다. 새 파서·분류기 개발은 후속 단계로 둔다.

거래소 등의 공식 목록·API·다운로드 자료를 우선 탐색하고, 부족한 ADR 권리는 발행사나 예탁기관의 공식 자료로 보완하는 순서로 조사한다.

선정한 출처를 한 차례 평가한 뒤 유망한 경로가 없으면 미해결 사유를 남기고 조사를 종료하여 제약을 다시 논의한다. 새 출처를 계속 추가하거나 모든 종목을 미확인으로 제외한 결과를 성공으로 인정하지 않는다.

기존 보고서와 공식 안내로 후보를 찾고 유망한 새 수집 경로를 최대 3개 선정하여 상세 평가한다. 같은 목록의 파일 형식이나 주소 차이는 하나의 경로로 센다. 선정 후 실패한 경로를 새 후보로 계속 교체하지 않는다.

자동 이용 조건을 확인한 공개 경로에서 목록·대표 표본을 받는 데 필요한 최소 실제 요청을 조사 범위에 포함한다. 로그인·새 자격 증명·문의 전송·접근 제한 우회는 포함하지 않으며 접근 실패나 조건 불명확은 보류 사유로 남긴다.

일부 유형에만 쓸 수 있는 출처는 입증한 용도에 한해 보완 후보로 기록한다. 조사 자체는 한계와 부정적 결과까지 보고하면 완료할 수 있지만, #250의 자동 판별 검증과 후속 차단 해제에는 기존 필수 조건의 충족이 필요하다.

확정한 작업은 이 저장소의 문서·선별 증거를 산출물로 삼고, 실제 수집의 요청 조건·HTTP 결과·자료 구조·표본 대응·적용 범위와 이용 조건을 구분하여 검증하는 것이다. 기존 CLI를 실행하면 입력·stdout·stderr·종료 코드를 공용 검증 경계로 사용한다. 문서·증거의 정합성·공백·링크를 확인하며, 코드 변경이 없는 조사를 위해 새 파서나 테스트를 만들지 않는다.

기존 검토 기준점 `835bebed44de81a821660370428101b931953e05`를 유지하고 이번 인터뷰의 시작 HEAD는 `37ef7a385800786e07b4084185ee00cd34c8ae56`로 기록한다. 이번 설계 문서와 이후 조사 변경의 고정 변경본을 Standards·Spec 두 축으로 검토하며, 시작 전에 존재한 `GLOSSARY.md`와 `docs/kis-data-validation.md`의 미커밋 변경은 이번 책임 범위에서 제외한다. 최종 범위·검증 경계·검토 기준의 확인과 조사 실행·이슈 게시·커밋·푸시 요청은 구분한다.

이번 실행의 상세 평가 대상은 Cboe 미국 주식 거래 종목 참조 자료, BNY DR Directory, Citi Global DR Directory의 세 경로로 고정한다. 같은 경로의 안내·이용 조건·배포 형식은 별도 후보로 세지 않으며, 평가 결과가 보류여도 다른 후보로 교체하지 않는다.

## 제3자 공급자 조사 설계

2026-10-19 위 한정 조사 종료 후 사용자는 [ADR 0006](adr/0006-third-party-security-type-sources.md)의 공급자 범위·비용·계정·판별 근거·종료 조건을 최종 확인하고 `implement`로 조사 실행과 현재 브랜치의 커밋을 요청했다. 유형과 개별 상장 증권 연결에 한해 자동 이용을 허용하는 제3자 공급자까지 비교하며, 시세·거래량·거래대금·순위는 KIS로 유지한다. 앞선 무료·공개 공식 출처 한정 조사와 이번 범위를 구분한다.

무료 요금제를 먼저 검토하며 유료 후보는 가격과 필요한 요금제를 비교한 뒤 예산을 별도로 결정한다. 개인이 직접 가입하고 API 키를 발급받을 수 있는 서비스를 대상으로 하며 영업 문의·협상·기업 계약이 필수인 서비스는 제외한다. 공개 문서로 후보를 추린 뒤 최대 3개를 이용 조건·유형·증권 연결·최신성·비용 기준으로 상세 평가한다. 충족 후보가 없으면 부족한 조건과 재개 조건을 기록하고 조사를 종료한다.

문서로 정의된 공급자 분류를 근거로 인정하며 모든 종목의 발행사 원문 대조를 요구하지 않는다. ADR 표시만으로 기초 권리를 추정하지 않고 기존 표본·반례와 모순을 확인한다. 실제 응답이 필요한 항목은 미검증으로 남기며 문서 예시와 실제 API 응답을 구분한다. 가입·약관 동의·결제·자격 증명 생성·실연동, 파서·분류기 확장, 이슈 게시·푸시는 이번 실행에 포함하지 않는다. #250의 자동 판별 검증과 후속 차단은 유지한다.

이번 산출물은 공급자 비교 보고서와 선별 근거다. 문서·증거의 정합성·공백·링크를 확인하며 코드 변경이 없어 새 TDD·변이 검사는 추가하지 않는다. 기존 CLI를 향후 변경하면 입력·stdout·stderr·종료 코드를 공용 검증 경계로 사용한다. 이번 실행의 최종 전체 회귀 검사는 모의 외부 통신을 사용하며 실제 공급자 호환성·유형 판별 성공과 구분한다.

기존 검토 기준점 `835bebed44de81a821660370428101b931953e05`를 유지하며 이번 책임 범위의 시작점은 `0a0e88bf47c79ab2bbbda26942f60b94e94884e9`다. 해당 시작점 이후 이번 설계와 조사 변경의 고정 변경본을 Standards·Spec 두 축으로 검토하며 다른 티켓의 과거 변경과 구분한다. 시작 전에 존재한 `GLOSSARY.md`와 `docs/kis-data-validation.md`의 미커밋 변경은 제외하고 보존한다.

## Massive 이용 범위 확인의 후속 설계 인터뷰

2026-10-19 제3자 공급자 조사 종료 후 다시 시작한 인터뷰에서 사용자는 다음 단계를 Massive 참조 메타데이터의 개인 CLI 자동 이용 범위 확인에 한정하는 추천안을 수락했다. 보통주·적격 ADR의 기존 기준은 유지한다. 기존 자료의 미해결 조항과 필요한 확인을 구체화하고 공개 자료로 결론이 나지 않으면 문의 초안까지 준비한다. 문의 전송 여부는 별도로 결정하며 다른 공급자 조사로 자동 확대하지 않는다.

개인 이용은 허용하지만 실제 응답의 공개 재배포는 허용하지 않는 공급자도 검토 대상으로 유지한다. 계약이 허용하는 범위에서 원자료는 저장소 밖 비공개 위치에 보관하고 공유 문서에는 공개 가능한 검증 방법·결론·한계를 기록한다. 구체적인 보관 위치와 재현 방법은 공급자를 정한 뒤 확정한다. 이 합의 자체는 원자료 저장이나 공개 권한을 확인한 결과가 아니다.

이용 범위 확인 결과는 허용 범위 확인·명시적 제한 확인·판단 보류로 구분한다. 공개 자료로 판단할 수 없으면 미해결 조항·부족한 근거·재개 조건과 문의 초안을 남기고 이번 작업을 종료한다. 이용 범위가 확인돼도 실제 유형·증권 연결·현재성 검증은 다음 단계로 둔다.

문의 초안은 개인이 터미널에서 실행하는 비상업 도구라는 용도를 설명한다. Massive 유형·식별 자료의 자동 조회, KIS 종목과의 연결 및 후보 포함 여부 판단, 필요한 참조 응답의 비공개 저장·검증, 원자료를 제외한 검증 방법·결론의 공유 문서 기록을 구분하여 각 허용 범위를 질문한다. 시세·거래량·순위는 KIS에서 수집한다는 점을 밝히며 계정·자격 증명·개인 투자 내역은 담지 않는다. 문의 전송은 별도 결정이다.

사용자는 전체 작업 범위·공용 검증 경계·검토 기준을 함께 최종 확인했다. 산출물은 기존 조사 보고서의 후속 판정과 필요한 경우 문의 초안이다. 공개 공식 자료의 근거·링크·공백과 기존 요구사항의 정합성을 확인한다. 코드 변경이 없는 조사이므로 새 코드 테스트는 추가하지 않는다. 향후 CLI를 변경하면 입력·stdout·stderr·종료 코드를 공용 검증 경계로 유지한다.

기존 검토 기준점 `835bebed44de81a821660370428101b931953e05`를 유지하며 이번 인터뷰의 시작 HEAD는 `97f90defcd98efa054431f01eb2966083cf36ef2`다. 시작 시 Git 작업 트리에 변경은 없었다. 시작점 이후 이 작업의 변경을 다른 작업과 구분하여 고정 변경본을 Standards·Spec 두 축으로 검토한다.

설계 인터뷰는 완료했다. 설계 확정과 조사 실행·이슈 게시·커밋·푸시는 구분하며 실행과 게시 작업은 사용자의 별도 요청 후 진행한다. 이번 합의는 공급자 채택·가입·키 발급·결제·실연동·분류기 구현의 승인이 아니며 기존 미검증 조건과 후속 차단을 유지한다.

## Massive 문의 경로의 후속 설계 인터뷰

2026-10-19 공개 자료 확인 종료 후 사용자는 준비된 문의 초안을 바탕으로 Massive에 이용 범위를 확인하는 추천 방향을 수락했으나, 이후 문의가 반복해서 다음 단계가 되는 전제를 문제 삼았다. 문의 경로는 재검토 상태이며 발송 주체·정보 범위의 세부 설계는 보류한다. 후속 인터뷰는 미확정 사항이 차단하는 작업의 범위와 필요한 자료부터 좁혀 읽는 절차를 다룬다. 실제 문의 전송은 승인되지 않았으며 공급자 채택과 실제 유형·ADR 기초 권리·KIS 연결·현재성 검증은 미완료로 유지한다.

### 재검토 합의

미확정 사항은 다음 순서로 평가한다.

1. 확인한 사실과 그 근거를 기록한다.
2. 남은 해석을 구분하고, 명시적 제한·근거 간 모순·설명 부족 중 어디에 해당하는지 제시한다.
3. 해당 미확정 사항에 직접 의존하여 막히는 작업과 의존하지 않아 계속할 수 있는 작업을 제시한다.
4. 문의를 추천할 때는 해결할 질문과 기존 근거로 판단할 수 없는 이유를 제시한다.

Massive API의 실제 사용을 보류하더라도 저장된 KIS 자료 검토나 독립적인 일정 검증은 계속할 수 있다. 설명 부족만으로 문의나 답변 대기를 필수로 만들지 않으며 실제 사용·채택·후속 구현의 진행 여부는 각각의 필수 조건으로 판단한다. 기존 후속 구현 차단을 해제하려면 해당 근거는 별도로 충족해야 한다.

자료 읽기는 dotfiles의 `.claude/rules/skill-overrides.md`에 있는 공통 절차를 따른다. 필수 지침 전문 읽기와 원문 보존을 유지하고 기존 절차를 보완하며 새 도구나 중복 규칙은 만들지 않는다.

사용자는 이 문서와 공통 절차의 수정·검증 범위를 최종 확인했다. 이번 변경의 비교 기준은 stock-scout의 `f66f7a0dbfa29e058e8b0fce2133709a1764c760`과 dotfiles의 `0d1cbb7f9d191a314c33a85f62d1f0d7fccd9c4d`로 한다. 문서 정합성·공백·링크와 Standards·Spec 두 축을 확인하며 새 코드 테스트는 추가하지 않는다. CLI 변경 시 공용 검증 경계는 입력·stdout·stderr·종료 코드를 유지한다. 이 합의에는 문의 전송·이슈 게시·커밋·푸시를 포함하지 않는다.

## 2026-10-20 차단 범위와 다음 작업의 설계 인터뷰

사용자는 이번 인터뷰를 미확정 사항이 직접 차단하는 작업을 구체화하고 다음 실행 작업 하나를 정하는 범위로 진행하는 추천안을 수락했다. 자동 조회·분류, 응답 보관, 검증 결과 공개를 각각 평가하고 명시적 제한·근거 충돌·설명 부족을 구분한다. 후보군 기준과 공급자 범위 및 문의를 필수 단계로 두지 않는 기존 합의는 유지한다.

다음 작업은 Massive의 자동 이용·필요한 응답 보관에 관한 기존 보류 판단을 한 차례 재검토하는 것으로 정했다. 기존 근거에서 명시적 제한과 적용 관계의 설명 부족을 구분하고 실제 검증 재개에 부족한 근거를 특정한다. 결과 공개는 별도로 판단하며 이번 재검토만으로 공급자 채택이나 #250 완료를 선언하지 않는다.

합의된 내용은 설계 문서에 기록하며 새 용어나 장기 결정이 생기면 용어집·ADR에 반영한다. 조사 실행은 별도 요청 후 진행한다. 이 인터뷰의 시작 HEAD는 `679e4c87347bea1625150716231e4afcbd6dc3ab`이며 시작 시 Git 작업 트리에 변경은 없었다.

사용자는 Q3의 최종 범위·검증 기준을 수락하고 `$implement`로 실행을 요청했다. 기존 근거와 직접 관련된 최신 공식 자료를 한 차례 대조하고 자동 이용·필요한 응답 보관의 사실·해석·차단 범위·부족한 근거를 기존 보고서에 기록한다. 공개 권한은 별도로 판단하며 해결되지 않으면 보류 이유를 구체화해 종료한다. 문서 정합성·출처·링크·공백과 Standards·Spec 두 축을 검토한다. 문서 작업이므로 새 코드 테스트는 추가하지 않으며 기존 전체 회귀 검사를 최종 단계에서 실행한다. 향후 CLI 변경의 공용 검증 경계는 입력·stdout·stderr·종료 코드로 유지한다.

검토 범위는 이번 시작 HEAD 이후 이 작업의 설계·재검토 변경이며 다른 저장소는 변경하지 않는다. `implement`에 따라 현재 브랜치에 커밋한다. 문의 전송·가입·키 발급·결제·실제 API 검증·분류기 구현·이슈 게시·푸시는 포함하지 않는다. 재검토 결과는 [기존 보고서](third-party-security-type-sources.md#2026-10-20-자동-이용보관-차단-범위-재검토)에 기록한다.

## 2026-10-20 LLM 유형 판단의 설계 인터뷰

사용자는 KIS 거래량·거래대금 순위의 자동 수집을 유지하고, LLM이 조회 근거를 바탕으로 종목 유형과 추천 여부를 함께 판단하는 방향을 수락했다. 보통주와 적격 ADR만 추천하고 ETF·ETN·우선주·워런트를 제외하는 제품 조건은 유지한다. 종목을 사용자가 직접 입력하는 방식으로 첫 목표를 바꾸는 제안은 철회했다.

유형을 확정하는 범용 코드 분류기를 추천 구현의 필수 선행 산출물로 삼는 대신, LLM이 필요한 정보를 조회하고 유형 판단 근거·선정 이유·위험을 제시하도록 설계한다. 이름이나 모델의 기억만으로 유형을 추정하지 않으며 유형을 확인하지 못한 종목은 추천에서 제외한다. 코드는 추천 종목이 입력 순위에 속하는지, 최대 후보 수·필수 출력·호출 예산을 지켰는지 검사한다. 기존 반례는 이 방식의 실제 평가에 사용하며 LLM 판단의 정확성이 입증된 것으로 취급하지 않는다.

사용자는 Q4에서 KIS 조회 함수와 OpenAI 웹 검색을 우선 구성 후보로 삼고 실제 ChatGPT 구독 인증 경로에서 호환성을 확인하는 추천안을 수락했다. 첫 구성에 MCP 서버를 필수로 두지 않는다. 웹 검색이 지원되지 않으면 별도 검색 API를 직접 도구로 연결하는 방안을 비교하고 그때 MCP의 필요성도 판단한다. 별도 서비스의 자동 가입·키 발급·결제나 구독 경로의 검색 미지원만을 이유로 한 유료 모델 API 전환은 승인하지 않았다. 검색 자료는 종목 유형·증권 연결의 근거로 사용하며 기존 시세·거래량·거래대금·순위의 KIS 공급자 원칙과 뉴스 수집 제외 범위는 유지한다.

사용자는 Q5에서 자료 부족이나 종목별 유형 자료 조회 실패는 해당 종목을 제외하고 나머지 분석을 계속하는 추천안을 수락했다. 제외 사유와 분석 범위가 줄었다는 사실을 표시한다. KIS 순위 수집 실패와 모델 실행 실패는 전체 실패로 처리하며 모든 종목의 유형 확인이 실패하면 정상적인 후보 없음과 구분하여 분석 불충분으로 알린다. 이는 앞선 필수 유형 자료 조회 실패의 전체 실패 계약을 변경하는 합의이며, 인증·서비스 전반의 장애와 종목별 실패를 구분할 구체적 경계는 후속 설계에서 확정한다.

사용자는 Q6에서 추천 종목마다 해당 거래소·종목 코드에 대응하는 유형 근거와 출처를 요구하는 추천안을 수락했다. 명확한 근거 하나면 충분하지만 확인된 반대 근거는 해결해야 한다. ADR은 보통주 성격까지 확인하며 검색 요약이나 회사명만으로 판단하지 않는다. 코드는 근거 기록의 존재와 형식을 검사하고 의미의 타당성은 LLM 판단과 별도 평가로 확인한다.

사용자는 Q7에서 인증 실패·검색 서비스 전체 장애·호출 한도 도달로 필요한 확인을 계속할 수 없으면 전체 실패로 처리하는 추천안을 수락했다. 공통 장애에 따른 제외가 정상 추천으로 표시되지 않게 한다.

사용자는 Q8에서 기존 반례를 정답이 확인된 평가 사례로 사용하고 제외 대상의 잘못된 포함과 근거 없는 유형 확정이 없어야 통과하는 추천안을 수락했다. 보통주와 적격 ADR의 실제 포함 사례도 요구하며 전부 제외한 결과는 통과로 인정하지 않는다. 같은 회사의 다른 증권과 자료 충돌·부족을 다루고 모의 검사와 실제 검색·모델 결과를 구분한다. 표본 통과를 전체 시장 정확도 보장으로 확대하지 않는다.

사용자는 Q9에서 다음 실행 작업을 KIS 순위 수집, LLM의 정보 조회·유형 판단, 포함·제외 결과와 근거 출력까지의 작은 흐름 검증으로 정하는 추천안을 수락했다. 구독 경로의 도구 호환성과 유형 판단을 함께 확인하며 범용 분류기나 별도 MCP 서버를 먼저 만들지 않는다. 매수 추천 단계 연결은 이 흐름을 확인한 다음 작업으로 둔다. 설계 합의와 실행 요청은 구분한다.

사용자는 Q10에서 자료의 기준일·적용일과 확인 가능한 후속 변경을 살펴 현재 해당 증권에 적용되는지 확인하는 추천안을 수락했다. 조회 시각만으로 최신성을 판단하지 않으며 현재 적용 여부가 불확실하면 해당 종목을 제외한다. 모든 기업행동의 실시간 반영을 보장하는 시스템은 이번 범위에 포함하지 않는다.

사용자는 Q11에서 순위 종목을 어느 증권에 연결해야 하는지 확정할 수 없으면 전체 실패하는 기존 계약을 유지하는 추천안을 수락했다. 같은 회사의 종류주·ADR을 합치지 않고 원본 거래소·종목 코드를 보존한다. 증권 연결 자체의 모호함과 식별 후 유형·현재 적용 여부의 불확실성을 구분한다.

역할 분담과 실패 계약의 변경은 [ADR 0007](adr/0007-llm-security-type-judgment.md)에 기록한다. 기존 ADR 0005·0006의 출처 범위는 유지하며 코드 판별 전제와 실패 처리 중 변경한 부분은 새 결정을 따른다.

사용자는 Q12에서 최종 작업 범위·공용 검증 경계·검토 기준을 수락하고 `$to-spec`으로 #250 명세 게시를 요청했다. 작업 범위는 이 저장소의 KIS 순위 수집부터 LLM의 자료 조회·유형 판단, 포함·제외와 근거 출력까지의 작은 흐름이다. 공용 검증 경계는 CLI 입력·stdout·stderr·종료 코드와 외부 도구 요청이다. 비교 기준은 인터뷰 시작 커밋 `65fcb783671c45398e71d68eb797f4a418e11979`이며 이후 이 작업의 설계·구현 변경을 Standards·Spec 두 축으로 검토한다. 이전 인터뷰의 더 오래된 검토 기준은 당시 작업의 이력이다.

인터뷰는 완료했다. EODHD 추가 조사는 자동으로 착수하지 않는다. 인터뷰의 시작 HEAD는 `65fcb783671c45398e71d68eb797f4a418e11979`이고 시작 시 Git 작업 트리에 변경은 없었다. 이번 요청은 #250 명세 게시와 `ready-for-agent` 라벨 적용이며 구현·실연동·커밋·푸시는 포함하지 않는다. 실제 검증 완료나 후속 차단 해제와 명세 게시를 구분한다.

## 2026-10-20 실행 흐름과 평가의 후속 설계 인터뷰

인터뷰 시작 HEAD는 `05d9c14e9861fb7856844837c82ad27e0c8094eb`이며 시작 시 Git 작업 트리에 변경은 없었다. #250·#237의 현재 본문과 댓글, ADR 0007과 실제 실행 기록을 확인했다. 로그인·KIS·구독 검색 연결은 확인됐지만 최종 유형 결과와 독립 표본 정확도 대조는 미완료인 상태에서 시작한다.

사용자는 Q1에서 기존 근거 검증과 실행 한도를 유지하며 조회부터 최종 판단까지 완료할 수 있도록 실행 흐름을 개선하는 범위를 수락했다. 시간 연장이나 근거 검사 완화로 성공을 대신하지 않으며 한도 변경은 필요성을 확인한 뒤 별도로 결정한다.

사용자는 Q2에서 실제 자동 순위 수집 실행과 독립 정답을 확인한 고정 표본 평가를 모두 요구하는 방식을 수락했다. 고정 표본도 같은 판단 경로를 사용하며 평가 입력으로만 제공한다. 제품의 자동 순위 수집을 수동 종목 입력으로 바꾸지 않는다. 실행 분할 방식·평가 절차와 최종 작업 범위는 아직 합의하지 않았다. 이 인터뷰에는 구현·실연동·원격 게시·커밋·푸시를 포함하지 않는다.

사용자는 Q3에서 자료 조회와 최종 유형 판단을 분리하는 추천안을 수락했다. 코드는 실제 조회한 근거에 ID를 부여하고 최종 판단은 URL을 다시 작성하는 대신 해당 ID를 참조한다. 두 단계는 기존 실행 한도를 공유한다. 최종 판단 단계에는 추가 조회를 허용하지 않으며 근거가 부족한 종목은 제외한다. 근거 연결 검사와 내용의 타당성 평가는 별도로 유지한다.

사용자는 Q4에서 실행 전에 고정 표본과 독립 정답을 확정하고 같은 모델·설정으로 3회 모두 통과해야 평가 완료로 인정하는 추천안을 수락했다. 정답은 모델에 제공하지 않는다. 매회 잘못된 포함과 근거 없는 유형 확정이 없어야 하며 보통주와 적격 ADR의 실제 포함도 확인한다. 실패한 실행도 모두 기록하고 세 번의 통과를 전체 시장 정확도 보장으로 확대하지 않는다. 현재성 확인 기준·평가 입력의 경계와 최종 작업 범위는 후속 질문에서 정한다.

사용자는 Q5에서 근거 ID·URL과 실제 읽은 유형 관련 발췌문, 증권 연결 정보, 자료의 기준일·적용일과 후속 변경 확인 결과를 판단 단계에 함께 전달하는 추천안을 수락했다. 실제 조회 내용과 모델의 해석을 구분한다. 날짜 없는 페이지도 다른 근거로 현재 적용 여부를 확인할 수 있으나 확인하지 못하면 제외한다. 원문 보관은 출처의 허용 범위를 따른다.

사용자는 Q6에서 전체 모델 단계 180초 중 조회를 최대 120초로 제한하고 남은 시간을 최종 판단에 확보하는 추천안을 수락했다. 우선 검증용 배분으로 사용하며 정상적으로 조회를 마친 범위에서 판단하고 자료 부족은 개별 제외로 표시한다. 공통 장애·호출 한도 도달은 전체 실패다. 모델 단계의 비정상 중단은 기존 명시적 완료 계약에 따라 전체 실패하며 부분 기록을 정상 결과로 사용하지 않는다. 이 배분으로 완료하지 못하면 실패를 기록하고 재논의한다.

사용자는 Q7에서 고정 표본을 사례별로 실행하고 전체 사례를 도는 것을 한 회차로 계산하는 추천안을 수락했다. 같은 회사의 서로 다른 증권 구분 사례는 관련 종목을 함께 넣는다. 각 실행에 기존 한도를 적용하고 전체 평가를 3회 반복한다. 모델·설정은 시작 전에 고정하며 중간에 수정하면 수정된 버전으로 3회를 다시 평가한다. 실제 KIS 순위의 여러 종목을 함께 처리하는 실행도 별도로 확인한다.
