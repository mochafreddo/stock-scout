# 커밋 단계 검사 설계

2026-10-18 #244 세션 회고의 설계 인터뷰에서 Q1·Q3·Q6·Q10 권장안을 합의했다. 이 문서는 합의 기록이며 구현·설치 완료를 뜻하지 않는다. 공통 HTTP 수집·Git 전달 준비·이슈 본문 갱신 도구는 dotfiles에서 관리하고 커밋 검사는 stock-scout에 먼저 적용한다. 다른 저장소의 훅은 일괄 변경하지 않는다.

staged 스냅샷을 기준으로 문서 변경은 공백·로컬 링크를 검사하고, 코드 변경은 형식·린트·타입 검사까지 통과해야 커밋되도록 한다. 작업 디렉터리의 미커밋 수정으로 staged 코드의 오류를 가리지 않는다. 자동 수정은 하지 않으며 전체 테스트는 최종 검증과 기존 pre-push 단계에서 수행한다.

기존 `scripts/pre-push.ts`는 전송할 커밋 스냅샷에서 문서와 코드 검사를 수행한다. 새 검사는 가능한 부분을 재사용하고 기존 비밀정보 검사·Actions 비활성화와 양립해야 한다. staged 스냅샷에 맞는 의존성이 없거나 검사기를 실행할 수 없으면 커밋을 차단한다. 검사 실패와 실행 불가를 구분하고 훅 안에서 패키지를 설치하지 않는다. 기존 훅은 보존하며 안전하게 연결할 수 없으면 설치를 중단한다. `--no-verify`까지 막는 보안 장치로 취급하지 않는다. 부분 스테이징과 최초 커밋을 지원한다. 충돌이 남은 인덱스는 거부하고 검사 도중 staged 내용이 달라지면 그 결과로 커밋을 허용하지 않는다. staged 입력과 의존성 확인은 이 외부 계약을 만족하는 최소 방식으로 구현한다.

이번 후속 결정은 2026-10-17의 push 직전 검사에 커밋 단계 검사도 추가하는 범위다. 최종 설계 확인과 별도 구현 요청 전에는 검사기 코드와 실제 훅을 변경하지 않는다. 주식 도메인 용어집에는 개발 도구 용어를 추가하지 않는다.

## 최종 확인안

기존 스냅샷·문서·품질 검사를 재사용해 커밋 검사와 훅 설치·사용 안내·기존 테스트를 보완한다. 공개 검증 경계는 실제 임시 Git 저장소의 `git commit`·`git push`, 검사 CLI 입력·출력·종료 코드와 커밋 결과, 원본 파일·인덱스 보존이다. 부분 스테이징의 오류 은폐, 검사 중 staged 변경, 최초 커밋, 충돌 인덱스, 의존성 준비 실패, 기존 훅 보존과 pre-push 회귀를 검사한다. 위험한 로직은 같은 환경에서 음성 대조를 확인하며 형식·린트·타입과 최종 전체 테스트를 수행한다.

검토 기준점은 `f9aeb1f857d6230490ef3596c955967e6aed0233`이다. 이번 설계와 [ADR 0004](adr/0004-staged-commit-validation.md) 및 이후 구현을 포함한다. 기존 미추적 인증 ADR `docs/adr/0001-kis-token-issuance-state.md`는 제외하고 보존한다. 작업에 포함한 기존 설계 변경은 구현 작업 트리를 만들기 전 선행 커밋으로 정리하며 리뷰 기준점은 그 이전으로 유지한다.

주식 도메인과 KIS·LLM 코드는 변경하지 않고, 공통 수집기와 이슈 도구는 dotfiles에서 관리한다. 실제 작업 트리 생성·전달 전에 원격과 로컬을 확인하여 동시 변경을 보존한다. 이 절은 사용자 최종 확인을 위한 범위 제안이며 구현·훅 설치·커밋·푸시의 완료나 착수 승인을 뜻하지 않는다.

## 착수 확인

2026-10-18 사용자가 `implement`를 호출하여 위 범위·검증 경계·검토 기준점으로 구현 착수를 요청했다. 이번 설계 파일과 ADR은 선행 커밋에 포함하고, 구현·검증 결과는 완료 후 별도로 기록한다. 원격 푸시는 이번 요청에 포함하지 않는다.
