# 코드베이스 검토 후속 수정 설계

2026-11-15 코드베이스 검토의 P2 6건과 P3 2건에 대해 사용자가 Q1~Q8의 권고안을 모두 수락하고, Q9에서 전체 구현 범위·공개 검증 경계·리뷰 기준을 최종 확정한 기록이다. 검토 기준은 `d20daa308892b10b454a9fafa0588d909ce0193f`이며, 이 기준부터 설계 문서와 후속 구현 변경 전체를 리뷰한다. 아래는 합의한 수정 방향이며 구현 완료를 뜻하지 않는다.

확정한 구현 명세는 [#326](https://github.com/mochafreddo/stock-scout/issues/326)에 게시했다. 후속 구현의 요구사항·완료 기준은 해당 이슈를 따르며, 이 문서는 당시 설계 합의를 보존한다.

제품 요구사항과 책임 경계는 [#278](https://github.com/mochafreddo/stock-scout/issues/278), [#283의 결정](https://github.com/mochafreddo/stock-scout/issues/283#issuecomment-6686267791), [ADR 0019](adr/0019-toss-query-tools-transition.md)를 따른다. 현재 사용 계약은 [CLI 레퍼런스](toss-cli.md), 소비 절차는 [에이전트 지침](toss-agent-usage.md), 용어는 [용어집](../GLOSSARY.md)이 소유한다. 이 문서는 후속 수정의 결정과 검증 계획을 기록한다.

## 합의한 수정 방향

| 결정 | 수정 방향 | 보존할 경계 |
| --- | --- | --- |
| Q1 계좌 선택 결과 | 저장 직전에 실행 마감을 확인하고, 성공적으로 저장한 선택은 이후 마감 검사로 실패로 뒤집지 않는다. 적용한 별칭·범위를 성공으로 반환한다. | 저장 실패는 별도로 처리하며 이전 선택으로 자동 복구하지 않는다. 실제 계좌의 존재 확인은 이후 조회에서 수행한다. [ADR 0020](adr/0020-account-selection-commit-result.md)에 이유를 기록한다. |
| Q2 인증·권한 오류 | 본문 크기나 수신 오류가 있더라도 이미 확인한 HTTP 401·403의 중단 의미를 보존한다. | 유효한 본문에서 `expired-token`을 확인한 경우에만 기존 인증 복구를 허용한다. 민감한 본문은 출력하지 않는다. |
| Q3 봉 다음 경계 | 요청 `before`보다 엄격히 미래인 `nextBefore`는 응답 오류로 거부한다. | 같은 경계, 같은 시각의 다른 시간대 표기, 유효한 빈 페이지는 허용한다. 경계를 임의로 보정하지 않는다. |
| Q4 Markdown 링크 검사 | 링크 정규식의 과도한 역추적 원인을 제거하는 최소 수정을 적용한다. | 기존 정상 링크·괄호 링크 지원을 유지한다. 시간 제한만 추가해 파서 결함을 덮지 않는다. |
| Q5 Git 변경 분류 | staged·push의 변경 경로 열거에 `--no-renames`를 적용해 삭제·추가 양쪽의 파일 종류를 검사한다. | 코드에서 문서로 이름이 바뀌어도 기존 코드 검사 정책을 적용한다. [ADR 0004](adr/0004-staged-commit-validation.md)의 검사 수준은 낮추지 않는다. |
| Q6 파일 경로 | 파일 인수에 쓰는 file URL의 `.pathname`을 `fileURLToPath`로 바꾸고 같은 패턴의 호출자를 함께 확인한다. | URL 인수를 받는 곳에는 필요한 경우 `.href`를 사용한다. 공백·한글 경로를 제한하지 않는다. |
| Q7 다른 통화의 종가 | 일봉 소비 예제가 봉별 통화를 보존하고 비교할 양 끝 종가의 통화가 다르면 등락률을 `null`과 계산 불가 사유로 반환한다. | 임의 환산을 하지 않는다. 유효한 봉과 거래량은 유지하고 같은 통화의 기존 계산을 보존한다. |
| Q8 출처가 가려진 오류 | 일봉 소비 예제가 버전·오류 상태·빈 데이터 등 오류 응답 구조를 검증해 안전한 원래 오류를 전달한다. | 사용 가능한 봉 데이터에는 기존 엔드포인트 검증을 유지한다. 가려진 출처나 공급자 원문을 복원하지 않는다. |

## 구현 대상과 검증 계획

실행 코드 대상은 공통 클라이언트와 CLI의 계좌 선택·오류 처리, 봉 응답 검증, Git 훅의 링크 검사·변경 분류, 합성 실행 도우미의 경로 변환, 일봉 소비 예제다. 기존 명령별 테스트와 소비 테스트에 회귀 사례를 추가하고, 구현 후 현재 CLI·개발·에이전트 문서에 필요한 변경을 반영한다. 새 서버·분석 엔진·의존성은 추가하지 않는다.

공개 검증 경계는 CLI 인수·stdout JSON·stderr·종료 코드·외부 HTTP, 격리된 계좌 선택의 다음 실행에서 관측되는 결과, 실제 Git 훅, 소비 예제의 stdin/stdout이다. 내부 함수 배치나 문서 문구를 고정하는 검사는 만들지 않는다.

| 결정 | 실패를 확인할 사례 | 함께 유지할 정상 사례 |
| --- | --- | --- |
| Q1 | 저장 후 마감 초과가 실패 응답과 새 선택을 동시에 남기는 기존 경로 | 저장 전 마감 초과에서는 이전 선택 유지, 정상 저장의 성공 응답과 다음 실행의 선택 일치, 저장 오류의 안전한 실패 |
| Q2 | 큰 403 본문 뒤 다음 종목을 전송하는 기존 경로, 인증 오류 본문 수신 실패 | 일반 403 중단, 확인된 만료 복구, 민감정보 가림, 기존 일시 오류 재시도 |
| Q3 | 미래의 다음 경계를 따라 원래 조회 상한을 벗어나는 두 페이지 | 동일·과거 경계, 다른 시간대 표기, 빈 부분 페이지, 날짜 지정과 직접 before 지정 |
| Q4 | 닫히지 않은 긴 링크가 검사 한도를 넘기는 입력 | 일반·괄호 링크, 누락된 대상·앵커의 기존 실패, 문서·staged·push의 공통 검사 |
| Q5 | 코드→문서 이름 변경 뒤 실제 타입 오류가 있는데 staged·push가 통과하는 경우 | 일반 문서 변경, 코드 변경, 이름 변경의 양쪽 파일 분류 |
| Q6 | 공백·한글 경로의 합성 실행과 관련 훅 테스트 진입 실패 | 기존 일반 경로, 정상·부분·오류 합성 실행 |
| Q7 | 서로 다른 통화의 종가로 숫자 등락률을 만드는 경우 | 같은 통화, 영 기준가, 유효 거래량, 빈·부분·오류 결과 |
| Q8 | 출처가 가려진 빈 CLI 오류를 assertion으로 바꾸는 경우 | 기존 초기 입력·인증 오류 전달, 유효 봉의 출처 검증, 잘못된 오류 구조 거부 |

앞선 검토에서는 Q1~Q6을 실제 CLI·훅과 격리된 합성 입력으로 재현했다. Q5의 직접 훅 재현은 staged 경로였으며 push 경로는 코드로 추적했다. Q7은 실제 소비 예제에 합성 JSON을 직접 입력해 확인했다. Q8은 정적 경로 추적 근거이므로 구현 전 실행 재현을 추가한다. 공급자에서 이런 응답이 발생하는 빈도는 측정하지 않았다.

회귀 검사는 수정 전 실패를 확인한 뒤 같은 공개 경계에서 통과를 확인한다. 실행 가능한 음성 대조가 필요한 소스 변경에는 공용 mutation-probe 절차를 적용한다. 검토·단순화 이후 고정된 최종 소스로 린트·타입·전체 테스트와 필요한 문서 검사를 수행한다. 합성 HTTP·시계·상태 검사를 실제 토스·계좌 관측과 구분한다.

## 문서와 용어의 범위

Q1의 저장 완료와 시간 상한 사이의 선택은 [ADR 0020](adr/0020-account-selection-commit-result.md)에 기록한다. 나머지는 기존 계약을 지키기 위한 국소 수정이므로 별도 ADR을 만들지 않는다. 새 도메인 용어는 합의하지 않았으며, 일반 구현 개념을 추가하지 않고 기존 용어집을 유지한다.

Q9에서 확정한 범위는 Stock Scout의 8건 전체 수정과 관련 회귀 테스트·사용 문서 반영이다. 공개 검증 경계는 위 계획의 실제 CLI 입출력·종료 코드·합성 HTTP, 다음 실행의 계좌 선택 결과, 실제 staged·push 훅, 소비 예제 입출력이다. 실제 토스·계좌 조회, 인증 설정 변경, 자료의 외부 전달, GitHub 게시는 포함하지 않는다. 이번 작업은 설계 문서 반영까지이며, 실행 코드 구현·커밋·푸시는 별도 요청에 따라 진행한다.
