# 토스 자료의 외부 AI 전달과 조회 전용 자격 증명 조사

조사일: 2026-11-06. 대상은 [토스 자료의 외부 AI 전달 및 조회 전용 권한 범위 조사](https://github.com/mochafreddo/stock-scout/issues/284)의 두 질문이다. [AI 에이전트용 첫 도구 모음과 책임 경계 결정](https://github.com/mochafreddo/stock-scout/issues/281#issuecomment-6685141368)을 전제로 하며, [토스증권 API로 제공할 수 있는 시장·계좌 데이터의 범위와 제약 조사](https://github.com/mochafreddo/stock-scout/issues/279#issuecomment-6684230963)에서 남긴 외부 AI 전달 조건과 공급자 조회 전용 권한만 다룬다. 구현·인증 설정·실계좌 조회·실제 자료 전달은 수행하지 않았다.

## 조사 결과

공식 FAQ는 API 자료를 투자자 본인의 매매 목적으로만 이용하도록 하고 비상업적 목적이라도 제3자 배포를 금지한다. 그러나 로컬 Codex·Dot이 조회 결과를 외부 모델에 보내는 처리가 이 제한에서 어떤 취급을 받는지, 원자료와 요약·가공 결과를 구분하는지, 모델 사업자의 처리·보관 조건에 따라 허용되는 예외가 있는지는 확보한 공식 문서에서 확인하지 못했다. 따라서 **외부 AI 전달이 허용된 것으로도, 모든 외부 AI 처리가 명시적으로 금지된 것으로도 확정하지 않는다**. [공식 FAQ의 데이터 이용 정책](https://openapi.tossinvest.com/openapi-docs/faq.md#데이터-이용-정책)

현재 공식 인증 명세에서는 조회 전용 클라이언트·토큰을 선택하는 계약을 확인하지 못했다. OAuth scope 정의가 비어 있고 조회와 주문 생성에 같은 인증 방식이 쓰인다. 이는 조회 전용 권한의 증거가 아니며, 공개 문서에 없는 별도 설정까지 없다는 증거도 아니다. 공급자에 조회 전용 발급·설정의 존재와 차단 범위를 확인해야 한다. [공식 OpenAPI v1.2.28](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)

## 외부 AI 전달과 보관

직접 확보한 FAQ의 데이터 이용 정책은 API로 제공받는 정보 전반을 대상으로 본인의 매매 목적과 제3자 배포 제한을 설명한다. 검색 색인으로 확인한 약관 제5조 제3항은 국내·해외 시세정보에 대해 본인의 매매 목적만 허용하고 제3자 제공·배포·상업적 활용을 제한한다. 두 문구의 대상 표현이 다르므로, 시세 조항만 보고 계좌 자료가 자유롭게 전달 가능하다고 해석하지 않는다. [공식 FAQ](https://openapi.tossinvest.com/openapi-docs/faq.md#데이터-이용-정책), [공식 약관 제5조 제3항, 검색 색인 확인](https://home.tossinvest.com/ko/terms/v2?id=752)

약관 제3조의 적용 대상에는 시세·계좌·잔고·거래내역 조회와 주문이 들어 있다. 제5조 제2항은 보안코드의 유출·도용 방지와 제3자에 대한 대여·위임·양도·누설 제한을 규정한다. 이는 자료 이용 조건과 별도의 자격 증명 관리 조건이다. 키를 모델에 전달하지 않는 설계만으로 자료 전달 조건까지 충족했다고 판단할 수 없다. 이 조항들을 외부 에이전트가 지시하는 로컬 조회 프로세스에 어떻게 적용하는지도 별도 확인 사항이다. [공식 약관 제3조·제5조 제2항, 검색 색인 확인](https://home.tossinvest.com/ko/terms/v2?id=752)

약관 제13조는 회사가 거래기록을 보존하는 조항이다. 이를 고객이나 외부 모델 사업자의 자료 보관 허용 기간으로 사용하지 않는다. [공식 약관 제13조, 검색 색인 확인](https://home.tossinvest.com/ko/terms/v2?id=752)

### 자료별 미확인

아래 표의 미확인은 확보한 공개 문서에서 해당 처리의 허용 근거를 확인하지 못했다는 뜻이다. 금지·지원 불가라는 공급자 답변을 받은 상태가 아니다. 공통 근거는 [FAQ의 이용 정책](https://openapi.tossinvest.com/openapi-docs/faq.md#데이터-이용-정책)과 [약관 제5조](https://home.tossinvest.com/ko/terms/v2?id=752)이며, 약관의 직접 본문 확인에는 앞서 적은 한계가 있다.

| 자료 | 외부 모델 입력 | 외부 처리 후 보관·재이용 |
| --- | --- | --- |

모델 학습·평가·서비스 개선에 사용하는 경우, 학습에는 쓰지 않지만 남용 탐지 등을 위해 보관하는 경우, 처리 후 즉시 삭제하는 경우를 토스 문서가 구별해 허용하는 근거도 확인하지 못했다. 소비 환경의 보관 정책은 실제 처리 경로를 확인하는 데 필요하지만 토스의 허용을 대신하지 않는다.

설계상 로컬 CLI 실행과 외부 모델 처리는 다른 단계다. 로컬 조회 결과가 모델 문맥에 들어가면 외부 전달 경로가 생긴다. 식별자 제거·요약·로컬 파일 저장 중단은 전달량이나 저장 경로를 줄이는 조치이며, 공급자의 허용이나 외부 대화·모델 사업자 측 삭제를 보장하지 않는다. 이는 공식 허용 판정이 아닌 설계상 구분이다. [AI 에이전트용 첫 도구 모음과 책임 경계 결정](https://github.com/mochafreddo/stock-scout/issues/281#issuecomment-6685141368)의 금융자료 제공 방향을 변경하거나 공급자 승인으로 취급하지 않는다.

## 공급자 조회 전용 권한

[공식 OpenAPI JSON](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)의 다음 위치를 확인했다.

| 명세 위치 | 관측한 계약 | 의미의 한계 |
| --- | --- | --- |
| `components.securitySchemes.oauth2ClientCredentials.flows.clientCredentials` | `tokenUrl`은 `/oauth2/token`이며 `scopes`는 `{}`다. | 문서에 명명된 scope가 없다. 빈 scope를 조회 전용 권한으로 읽을 수 없다. |
| `components.schemas.OAuth2TokenRequest` | 문서화된 속성은 `grant_type`, `client_id`, `client_secret`이다. | 토큰 요청으로 조회 전용 scope를 선택하는 방법이 문서화되지 않았다. |
| `components.schemas.OAuth2TokenResponse` | 문서화된 속성은 `access_token`, `token_type`, `expires_in`이다. | 발급된 권한 집합을 나타내는 scope 필드는 문서화되지 않았다. |
| `paths./api/v1/orders`의 `get`·`post`, `paths./api/v1/conditional-orders`의 `post` | 모두 `oauth2ClientCredentials: []`를 인증 요구로 기재한다. | 조회·주문 생성의 인증 표기에 권한 구분이 없다. 실제 모든 클라이언트가 모든 주문 권한을 갖는다는 관측 결과는 아니다. |
| `components.parameters.AccountSeq` | `X-Tossinvest-Account`는 계좌 조회 결과의 `accountSeq`를 지정하는 헤더다. | 계좌 선택 값이지 조회·주문 권한을 선택하는 scope가 아니다. |

공식 개요의 클라이언트 등록 절차에는 조회 전용 키 선택이 설명되지 않는다. FAQ는 클라이언트당 유효 토큰이 하나이며 재발급하면 기존 토큰이 즉시 무효가 된다고 설명한다. 프로세스별로 토큰을 발급하는 방식은 문서상 권한 분리 방법이 아니며 기존 토큰 사용에도 영향을 준다. [개요의 시작하기](https://openapi.tossinvest.com/openapi-docs/overview.md#시작하기), [FAQ의 인증·접속](https://openapi.tossinvest.com/openapi-docs/faq.md)

`403 forbidden`의 권한 부족 설명도 공개 개요에 있지만, 이를 조회 전용 키 발급 기능의 증거로 볼 수는 없다. 권한 설정 방법·선택 가능한 역할·주문 차단의 적용 범위는 문서에서 확인하지 못했다. [공식 개요의 에러 응답](https://openapi.tossinvest.com/openapi-docs/overview.md#에러-응답)

| 수단 | 확인 수준 | 보호하는 경계와 한계 |
| --- | --- | --- |
| 공급자가 강제하는 조회 전용 클라이언트·토큰 | 공개 문서에서 설정 방법과 보장을 확인하지 못했다. | 확인된다면 자격 증명 자체의 주문 권한을 제한할 수 있다. 일반·조건 주문의 생성·정정·취소 전부에 적용되는지는 별도 확인해야 한다. |
| 허용 IP | 공식 개요·FAQ·토큰 발급 명세가 등록되지 않은 IP의 차단을 설명한다. | 호출 출발지를 제한한다. 허용된 IP에서 어떤 작업을 할 수 있는지까지 조회 전용으로 제한한다는 근거는 없다. |
| Stock Scout의 주문 도구 제외 | 첫 도구 모음 결정에서 주문 제출·정정·취소를 제품 범위에서 제외했다. 구현 검증은 후속 작업이다. | CLI의 공개 기능을 제한하는 제품 경계다. 공급자 키의 권한을 줄이거나 다른 프로그램의 키 사용까지 차단하는 조치는 아니다. |
| 키·토큰의 로컬 관리와 모델 출력 제외 | 첫 도구 모음의 설계 결정이며 명세도 `client_secret`을 노출하지 않도록 서버 측에서 사용하라고 설명한다. | 자격 증명 노출 경로를 줄인다. 공급자 scope나 자료 전달 허용을 대신하지 않는다. |

IP 설명의 근거는 [공식 시작 절차](https://openapi.tossinvest.com/openapi-docs/overview.md#시작하기)와 [FAQ](https://openapi.tossinvest.com/openapi-docs/faq.md), 제품 경계의 근거는 [AI 에이전트용 첫 도구 모음과 책임 경계 결정](https://github.com/mochafreddo/stock-scout/issues/281#issuecomment-6685141368), 시크릿 설명의 근거는 [공식 토큰 요청 스키마](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)다. 주문 API를 실제 호출해 차단 여부를 시험하지 않았다.

## 공식 확인 질문 초안

다음은 보내지 않은 문의 초안이다. 실제 계좌번호·키·토큰·개인 거래 사례를 포함하지 않는다. 전달 경로를 검토하는 데 필요한 서비스명·모델 사업자·인증 상품·보관 설정은 문의 시 사실에 맞게 특정해야 한다.

> 개인 투자자가 본인 컴퓨터에서 토스 Open API 조회 전용 CLI를 실행하고, 로컬 Codex 및 로컬 환경의 Dot이 그 결과를 외부 AI 모델의 입력으로 사용해 본인 투자 판단을 돕는 구조를 검토하고 있습니다. 주문 제출·정정·취소 기능은 제공하지 않으며, 공급자 키와 토큰은 로컬 조회 프로세스가 관리하고 모델에는 전달하지 않습니다. 자료나 분석 결과를 다른 투자자에게 공개·판매하는 목적은 없습니다.
>
> 1. 현재 적용되는 Open API 약관·시세 이용 계약·추가 동의 문서의 공식 주소와 개정일은 무엇입니까? 제5조의 제3자 제공·배포 제한은 위와 같은 외부 모델 추론 처리에도 적용됩니까? 처리 수탁·비공개 개인 이용 등 별도의 허용 조건이 있습니까?
> 2. 시장 원자료와 계좌 원자료 각각에 대해 전송 가능한 항목과 금지 항목은 무엇입니까? 계좌번호·직접 식별자를 제거한 보유·평균매수가·손익·매수 가능 금액·거래내역·주문 상태도 같은 제한을 받습니까?
> 3. 집계 수치·비중·등락률·자연어 요약·모델이 생성한 분석 결과에는 어떤 제한이 남습니까? 원자료의 복원 가능성이나 수치 포함 여부 등 구분 기준이 있습니까?
> 4. 처리 후 삭제, 학습 미사용과 한시적 운영 보관, 대화 기록·로그·백업 저장, 학습·평가·서비스 개선 이용을 구분해 각각 허용 여부·보관 기간·삭제 조건을 안내해 주실 수 있습니까? 국내외 처리 위치나 하위 처리자 조건도 있습니까?
> 5. 키를 외부에 전달하지 않고 외부 에이전트가 로컬 CLI 조회를 지시하는 구조는 자격 증명 대여·위임 제한과 어떤 관계입니까? 별도 승인이나 계약이 필요합니까?
> 6. WTS 클라이언트 발급·설정 또는 토큰 발급 시 공급자가 강제하는 조회 전용 권한을 선택할 수 있습니까? 가능하다면 공식 설정 절차·scope·역할 이름과 일반·조건 주문의 생성·정정·취소 차단 범위를 알려주실 수 있습니까?
> 7. 조회 전용 권한의 계좌별 적용, 복수 클라이언트 발급, 토큰 간 영향과 권한 확인 방법은 무엇입니까? 제공되지 않는다면 그 사실과 허용 IP와의 차이를 공식적으로 확인해 주실 수 있습니까?

## 후속 제품 결정에 제공할 선택지

아래 항목은 [에이전트 도구의 검증·전환 완료 기준 결정](https://github.com/mochafreddo/stock-scout/issues/283)의 접근·전달·중단 기준 결정을 위한 선택지이며 채택한 정책이 아니다.

| 남은 조건 | 후속 결정 선택지 | 추가로 필요한 근거 |
| --- | --- | --- |
| 외부 AI 전달 조건을 확인하지 못함 | 실제 토스 자료의 외부 전달을 보류하고 합성 자료로 CLI·에이전트 연결 검증을 진행하는 방안 | 허용 판단과 무관한 합성 검증 범위, 공식 답변 확보 경로 |
| 자료 종류·처리 방식에 따라 일부 허용됨 | 허용된 자료·요약 수준·소비 환경·보관 설정으로 전달 범위를 정하는 방안 | 항목별 공식 답변과 실제 소비 환경의 처리·보관 경로 |
| 필요한 전달이 금지되거나 조건을 충족할 수 없음 | 해당 기능 보류, 외부로 보내지 않는 처리 경로, 허용 계약을 갖춘 공급자 등을 다시 비교하는 방안 | 사용자와의 제품 재결정. 요약·수동 복사·다른 공급자를 자동 우회로로 사용하지 않는다. |
| 공급자 조회 전용 권한이 확인됨 | 해당 권한의 실제 적용 범위를 인수 조건으로 삼는 방안 | 공식 설정 계약과 주문 차단 확인 방법. 실검증은 별도 승인 범위에서 진행한다. |
| 공급자 조회 전용 권한이 없거나 끝내 미확인임 | 실계좌 연결을 보류하거나, 공급자 차원의 주문 권한 제한이 보장되지 않는 위험을 명시한 뒤 별도 수용 여부를 결정하는 방안 | IP 제한·주문 도구 제외와 구분한 사용자 결정 및 검증·전환 완료 기준 티켓의 중단 기준 |

이번 조사로 공급자 허용·조회 전용 보장·실연동 성공이 확인된 것은 아니다. 두 질문의 최종 허용·보장 범위에는 공식 확인이 필요하다. 계좌·인증·모델 접근과 문의 전송은 수행하지 않았다. 저장소 문서 검사와 게시 절차는 담당 세션에서 별도로 수행한다.
