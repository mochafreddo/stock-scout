# 외부 공식 종목 유형 관측하기

저장된 KIS 관측 자료를 입력하여 SEC의 발행사·공시·증권별 구조화 문맥을 확인합니다. [설계 합의](security-type-probe-design.md)에 따른 검증 도구이며 현재 적격 종목을 확정하는 후보군 분류기는 아닙니다. 보통주와 적격 ADR의 실제 자동 확인을 포함한 #250의 완료 기준은 아직 충족하지 않았습니다.

## 실행하기

Node.js 24 이상과 macOS의 `/usr/bin/xmllint`가 필요합니다. 새 패키지나 XML 라이브러리를 설치하지 않습니다. KIS 인증 정보는 사용하지 않으며 KIS를 새로 조회하지 않습니다.

저장소 루트에서 저장된 관측 JSON 파일을 전달하세요. 여러 파일을 한 실행에 전달할 수 있습니다.

```sh
node scripts/security-type-probe.ts docs/evidence/issue-250/info-NYS-BBDO.json
```

입력의 KIS 관측 시각과 원본 거래소·종목 코드를 보존합니다. 이름이나 티커의 접두사·구두점을 바꾸어 연결하지 않습니다. 선택적 식별자가 없다는 이유만으로 실패시키지는 않습니다.

KIS 관측 CLI의 종목 정보·거래량 순위·거래대금 순위 JSON과 저장소의 선별 마스터 JSON 형식을 입력할 수 있습니다. 마스터 입력에는 `receivedAt`과 종목별 `exchangeCode`·`symbol`이 필요합니다. 같은 거래소·종목 코드의 식별자가 서로 모순되면 요청 전에 실패합니다. NAS·NYS의 SEC 거래소 연결을 먼저 다루며 AMS는 하나의 외부 상장시장으로 추정하지 않고 미지원 연결로 남깁니다.

외부 요청에는 `StockScout/0.1 (+https://github.com/mochafreddo/stock-scout)`라는 User-Agent를 사용합니다. [SEC 접근 안내](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data)는 식별 헤더를 요구하고 연락처가 포함된 예시를 제공합니다. 저장소 URL의 허용이나 접근 성공을 보장하는 문구로 해석하지 마세요. 거부 응답을 받으면 실패하며 인증·프록시·다른 수집 경로로 우회하지 않습니다.

한 실행 안에서는 요청을 순서대로 보내고 같은 자료를 재사용합니다. 자동 재시도는 하지 않습니다. 여러 프로세스로 동시에 실행하지 마세요. 도구의 요청·크기·시간 제한은 자원 사용을 제한하기 위한 자체 상한이며 SEC의 가용성이나 실제 지원 범위를 검증한 운영값이 아닙니다. 한도를 넘기면 실패합니다.

실제 상한은 수집 완료 진단의 `limits`에서 확인하세요. 자료별 수집 시각·바이트 수·SHA-256은 `sources`에 표시합니다. 이 값은 응답의 추적 근거이며 정확성이나 현재성의 보장이 아닙니다.

## 결과 확인하기

현재성 검증은 미완료이므로 이 버전은 정상 후보군을 stdout에 출력하지 않습니다. 수집과 구조화 문맥 확인을 마쳐도 `CURRENTNESS_UNVERIFIED`를 stderr에 출력하고 종료 코드 1로 끝납니다. 진단의 `reportedType`은 공시에 보고된 표현이며 현재 거래 증권의 적격성이 아닙니다. `instrumentType`, `currentness`, `runtimeEligible`도 함께 확인하세요.

발행사 발견과 증권 식별을 구분합니다. CIK나 회사명이 같다는 이유로 별도 주식 종류를 합치지 않습니다. 공시의 `contextRef`와 증권별 차원을 함께 확인하며 표지의 보통주 표현을 거래되는 ADR 자체의 유형으로 확대하지 않습니다. 지원하지 않는 정상 문서의 권리 표현은 미확인으로 남기고, 수집·응답 구조·XML 파싱의 오류는 실패로 보고합니다.

현재는 submissions의 최근 이력에서 `10-K`·`20-F`·`40-F`를 탐색하고 제출 디렉터리의 추출 XBRL instance를 찾습니다. 선택 대상이 정정본이거나 지원하는 instance가 없으면 미확인으로 남깁니다. 추가 이력 파일과 다른 공시 형식은 해석하지 않으며, `coverage`에 그 범위를 표시합니다. 최근 이력에서 선택한 연차보고서를 모든 후속 변경까지 확인한 최신 권리 자료로 해석하지 마세요.

필수 자료 장애가 발생하면 앞서 얻은 관측을 정상 결과로 출력하지 않습니다. 오류는 안전한 코드로 표시하며 원문 응답·인증 정보·환경 변수 전체를 출력하거나 파일로 저장하지 않습니다. 전체 공시 원문을 저장소에 추가하지 마세요.

## 출처와 남은 조건

NYSE 매핑과 SEC 공시를 우선 검증 후보로 합의했으나, 출처 채택은 조건부입니다. [ICE 이용 조건](https://www.ice.com/privacy-security-center/terms-of-use)은 개인 비상업 다운로드 허용과 별개로 자동 수집·추출을 제한합니다. 공개 매핑 배포 안내와 이 제한의 적용 관계를 해결하지 못했으므로 이 버전에는 NYSE 자동 수집을 넣지 않습니다. 이는 NYSE 데이터에 접근할 수 없다는 결론이 아닙니다.

[SEC API 설명](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)은 공시 이력의 갱신을 설명합니다. 이력을 새로 받았다는 사실만으로 모든 권리 변경과 현재 거래 증권의 대응을 확인했다고 판단하지 않습니다. 후속 공시·정정과 비구조화 문서, 지원하지 않는 문맥의 범위는 미검증으로 남습니다. 임의의 TTL이나 오래된 저장 자료로 현재성 검사를 통과시키지 않습니다.

Bradesco의 [2025 20-F 표지](https://www.sec.gov/Archives/edgar/data/1160330/000129281426001753/R1.htm)는 BBD와 BBDO의 권리를 서로 다른 증권별 문맥으로 표시하지만, 같은 제출본의 [Exhibit 2.4](https://www.sec.gov/Archives/edgar/data/1160330/000129281426001753/ex02-4.htm)에는 그 문맥과 모순되는 권리·심볼 표기가 있습니다. 이를 오타로 추정해 해소하지 않습니다. [TSM 표지](https://www.sec.gov/Archives/edgar/data/1046179/000162828026025362/R1.htm)의 보통주 표현도 ADR 기초 주식과 거래 증권의 구분이 필요합니다. 구조화된 표지 하나를 읽었다는 사실을 적격 ADR의 현재 자동 확인으로 보고하지 마세요.

모의 CLI 검사와 실제 SEC 접근 결과는 별도로 보고합니다. 실제 적격 보통주·ADR 확인, 제외 유형, KIS 연결과 현재성의 필수 조건이 모두 검증되기 전까지 #250·#243과 후속 후보군·추천 구현의 차단을 유지합니다.

## 실제 실행 기록

2026-10-19 저장된 BBDO 관측 자료로 CLI를 한 번 실행했습니다. 저장소 URL User-Agent를 포함한 첫 SEC 발행사 목록 요청이 HTTP 403으로 거부되어 stdout 없이 `SOURCE_HTTP_FAILURE`와 종료 코드 1을 반환했습니다. 요청 조건·시각·소스 해시·안전한 진단은 [선별 실행 기록](evidence/issue-250/sec-probe-live.json)에 있습니다. 거부 원인을 User-Agent 형식으로 단정하지 않으며 다른 신원이나 경로로 우회하지 않았습니다.

리뷰 수정과 추가 식별자 회귀 수정 뒤 같은 요청을 각각 다시 실행했고 HTTP 403·stdout 없음·종료 코드 1을 재확인했습니다. 앞선 결과를 보존하고 같은 기록의 `finalSourceRerun`과 `identityGuardRerun`에 재검증 시각과 소스 해시를 추가했습니다. 마지막 기록의 해시는 최종 소스와 일치합니다.

실제 발행사 발견·공시 선택·XML 해석까지 도달하지 못했습니다. 그 경로와 권리·실패 처리는 외부 HTTP를 대체하고 실제 로컬 XML 파서를 사용한 CLI 테스트로 확인한 범위입니다. 실제 적격 보통주·ADR 자동 확인과 현재성은 미검증이며, 이번 구현·검증 작업은 부분 완료로 남습니다.
