# KIS 후보군 데이터 검증

## 현재 기준: 탐색과 분석의 분리

2026-10-26 후속 설계에서 [ADR 0011](adr/0011-ranking-discovery-and-runtime-data-readiness.md)에 따라 #249의 범위를 조회 가능 범위·사용 제약 확인으로 조정했다. 기존 여섯 순위·일별 시세의 실제 응답과 [공식 조사](kis-ranking-session-investigation.md)를 근거로 사용한다. 같은 성공 호출을 반복하거나 고정 12:00·15:00 KST, 추가 날짜·예외 거래일·공급자 답변·페이지·정상 빈 응답 실연동을 기다리는 조건은 두지 않는다.

조회 당시의 여섯 순위는 탐색 순위로만 사용하고 첫 페이지에서 각각 최대 N개를 취한다. 원래 순위·조회 시각을 보존하며 제외·중복 제거 뒤 보충하거나 후속 페이지를 요청하지 않는다. 완료 세션 순위·전체 시장 순위·목록의 완전성을 입증했다는 뜻이 아니다. N보다 짧은 비어 있지 않은 응답은 실제 행 수를 남겨 사용한다. 2026-10-28 #251에서 합의한 N·필요 기간·호출·실행 한도는 [ADR 0014](adr/0014-candidate-runtime-budget.md)를 따른다.

분석에는 공식 일정으로 확인한 데이터 기준 세션 날짜와 필요한 과거 기간의 KIS 일봉을 사용한다. 공식 필드 정의에 따른 사용은 승인된 운영 가정이며 정규장 전용 집계의 독립 검증이 아니다. 진행 중인 날짜의 행을 제외하고 필요한 날짜·기간·가격·거래량 필드를 실행마다 검사한다. 현재의 수정주가 미반영 조건을 표시하며 미확인 단위·배율을 환산하거나 서로 다른 기준의 수치를 비교하지 않는다. 여섯 순위 중 빈 응답이 있거나 분석 필수 자료가 부족하면 전체 실행을 자료 부족으로 종료한다. 자동 대기·재관측이나 정상 빈 후보군·후보 없음으로의 대체는 하지 않는다. 모든 종목이 정상적인 유형 제외로 사라진 빈 후보군과 구분한다.

#249의 새 완료 기준은 다음과 같다.

1. 기존 여섯 순위·일별 시세의 실제 응답과 공식 자료 조사로 조회 가능 범위를 확인한다.
2. 탐색 순위와 분석 일봉을 분리한 계약과 첫 페이지·최대 N개·미보충 정책을 명시한다.
3. 미확인 사항과 빈 응답·필수 자료 누락 시 중단 기준을 기록한다. 추가 시각 관측이나 공급자 답변을 완료 조건으로 두지 않는다.

이 기준은 조사 작업의 완료를 평가하는 것이며 데이터 의미 입증·런타임 구현·제품 인수를 뜻하지 않는다. 실제 날짜·필드 검사와 빈 응답·누락·잘못된 날짜의 CLI·외부 HTTP 모의 검사는 #245에서 검증한다. 공식 일정·공통 세션·장중 거부·출력 직전 개장 경계, 인증·유형·비밀·비용 조건은 유지한다. 일정 등 별도 기능의 미완료를 #249의 종료 관문으로 합치지 않는다.

설계 확정 단계에서는 로컬 문서와 #237·#239·#243·#245·#249·#251 이슈 수정안까지 작성하기로 했다. 기존 응답·실패·체크 이력을 보존하며 그 단계의 승인에는 실제 KIS 호출·코드·커밋·푸시·원격 이슈 갱신·종료가 포함되지 않았다. 검토 기준은 `97d85ac4ad6f125df58ab5684e69ea4776013045`와 확보한 각 이슈 원문이다. 문서 내용·참조·변경 범위를 확인하며 실행 코드 변경이 없어 코드 테스트·타입·린트·음성 대조는 생략한다.

아래 이전 결론·한국 낮 검증 계획·운영값 기록 중 완료 세션 순위 입증, 고정 시각 관측과 페이지·정상 빈 응답 실연동의 선행 조건은 위 기준으로 대체한다. 해당 기록의 미검증 사실과 나머지 기능의 완료 상태는 바꾸지 않는다.

조회한 #243 원격 본문은 2026-10-21의 완료 세션 순위·사전 지원 시간 입증 조건과 과거 차단 기록을 아직 포함한다. 후속 합의와 충돌하는 범위는 ADR 0011~0014와 하위 작업의 최신 완료 범위를 기준으로 해석하며, 과거 미검증 사실·실패·체크 상태는 소급 변경하지 않는다. 이 로컬 인계는 원격 완료 조건을 수정하거나 #243·#239·#245 또는 매수 추천 제품 인수를 완료 처리한 결과가 아니다. 원격 명세·완료 평가를 갱신할 때는 기존 본문과 최신 합의를 구분하고 각 조건의 근거·잔여 한계를 함께 반영해야 한다.

## 이전 결론과 차단 조건

아래는 후속 설계 변경 전의 관측·조사 이력이다. 완료 세션 순위·고정 시각 관측·페이지·정상 빈 응답 실연동·공지 완전성의 사전 입증과 N 미확정 조건 중 후속 합의가 대체한 범위는 위 현재 기준을 따른다. 당시의 응답과 미검증 사실 자체는 유지한다.

[#243](https://github.com/mochafreddo/stock-scout/issues/243)의 검증은 진행 중이다. 2026-10-17 토요일 관측에 이어 2026-10-19 개장 60·30·15분 전 목표의 [실제 관측 27건](kis-premarket-observation-20261019.md)을 완료했다. 세 표본의 일별 첫 행은 당일 20261019였고 직전 거래일 20261016 행은 별도로 유지됐다. 순위의 기준 세션·정규장 범위·단위와 공식 일정 공지의 완전성은 미검증이다. 최종 지원 시간과 N을 확정하거나 [#239](https://github.com/mochafreddo/stock-scout/issues/239)의 후보군 조회 및 후속 추천 구현을 검증 완료로 처리할 수 없다.

2026-10-26 [한국 낮 순위의 완료 세션 의미 조사](kis-ranking-session-investigation.md)에서 최신 공식 예제와 포털 정의를 확인했다. 완료 세션 선택·집계 범위·초기화 시점은 여전히 미확인이며 포털과 예제의 연속 조회 계약도 충돌한다. 합의한 단계 순서에 따라 12:00·15:00 KST 관측과 페이지·빈 응답 실연동·도구 변경을 보류한다. 새 KIS 관측이나 제품 지원 시간 검증을 완료한 결과는 아니다.

다음 필수 조건이 남아 있다.

- 한국 낮의 여섯 순위와 비교 시세가 직전 완료 정규장을 나타내는지 아래 검증 계획에 따라 확인한다. 기존 장전 세 시점 관측은 당시 증거로 보존한다. 순위에는 이번에 확인한 필드 중 기준일이 없으며, 조회 시각을 기준 세션으로 대체하지 않는다.
- 순위와 일별 시세의 정규장 범위, 거래량·거래대금의 단위와 집계 정의를 공식 자료로 확인한다. 같은 공급자의 두 응답이 일치한다는 사실만으로 시간외 포함 여부를 판정하지 않는다.
- 종목 유형의 공식 정의·실제 표본 확보와 안전한 자동 판별을 구분한다. 이후 확보한 우선주·워런트 정의와 반례는 [종목 식별 조사](kis-security-identification.md)를 따르며, #250의 유형·권리·증권 연결·현재성 미검증 조건을 유지한다. 이름이나 티커의 접미사로 분류하지 않는다.
- 페이지 이어받기, 빈 응답의 정상 여부, 계정에 적용되는 호출 제한과 준비 시각을 확인한 뒤 N·기간·전체 호출 및 실행 시간 제한을 합의한다.

기존 구현의 독립 공급자 대조·통합 시장 순위·정확한 거래대금 입증 요구는 적용하지 않았다. 이번 도구는 후보군이나 추천을 생성하지 않는다.

## 한국 낮 검증 계획

2026-10-26 [#249](https://github.com/mochafreddo/stock-scout/issues/249)의 설계 인터뷰에서 합의한 계획이다. 이 절은 조사·관측 결과가 아니며 기존 미검증 조건이나 후속 차단을 해제하지 않는다. 이후 진행한 첫 단계의 조사 결과는 위 보고서와 구분하며, KIS 호출·도구 변경은 후속 작업으로 둔다.

먼저 저장된 증거와 KIS 공식 API 설명·공개 예제에서 순위의 집계 세션, 초기화 시점, 과거 세션 선택 가능 여부를 한 차례의 범위를 정해 조사한다. 직전 완료 정규장 순위를 얻을 수 있는지 판단하고, 불명확하면 추가 관측으로 확인할 가설과 다음 확인 방법을 제시한 뒤 멈춘다. 같은 조회의 반복이나 공급자 답변 대기를 자동으로 추가하지 않는다. 충족 불가능하면 차단 근거와 탐색 방식 변경 선택지를 남기며, 탐색 방식 변경은 별도로 결정한다.

세션 의미가 확인되면 일반 거래일 하루의 12:00·15:00 KST를 첫 관측 목표로 삼는다. 공식 일정의 데이터 기준 세션과 판단 대상 세션, 각 요청·수신 시각과 목표 대비 지연을 기록한다. 두 시점의 성공만으로 그 사이 전체 시간이나 주말·휴장·조기 폐장·서머타임 전환의 지원을 확정하지 않는다. 예외 날짜는 미검증으로 남기고 기본 경로가 성립한 뒤 필요한 추가 검증을 정한다. 제품의 주말·휴장일 지원 목표는 유지한다.

각 시점에 NAS·NYS·AMS의 거래량·거래대금 여섯 순위와 거래소별 한 종목의 일별 시세를 비교한다. 첫 시점의 두 순위에 공통으로 나타나는 종목 중 거래량 순위가 가장 높은 종목을 거래소별로 선택하고 15시에도 같은 세 종목을 유지한다. 공통 종목이 없으면 거래량 순위 첫 종목을 사용하고 거래대금 순위와의 비교 불가를 기록한다. 표본을 선택할 수 없는 빈 응답은 미확인으로 남긴다. 이는 시장 데이터 비교 표본이므로 ETF도 허용하며 매수 후보 적격성 검증과 구분한다. 일부 표본의 수치 일치만으로 전체 순위의 기준 세션을 입증하지 않는다.

세션 의미 확인, 두 시점 기본 관측, 연속 페이지·빈 응답 검증 순서로 진행한다. 앞 단계가 막히면 뒤 단계의 호출·구현을 보류하고 #249의 미완료 조건과 차단 근거로 남긴다. 기존 여섯 순위·페이지·정상 빈 응답 검증을 삭제하거나, 확인되지 않은 빈 응답을 정상 빈 후보군으로 처리하지 않는다. 정규장 범위·단위·수정주가 여부도 확인 대상으로 유지하며, 필요한 과거 기간과 최종 운영값·지원 시간은 근거를 모아 [#251](https://github.com/mochafreddo/stock-scout/issues/251)에서 결정한다.

목표 시각을 놓치거나 조회에 실패하면 실제 시각과 실패를 그대로 기록한다. 성공한 다른 시각으로 대체하거나 자동 재관측하지 않는다. 공식 일정의 완전성·현재성 미검증은 별도 한계로 유지하며 일정 CLI 완성 자체를 관측 착수의 새 선행 조건으로 추가하지 않는다.

이번 문서 변경의 검토 기준은 `9e63bc9efc7bfa4df66fe17f7d4381d12c116dba`다. 문서 검증은 합의 내용·참조·변경 범위의 일치를 확인한다. 향후 도구 변경의 공개 검증 경계는 CLI 인수·표준 출력·표준 오류·종료 코드와 외부 HTTP 요청이며, 모의 검사와 실제 데이터 의미 검증을 구분한다.

### #250 최초 설계 합의 당시 기록

2026-10-19 [#250](https://github.com/mochafreddo/stock-scout/issues/250)의 설계 인터뷰에서 다음 기준을 합의했다. 이는 조사·구현·실연동을 완료했다는 기록이 아니며, 기존 관측의 미검증 조건과 후속 차단 상태를 유지한다.

거래소·발행사 공식 자료는 실제 표본의 유형을 확인하는 보조 근거로 허용한다. 자동 판별에 사용할 데이터 공급자는 KIS로 유지한다. 발행사가 특정 증권을 우선주로 설명한다는 사실만으로 그 표본에서 관측한 KIS 코드의 일반적인 의미를 확정하지 않는다.

유형별로 공식 의미 확인과 실제 응답 확인을 별도로 기록하고, 두 근거가 연결된 유형만 판별 가능성이 검증됐다고 본다. 공식 정의만 확인했거나 실제 표본만 확보한 경우에는 남은 검증을 명시한다. 워런트의 공식 정의가 있어도 실제 표본이 없으면 실제 판별은 미검증으로 남긴다.

마스터와 상품 정보의 유형 표시가 충돌하고 공식 설명으로 해결되지 않으면 임의로 한 필드를 우선하지 않고 해당 종목을 유형 미확인으로 제외한다. 이 충돌 때문에 보통주·ADR을 안전하게 식별할 수 없다면 후속 구현의 차단 조건으로 기록한다.

순위·마스터·상품 정보는 공식 필드 의미와 실제 대응을 확인한 거래소·종목 코드 조합으로 한 실행 안에서 연결한다. ISIN을 모든 종목의 필수 키로 고정하지 않으며 선택적 식별자의 누락만으로 실패시키지 않는다. 원본 식별자를 보존하고 접두사·구두점을 임의로 제거하거나 회사명으로 합치지 않는다. 심볼 변경·거래소 이동 전후의 영구 식별은 범위 밖이다. 이는 연결 기준에 관한 합의이며 현재 표본으로 모든 표기 간 대응을 검증했다는 뜻은 아니다.

같은 거래소·종목 코드가 서로 다른 증권 식별자를 가리키거나 순위 행을 어느 종목 정보에 연결해야 할지 확정할 수 없으면, 후속 후보군 실행은 전체 실패로 처리한다. 유형 미확인은 종목 식별 뒤의 개별 제외이며 식별 자체의 모호함과 구분한다.

정상 응답을 받았지만 유형을 확정하지 못한 경우만 유형 미확인으로 개별 제외한다. 인증·통신 오류와 응답 구조 오류는 조회 실패로 구분한다. #250 조사에서는 확보한 증거를 남기고 해당 검증을 미완료로 기록하며, 후속 후보군 실행에서는 전체 실패로 처리한다.

DR 표시만으로 적격 ADR을 확정하지 않는다. 보통주 성격임을 확인한 ADR은 포함하고, 기초 증권이나 권리가 우선주 성격이면 제외하며, 구분할 근거가 부족하면 유형 미확인으로 제외한다. 예탁증서의 성격은 [용어집](../GLOSSARY.md)의 후보군 적격 조건을 따른다.

전체 상장 종목을 조사하는 대신 보통주·ADR·ETF·ETN·우선주·워런트의 유형별 실제 표본과 공식 정의를 연결하고 오분류를 드러내는 반례를 확인한다. 외국 기업 보통주와 같은 회사의 서로 다른 증권도 확인한다. 기존 표본은 재사용할 수 있지만 채택할 분류 코드마다 실제 대응 근거를 남긴다. 확보하지 못한 유형은 미검증으로 유지하며, 표본 확인을 전체 시장의 분류 정확도 보장으로 확대하지 않는다.

### #250 유형 자료의 현재 정책과 남은 차단

2026-10-20 [ADR 0007](adr/0007-llm-security-type-judgment.md)에 따라 현재 첫 검증 흐름은 KIS 순위 → LLM의 자료 조회·유형 판단 → 포함·제외와 근거 출력이다. [현재 상태와 실행 기록](llm-security-probe.md#현재-검증-상태)에 로컬 검사와 로그인 지연 이력·이후 실제 인증 성공을 구분했다. 현재는 구독 도구의 개별 실제 호환성을 확인했지만 최종 출처 연결과 제한 시간 내 유형 결과가 미완료다. 범용 코드 분류기나 Massive 채택·문의는 이 흐름의 필수 선행 산출물이 아니다. 최초 설계의 코드 판별 전제와 개별 유형 자료 조회 실패의 전체 실패 계약은 해당 범위에서 대체한다. 실제 유형 평가와 나머지 시장 데이터·일정·운영값 차단은 유지한다.

최초 설계 이후 [ADR 0005](adr/0005-official-security-type-sources.md)·[ADR 0006](adr/0006-third-party-security-type-sources.md)에 따라 종목 유형과 개별 증권 연결에는 외부 공식 자료와 허용된 제3자 공급자 자료를 검토한다. 시세·거래량·거래대금·순위 및 그 밖의 종목 정보는 KIS로 유지한다. 앞선 최초 설계의 KIS 전용 범위가 현재 유형 자료 정책을 제한하지 않는다.

2026-10-20 [재검토 보고서](third-party-security-type-sources.md#2026-10-20-자동-이용보관-차단-범위-재검토)는 Massive 자동 연결·분류·후보 포함 판단에 표시·비표시 이용 제한이 적용되는 관계를 미확정으로 남긴다. 해당 실제 검증과 채택은 보류하되 보관 일수의 설명 부족과 실제 결과 공개의 미확정을 비공개 검증의 독립적인 전체 중단 이유로 삼지 않는다. 허용된 이용을 전제로 보관·백업·삭제 방법을 정하고 종료·제한·정지 시 삭제 의무를 반영해야 한다. 문의나 답변 대기는 필수 선행 조건이 아니다.

실제 유형·ADR 기초 권리·KIS 연결·현재성 검증이 남아 #250과 후속 후보군·추천의 차단을 유지한다. 저장된 KIS 자료 검토와 독립적인 일정 검증은 계속할 수 있지만 이번 갱신에서 추가 실행하지 않았다. 장전 데이터 의미·일정·운영값 등 다른 미검증 조건도 유지한다.

## 검증 도구와 재현

현재 관측 CLI의 실행 환경·로컬 검사·실제 조회 절차는 [처음 실행하고 검증하기](getting-started.md)에 있다. 인수·환경 변수·요청 조건·출력 필드·오류의 정확한 계약은 [KIS 관측 CLI 레퍼런스](kis-probe-reference.md)에 있다. 도구의 성공 코드는 자료의 의미나 장전 지원 시간을 검증한 결과가 아니다.

마스터 표본은 공식 예제를 실행하지 않고 표준 라이브러리로 ZIP을 메모리에서 읽어 선택했다. 마스터 자동 수집 기능은 CLI에 추가하지 않았다. 재확인할 때 ZIP의 대문자 파일명과 24열 구조를 확인하고, 위 공식 열 정의에 따라 `symbol`, `securityType`, `dr`, `etpType`, 거래소·식별자만 추린다. 새 분류 표본은 후보군에 추가하지 않는다.

모의 검사와 위 실제 조회는 별도 근거다. 기존 검사 결과와 음성 대조 결과는 [#243 작업 기록](https://github.com/mochafreddo/stock-scout/issues/243#issuecomment-6232840769)에 있다. 재현 명령과 검사 대상은 시작 안내에서 확인한다. Actions는 비활성 상태를 유지한다.

### 구현과 검증 근거의 구분

현재 동작의 기준은 [관측 CLI](../scripts/kis-probe.ts)이며, 모의 검사의 범위는 [CLI 테스트](../tests/kis-probe.test.mjs)와 [HTTP 모의 코드](../tests/kis-http-mock.mjs)에서 확인한다. 레퍼런스가 설명하는 모든 경계에 자동 검사가 있는 것은 아니다.

| 항목 | 현재 근거 | 남은 한계 |
| --- | --- | --- |
| 네 모드·세 거래소의 요청과 JSON 출력 | CLI 프로세스 모의 검사. 경로별 `tr_id`, 종목 정보의 상품유형 코드, 일별 `GUBN/MODP` 등을 확인함. | 모의 데이터는 실제 상장 종목·시장 데이터가 아니며 모든 쿼리 값을 검사하지 않음. |
| 인증 누락·잘못된 입력·오류 출력 | 앱 키 누락, 일부 잘못된 인수, HTTP·KIS·JSON·통신·행 구조 오류를 모의 검사함. | 모든 인수 경계와 오류 코드별 정확한 대응을 자동 검사하지 않음. |
| 필드 제한과 미검증 표시 | 테스트용 비밀 필드의 배제, 일부 선택 필드, `validation`과 `dataSession`을 모의 검사함. | 모든 허용 필드·값 타입 조합의 자동 검사는 아님. |
| 빈 배열·연속 조회 표시 | 빈 응답과 `M` 표시 보존을 모의 검사함. 페이지 이어받기는 하지 않으며 명시적 만료 복구에서만 한 번 재조회함. | 인증·복구 테스트는 외부 요청 경로와 횟수를 확인함. 실제 후속 페이지·정상 빈 응답 의미는 미검증. |
| 1000행 제한·허용 연속 조회 코드·15초 제한 | 구현의 조건과 설정을 정적으로 확인함. | 초과 행·비허용 코드·실제 시간 초과를 재현하는 전용 자동 검사는 없음. |
| 실제 응답의 세션·단위·유형 | 위 토요일 관측과 저장 자료, 고정 커밋의 공식 예제. | 장전 지원·정규장 범위·보통주 및 우선주 코드 정의 등 필수 조건이 남음. |

이 표는 기존 검사와 미검증 경계를 구분한다. 자동 검사에 없는 동작도 구현에 있을 수 있으나 모의 검사 통과만으로 입증했다고 보고하지 않는다. [인증 없는 모의 실행](getting-started.md#인증-없이-관측-json-확인하기)은 출력 형식을 직접 확인하는 절차이며 실연동 근거를 추가하지 않는다.

## 인증 절차 명세

2026-10-17 추가 설계 대화에서 합의한 자동 발급·보호된 캐시 재사용·만료 판정·인증 실패 처리와 검증 조건은 [#243 명세](https://github.com/mochafreddo/stock-scout/issues/243)에 통합했다. 해당 이슈를 요구사항의 기준으로 삼는다. 자동 발급·보호된 캐시 재사용은 #247에서, 조회 중 명시적 만료의 한 번 복구는 #248에서 구현했다. 현재 CLI는 앱 키·시크릿만 입력받으며 사전 발급 토큰 입력을 사용하지 않는다. 실행·복구·모의 검사와 실연동의 구분은 [KIS 인증과 복구](kis-auth.md)에 있다. 실제 만료 복구와 부모의 시장 데이터 검증은 미완료다.


정책 근거는 [#246의 조사 기록](https://github.com/mochafreddo/stock-scout/issues/246#issuecomment-6233975943)과 [완료 기록](https://github.com/mochafreddo/stock-scout/issues/246#issuecomment-6234140883)에 있다. 아래는 당시 확인한 공식 자료·운영 가정과 이후 구현 상태를 구분한 기록이다.

### 공식 문서에서 확인한 사실

아래 내용은 2026-10-17 KIS 공식 상세 문서와 FAQ 본문을 비로그인 브라우저에서 직접 확인한 결과다.

- [접근토큰발급(P) 상세 문서](https://apiportal.koreainvestment.com/apiservice-apiservice)의 OAuth인증 → 접근토큰발급(P)은 POST `/oauth2/tokenP`에 `grant_type=client_credentials`와 앱 키·시크릿을 전달하는 방식을 정의한다. 개인고객 접근토큰 수명은 24시간이며 6시간 이내 재호출하면 기존 토큰을 반환한다고 안내한다.
- [재호출 FAQ](https://apiportal.koreainvestment.com/community/10000000-0000-0011-0000-000000000002/post/f2b74a2b-c63e-496a-81fc-fece1b38a825)는 기존 토큰이 재반환될 수 있으므로 서버 만료 일시 `access_token_token_expired`를 함께 저장해 관리하도록 권한다. 확인한 본문에는 이 시각의 시간대와 재반환 시 `expires_in`이 남은 수명인지 최초 유효기간인지에 대한 명시적 정의가 없다.
- 발급 호출 주기는 [관리 FAQ](https://apiportal.koreainvestment.com/community/10000000-0000-0011-0000-000000000002/post/0ad7f35e-8ada-4c37-ae11-c9ee293f3720)의 5분당 1회와 [EGW00133 FAQ](https://apiportal.koreainvestment.com/community/10000000-0000-0011-0000-000000000002/post/a046c19e-d638-4eda-bd1a-264934fdfd5e)의 1분당 1회 안내가 일치하지 않는다. 최신 게시일만으로 이전 안내의 폐기를 확정하지 않았다.

[공식 오류 코드 표](https://apiportal.koreainvestment.com/faq-error-code)의 EGW서버 정의에 따르면 `EGW00123`은 토큰 만료, `EGW00121`·`EGW00122`는 무효·미발견 토큰이다. `EGW00205`는 Bearer 자격 증명 유형 오류이므로 앞선 실제 조회 실패를 토큰 만료 증거로 해석하지 않는다. 앱 키·시크릿·라우팅·시간 초과 오류를 포함한 상세 분류는 #246에 기록했다.

### 승인한 운영 정책

- 서버 만료 일시를 KST(UTC+09:00)로 명시적으로 해석한다. 이는 사용자가 승인한 운영 가정이며 공식 시간대 계약을 입증한 사실이 아니다. 실행 환경의 로컬 시간대에 의존하지 않는다. 가정이 틀리면 만료 토큰 재사용이나 조기 재발급이 가능하며 반대 근거가 확보되면 정책과 검증을 재검토한다.
- `expires_in`은 만료 계산·보조 검증·발급 성공 판정에 사용하지 않는다. 이 필드의 누락·값 불일치를 실패 조건으로 삼지 않으며 요청 시각에 더하거나 24시간 고정값으로 서버 만료 일시를 대체하지 않는다. 서버 만료 일시가 누락되거나 잘못됐거나 해석할 수 없으면 실패한다.
- 만료까지 60초 이하인 토큰은 재사용하거나 정상 발급으로 인정하지 않는다. 발급 시도 간격은 이 경계와 별도로 최소 5분(300초)이며 기존 토큰 재반환과 통신 실패를 포함한 모든 발급 시도에 적용한다. 5분은 상충하는 두 안내보다 자주 요청하지 않기 위한 CLI 자체 정책이다. 공급자의 실제 적용 단위나 실패 요청 포함 여부, 다른 프로그램의 호출까지 입증하거나 통제한 결과가 아니다. 제한 안에서는 대기·자동 재시도 없이 남은 시간을 알리고 실패한다.
- 조회 오류의 구조화된 코드가 정확히 `EGW00123`일 때만 캐시를 무효화하고 발급·조회를 한 번 다시 시도한다. HTTP 비정상 상태에서도 오류 본문을 확인하며 정상 형태의 데이터가 오류에 함께 있어도 성공으로 처리하지 않는다. 복구에도 발급 간격·잠금·안전한 저장을 적용하고 제한 충돌·발급 또는 저장 실패·두 번째 만료에서는 추가 발급 없이 실패한다. 발급 API 자체의 실패를 조회 복구 루프로 재귀 처리하지 않는다.
- 무효·미발견 토큰, 앱 키·시크릿·Bearer 유형 오류, 인가 코드·세션 키 만료, 공급자 라우팅·시간 초과는 자동 재발급 대상에서 제외한다. 구조화된 KIS 응답이 없는 DNS·TLS·연결 종료·클라이언트 타임아웃은 통신 실패로 구분한다. HTTP 상태·오류 문구의 부분 일치, 코드 누락·미등록 코드·해석 불가능한 응답으로 토큰 만료를 추정하지 않는다.
- 공급자 문의 제출·답변 수신과 사용하지 않는 `expires_in`의 의미 확정은 후속 구현의 선행 조건이 아니다. KST 운영 가정은 인증에 한정하며 시장 데이터·종목 유형·거래 일정의 미검증 조건을 추정으로 대체하지 않는다.

### 구현 상태와 검증 한계

#246 조사 당시 CLI는 사전 발급된 `KIS_ACCESS_TOKEN`을 요구했다. 이후 [#247](https://github.com/mochafreddo/stock-scout/issues/247)에서 자동 발급·캐시 재사용을, [#248](https://github.com/mochafreddo/stock-scout/issues/248)에서 명시적 만료의 한 번 복구를 구현했다. 현재 CLI는 앱 키·시크릿만 입력받으며 사전 발급 토큰 입력을 사용하지 않는다. 조건부 무효화·공통 발급 제한과 검증 범위는 [KIS 인증과 복구](kis-auth.md)에 있다.

#246 조사에서는 자격 증명 조회·실제 인증 호출·의도적인 만료나 잘못된 앱 키 요청을 수행하지 않았다. 앞선 토요일의 메모리 전용 발급도 새 인증 절차의 검증 결과가 아니다. 이후 #247에서 실제 발급·별도 프로세스 재사용과 해당 응답의 KST 해석을 확인했으며, #248의 복구 검사는 외부 HTTP와 시각을 대체한 모의 검사다. 공식 시간대 계약과 실제 만료 복구의 오류·재발급·재조회 조합은 여전히 미검증이다. 문서에서 확인한 오류 코드 의미나 모의 검사 통과를 실연동 성공으로 확대하지 않는다.

#246의 완료는 #243·#239의 시장 데이터 검증이나 전체 제품 인수 완료를 뜻하지 않는다. 명세 합의와 구현·실연동의 실행 승인은 구분한다. Actions는 비활성 상태를 유지한다.
