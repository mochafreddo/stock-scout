## 승인과 선행 근거

사용자는 2026-11-10 이 대화에서 기존 보호 위치·인증·기본 계좌 재사용과 필요한 토큰 갱신, Codex·dots 각각 최대 25회의 시장·계좌 조회를 승인했다. 시장 명령 전체, 보유·USD/KRW 매수 가능 금액, 최근 30일 거래내역, 일반·조건 주문 OPEN/CLOSED가 범위다. 금융 JSON을 각 소비 에이전트가 해석하고 해당 대화의 처리·보관 대상으로 삼되 별도 원문 파일·공유 로그에는 저장하지 않는 범위를 승인했다.

[#294의 사용자 재결정](toss-access-readiness.md)에 따른 공급자 조회 전용 권한과 세부 처리·보관 조건의 남은 미확인은 유지한다. 이번 승인이 공급자의 개별 계약이나 소비 환경의 실제 학습·메모리 설정을 확인한 근거는 아니다. 기본 계좌·허용 범위·자격 증명을 변경하지 않았다. 보호 디렉터리와 실행기는 0700, 자격 증명·선택·상태 파일은 0600인 메타데이터를 확인했다. 비밀값·선택 파일 본문을 모델에 전달하지 않았다.

선행 [시장 조회 #296](toss-market-validation.md)와 [계좌 조회 #297](toss-account-validation.md)은 이번 착수 시 종료 상태였다. 명령별 자료 의미·원응답 대조·실제 페이지 연결은 그 기록을 적용한다. #297의 조건 주문 실제 다음 페이지 표본 예외와 진행 중 조건 주문 미관측 한계를 유지한다. 이번에는 소비 환경의 발견·호출·해석을 확인하며 공급자 검증 전체를 반복하지 않았다.

## Codex: 직접 관측

로컬 Codex 데스크톱의 이 대화에서 [에이전트 지침](toss-agent-usage.md)과 [CLI 레퍼런스](toss-cli.md)를 읽고 `--help`의 현재 명령·인수를 확인했다. 별도 Codex CLI 에이전트를 띄우지 않고 로컬 프로세스 실행 도구로 승인된 기존 실행기를 호출했다. 제품 런타임은 위 기준 커밋 그대로이며 합성 실행기·지침만 이번에 확장했다.

2026-11-10 21:17:22~21:17:56 KST에 실제 조회 21회를 순차 실행했다. stdout 전체는 관측 프로세스 메모리에서 JSON으로 해석하고, 각 명령의 자료와 출처를 이 승인된 Codex 문맥에 전달했다. 큰 목록은 개수와 일부 항목, 보유는 요약과 일부 항목을 전달했다. 메타데이터 증거에는 명령·시각·상태·종료 코드·누락 사유·페이지 존재 여부만 저장했다. 실자료 원응답·계좌 식별자·금융값·실제 커서는 이 공유 기록에 포함하지 않는다.

모든 호출의 stderr는 비어 있었고 `success=0`·`partial=2`가 일치했다. stdout의 계좌·인증 필드 키 부재를 관측 프로세스에서 확인했다. 모든 가능한 비밀값·계좌번호와 문자열을 전수 대조한 검사가 아니며 마스킹의 기존 공개 회귀 검사·#297 근거와 구분한다. 이번 소비 실행은 원응답과의 재대조나 독립 원장 검증이 아니다. 실제 후속 페이지는 호출하지 않았으며 #296·#297의 공급자 관측과 아래 합성 소비 검증에 연결한다.

## 합성 소비와 실행기 확장

기존 `tests/toss-agent-cli.mjs`를 확장해 나중에 추가된 시장 명령과 모든 계좌 조회를 같은 실제 CLI·외부 HTTP mock 경로에서 실행할 수 있게 했다. 계좌 선택은 매 호출의 격리된 임시 상태에 합성 계좌만 준비하며 실제 상태를 읽거나 변경하지 않는다. 거래내역·일반 종료 주문·조건 주문에는 빈 첫 페이지와 정확한 커서·context를 사용하는 마지막 페이지가 있다. 별도 서버나 새 공급자는 추가하지 않았다.

Codex에서 지침 → help 발견 → 합성 보유 JSON 해석 → 빈 거래내역 partial·2 → 반환된 cursor/context 복사 → 실제 항목이 있는 마지막 success·0 → 합성 계좌 PERMISSION_DENIED·1을 직접 실행하고 해석했다. 빈 페이지는 완료가 아니며 오류는 빈 계좌가 아니다. 합성 constraints의 partial·2도 적격성 미확인으로 읽었다. 자동 회귀 검사는 추가 시장 명령·양쪽 주문 그룹·거래내역 및 두 주문 커서 연결·소수 문자열·null·계좌 가림을 검사한다. 자동 테스트만으로 dots 실행을 입증하지 않는다.

확장 전 계좌 소비 검사와 나중 시장 명령 검사가 각각 실패하는 것을 확인한 뒤 실행기를 확장했다. 중간 실행에서 stock 합성 응답의 필수 필드 누락으로 RESPONSE_INVALID가 나왔고, 응답 fixture를 공식 계약에 맞게 수정했다. 제품 응답 검증이나 테스트 기대값을 완화하지 않았다.

## dots: 사용자 보고와 실제 연결 차단

사용자가 전달한 dots 실행 보고에 따르면, 2026-11-10 21:42:44~21:43:50 KST에 로컬 Darwin 25.6.0 arm64·Node v26.12.1 환경에서 커밋 `92d040d16c9caac5edb3fcd4879e1451ed88c573`을 실행했다. 아래는 사용자 보고이며 Codex가 dots 화면이나 원본 실행 로그를 직접 확인한 결과가 아니다. 개인 호스트 이름과 실제 보호 경로는 공유 기록에서 제외했다.

지침 → CLI 레퍼런스 → `node scripts/toss.ts --help`의 발견 경로는 success·0이었다. 합성 종목·가격·네 순위·거래 가능 목록·호가·체결·세션·보유·USD 매수 가능 금액·거래내역·일반 및 조건 주문 OPEN/CLOSED는 success·0으로 보고됐다. constraints는 적격성·앱 조건 미확인의 partial·2로 해석했다. 합성 `error holdings`와 `error prices`의 PERMISSION_DENIED·1은 정상 빈 결과와 구분했다.

합성 candles·transactions·orders CLOSED·conditional-orders CLOSED의 빈 첫 페이지 partial·2에서, 반환된 봉 경계 또는 cursor/context를 그대로 사용해 항목이 있는 마지막 success·0 페이지까지 확인했다고 보고했다. 거래내역 결제일·상태와 주문 생성일·상태, 미국 요청 날짜와 KST 세션, 통화와 소수 문자열·null·미확인을 구분했고 합산이나 정산 금액 재계산은 하지 않았다. candles의 success 시나리오 거부는 기존에 문서화한 실행기 범위이며 partial 시나리오로 봉을 검사했다.

합성 `buying-power KRW`는 RESPONSE_INVALID·1로 보고됐다. Codex에서도 같은 명령의 실패를 재현했다. 합성 실행기가 KRW에 소수 금액을 반환했으나 제품 계약은 정수 문자열을 요구하는 것이 원인이다. KRW fixture를 정수 문자열로 수정하고 공개 CLI 회귀 검사의 수정 전 실패와 수정 후 통과를 확인했다. 제품의 금액 검증은 변경하지 않았다. 수정본의 dots 재실행은 아직 보고되지 않았다.

실제 조회는 기존 실행기의 `stock AAPL` 한 번이 21:43:50 KST에 AUTH_STORAGE·1로 실패해 중단했다. 승인된 25회 중 실제 실행은 1회, 성공은 0회이며 나머지 시장·계좌 명령은 실행하지 않았다. 출력만으로 보호 저장소의 구체적 거부 원인이나 토큰 갱신 여부는 확정할 수 없다. 파일 접근·실행 사용자·경로·잠금·상태 검증 경로의 어느 단계가 막혔는지 dots 환경의 추가 근거가 필요하다. Codex의 정상 권한 메타데이터 확인을 dots 접근 성공의 근거로 삼지 않는다. 보호 권한 완화·인증 복사·저장소 이동은 수행하지 않았다.

후속 Codex 메타데이터 비교에서 같은 사용자·경로·0700/0600 권한으로 샌드박스 안의 쓰기 접근 검사는 EPERM, 승인된 샌드박스 밖 검사는 성공이었다. 경로는 정규 경로와 같고 Git 상위 경로도 없었다. 자격 증명이나 선택 파일 본문을 열지 않았고 검사 자체는 보호 파일에 쓰지 않았다. CLI는 조회에도 공통 상태·잠금 쓰기가 필요하므로 실행 환경의 쓰기 제한은 가능한 원인이다. 이는 Codex에서 관측한 차이이며 dots의 실제 실패 단계는 미확정이다. dots의 기존 실행기 권한 승인 경로를 확인한 뒤 재시도하며 보호 파일의 권한을 낮춰 우회하지 않는다.

[#295의 이전 합성 결과](toss-agent-validation.md)와 이번 합성 실행 보고 모두 실제 시장·계좌 자료 소비의 성공을 대신하지 않는다. 재개 시 수정된 KRW 합성 명령과 승인된 범위의 실제 소비 경로를 dots에서 다시 확인한다. 연결이 성립하지 않으면 사용자 연결 방식 재결정으로 남긴다.

## 인수 상태

Codex의 승인된 실제 소비 경로와 합성 오류·후속 페이지 처리를 확인했다. dots의 명령 발견·합성 페이지 및 오류 처리는 사용자 보고로 확보했으나, 수정된 KRW 합성 재실행과 AUTH_STORAGE 해소 뒤 실제 시장·계좌 소비가 남아 있다. #298 완료·두 환경 인수·최종 전환을 선언하지 않으며 기존 KIS·내장 모델 경로 제거도 보류한다. 추천 품질·수익률 평가는 수행하지 않았으며 인수 조건으로 추가하지 않는다. 재개 조건은 dots 접근 차단 원인의 확인과 승인된 실제 소비 실행 또는 사용자의 연결 방식 재결정이다.
