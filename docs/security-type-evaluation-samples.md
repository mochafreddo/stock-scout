# 종목 유형 평가 표본과 독립 정답

2026-10-22 [#260](https://github.com/mochafreddo/stock-scout/issues/260)의 표본 조사 기록이다. 기준은 [#250](https://github.com/mochafreddo/stock-scout/issues/250), [ADR 0007](adr/0007-llm-security-type-judgment.md)과 [실제 평가 재개 설계](security-type-live-evaluation-design.md)다. 모델 출력 없이 공식 자료로 정답을 확인했다. 실제 모델 평가는 실행하지 않았다.

## 현재 상태

현재 평가 정책은 [ADR 0010](adr/0010-incremental-security-type-validation.md)을 따른다. 아래 8개 사례·11개 증권과 버전 `2026-10-22.2`는 당시 확정한 참고 표본이며 전체 실행·3회 통과·적격 종목 전부 포함의 필수 관문이 아니다. 초기 정확도 점검에서는 실행 전에 필요한 작은 부분집합을 고르고 정답과 제출 근거를 대조한다. 원래 표본·정답·입력 해시와 당시 준비 완료 상태는 바꾸지 않는다.

2026-10-26 후속 구현 요청으로 AAPL과 BBD·BBDO 두 사례·세 증권의 실제 평가와 제출 근거 심사를 수행했고 선택 표본의 통과 기준을 충족했다. 실행 코드는 바꾸지 않았다. 아래 [첫 점검 결과](#261-첫-점검-결과)와 [선별 실행 근거](evidence/issue-261/evaluation.json)는 원래 #260의 표본 준비 기록과 구분한다.

8개 사례, 11개 증권의 유형·상장 연결과 기대 포함·제외를 확정했다. 2026-10-22 후속 합의로 자료 부족·미해결 충돌의 실제 표본 확보를 필수 준비 조건에서 제외하고, 버전 `2026-10-22.2`의 표본 상태를 `sample_ready`로 기록한다. 입력 8개·정답·입력 해시는 이전 버전과 같으며 평가 정책과 준비 상태만 변경했다. 당시 실제 모델 평가는 0회였으며 #250의 정확도 검증·제품 인수 완료나 실행 선행 조건 전체의 충족을 뜻하지 않는다.

평가자용 [정답 목록](evidence/issue-260/answers.json)은 입력 파일의 SHA-256과 독립 정답을 기록한다. 각 입력에는 기존 CLI가 허용하는 `securities`, `exchange`, `symbol`만 있다. 자료 부족·충돌의 자리에 가상 티커나 이미 적격으로 확인한 종목의 임의 제외를 넣지 않았다. 모의 HTTP 검사의 부족·충돌 사례를 실제 표본 확보로 계산하지 않는다.

## #261 첫 점검 계획

2026-10-26 설계 인터뷰에서 첫 점검은 기존 01 보통주와 03 같은 회사의 ADR 권리 사례로 정했다. `NAS/AAPL`은 보통주 포함, `NYS/BBDO`는 보통주 성격 ADR 포함, `NYS/BBD`는 우선주 성격 ADR 제외를 확인한다. 두 입력 사례·세 증권으로 기본 포함·제외와 같은 발행사의 별도 증권·ADR 기초 권리 구분을 점검하고, 나머지 표본은 후속 확장에 사용한다. 기존 정답·입력·해시와 과거 준비 기록은 보존한다.

실행 전에 선택한 표본의 상장 연결·유형·권리·현재 적용 가능성을 모델 출력과 독립적으로 재확인한다. 선택 이유·정답·근거·확인 시점·입력 해시와 소스·모델·설정을 고정하며 모델에는 입력 JSON만 전달한다. 이 설계 작업에서 현재성을 새로 확인한 것은 아니다. 적용 가능성이 달라졌다면 실제 모델 실행 전에 이유와 새 평가 버전을 기록하며, 실행 결과에 맞춰 정답이나 실패 표본을 바꾸지 않는다.

점검 결과는 다음과 같이 구분한다. 근거 ID와 실제 열람 출처의 연결, 자료가 뒷받침하는 의미는 별도로 심사하며 증권 연결·유형·현재 적용 가능성·알려진 반대 근거와 ADR 기초 권리를 확인한다.

| 결과 | 기준 |
| --- | --- |
| 통과 | AAPL과 BBDO를 각각 올바른 유형과 타당한 근거로 포함하고, BBD는 우선주 성격 ADR임을 확인해 제외한다. |
| 부분 충족 | 실행을 완료했지만 일부 종목의 식별·유형·현재 적용 가능성을 확인하지 못해 보수적으로 제외했다. 미확인을 확인된 비적격 유형의 정답으로 대신하지 않으며 누락 사유를 개선 대상으로 남긴다. 전부 미확인이면 계속 분석 불충분이며 유용한 판단 성공으로 표시하지 않는다. |
| 실패 | 잘못된 포함·잘못된 유형 확정·근거 없는 확정이나 실행 오류가 있다. 다른 종목의 자료나 해결되지 않은 권리·현재성 충돌에 의존한 판단도 통과하지 않는다. 실패는 부분 충족보다 우선한다. |

후속 작업은 최초 평가와 관측한 문제의 최소 수정, 영향받는 회귀 검사·사례 재확인을 한 범위로 진행한다. 먼저 AAPL 사례, 이어 BBD·BBDO 사례를 각각 한 번 실행한다. 오류나 오분류가 나오면 남은 평가를 멈추고 원인을 확인한다. 기존 실행에서 웹 열람 자료가 최종 유형 근거로 연결되지 않은 지점을 조사하되 원인을 미리 단정하지 않는다. 근거 없이 같은 실행을 반복하거나 안전 검사를 완화하지 않는다.

실제 CLI 실행 예산은 최초 두 사례와 수정 후 재확인을 합쳐 최대 4회다. 남은 최대 두 번은 관측한 문제를 수정한 뒤 영향받는 사례를 확인하는 데만 사용하며 공통 변경이면 두 사례를 모두 다시 확인한다. 성공하면 반복하지 않는다. 예산 안에 해결하지 못하면 실패·미수행·부분 충족과 다음 선택을 남기고 추가 실행이나 모델·한도 변경을 별도로 결정한다. 통과한 실행만 합치지 않으며 실패와 각 실행의 입력·구현 버전을 보존한다.

개발·테스트 모델은 `gpt-6-luna`를 유지한다. 각 CLI 실행에는 모델 흐름 전체 180초, 모델 HTTP 요청 최대 12회·KIS 종목 정보 도구 최대 32회·관측 웹 도구 호출 최대 32회를 적용한다. 별도 조회 전용 120초 제한은 없고 웹 호출 수는 공급자 내부 요청의 사전 상한이 아니다. 기존 구독 인증과 출처·실패·비밀·비용 계약을 유지하며 유료 API로 자동 전환하지 않는다. 이 값은 최종 제품 운영값이 아니다.

각 실행의 입력·소스·설정 해시, 모델·명령·시작 및 종료 시각, stdout·stderr·종료 코드와 안전한 외부 요청·출처 관측, 포함·제외·미확인 수·처리 시간을 비밀 값 없이 보존한다. 공개 검증 경계는 CLI 입력·stdout·stderr·종료 코드와 외부 HTTP 요청이다. 실제 근거의 의미 심사는 모의 회귀 검사와 구분하고, 코드 수정 시 영향받는 검사와 버그 수정 전 실패·수정 후 통과를 확인한다. 새 범용 평가 프레임워크는 추가하지 않는다.

설계 확정 당시 범위는 이 문서와 ADR 0010의 로컬 설계 반영까지였으며 구현·실제 호출·커밋·푸시·원격 이슈 갱신·종료는 포함하지 않았다. 후속 `implement` 요청은 위 계획의 실제 평가와 필요한 최소 수정·검증·리뷰·현재 브랜치 커밋을 승인했다. 푸시·원격 이슈 갱신·종료는 포함하지 않는다. 검토 기준은 `1c68e351c44f931d84c3fae478461f563caec728`과 이번에 확보한 #237·#250·#261 원문 및 관련 실행 기록이다. 이 점검 결과를 전체 시장 정확도·매수 추천 제품 인수나 다른 시장 데이터·일정·운영값의 검증 완료로 확대하지 않는다.

## #261 첫 점검 결과

2026-10-26 실행 전에 기존 두 입력과 독립 정답을 버전 `2026-10-26.1`로 선택·고정했다. 공식 Nasdaq 디렉터리의 생성 시각 `1023202621:31`에서 AAPL 보통주와 NYSE의 별도 BBD·BBDO 상장을 재확인했다. 발행사 [주식 안내](https://www.bradescori.com.br/en/services/bradesco-shares/)와 [FAQ](https://www.bradescori.com.br/en/services/faq/)에서 BBD 우선주 성격 ADR, BBDO 보통주 성격 ADR과 1:1 비율을 확인했다. 해당 페이지의 발행일은 표시되지 않으며 최신 디렉터리와 함께 현재 적용 가능성을 판단했다. 모든 후속 기업행동의 부재를 전수 입증한 것은 아니다. Bradesco 원문 직접 수집은 네트워크 오류였고 웹 도구의 실제 페이지 열람을 근거로 삼았다. 원문 전체 보관 성공으로 표시하지 않는다.

| 사례 | 실제 결과 | 포함·제외·미확인 | 모델 흐름 / 프로세스 전체 | 모델 요청·KIS 정보·관측 웹 호출 |
| --- | --- | --- | --- | --- |
| AAPL | `common`, 포함, 종료 코드 0 | 1·0·0 | 17.320초 / 19.723초 | 3·1·2 |
| BBD·BBDO | BBD `preferred_adr` 제외, BBDO `common_adr` 포함, 종료 코드 0 | 1·1·0 | 18.340초 / 18.457초 | 3·2·2 |

두 실행은 기존 `gpt-6-luna`·구독 인증과 실행별 한도를 유지했다. 정답·평가자 근거를 모델에 주지 않았으며 외부 요청 관측에서 원본 거래소·종목 코드만 담긴 평가 입력을 확인했다. 입력·실행 코드·잠금 파일 해시는 실행 전후 같았고 모델 요청 세 번 모두 HTTP 200과 명시적 완료를 관측했다. 두 실행의 stdout·stderr·종료 결과·안전한 요청 관측과 처리 시간을 저장소 밖의 소유자 전용 기록에 보존했으며, 공유 가능한 해시·집계·근거 심사만 [실행 근거](evidence/issue-261/evaluation.json)에 남겼다.

AAPL은 실제 연 [2026-07-30 SEC 8-K](https://www.sec.gov/Archives/edgar/data/320193/000032019326000018/aapl-20260730.htm)의 표지에서 Common Stock·AAPL·Nasdaq 연결을 확인했다. 공시는 조회일보다 오래된 자료이지만 독립적으로 확보한 최신 디렉터리도 같은 유형·상장을 명시한다. FAQ의 거래소·티커나 우선주 부재만으로 유형을 확정한 결과가 아니다. BBD·BBDO는 실제 연 발행사 주식 안내가 두 ADR의 기초 주식 종류를 명시한다. KIS 이름·코드 `01`은 단독 유형 근거로 인정하지 않고 종목 연결을 보완하는 자료로 심사했다. 확인한 자료 범위에서 해결되지 않은 유형·권리 충돌은 발견하지 못했다.

각 실행에서 성공한 웹 열람이 출처 목록에 등록되고 해당 목록이 후속 모델 요청에 전달됐으며 최종 판단이 같은 출처 ID를 인용한 것을 확인했다. 이 연결 확인과 위 자료 의미 심사는 별개다. 기존 실제 순위 실행의 근거 연결 문제가 전체 입력에서 해결됐다고 일반화하지 않으며, 이번 두 사례에서 코드 결함이 관측되지 않아 실행 코드·프롬프트·검사 기준은 수정하지 않았다. 선택한 세 증권은 모두 통과, 미확인 누락과 실행 실패는 0건이다. 최대 4회 중 2회만 사용했고 성공 후 반복이나 모델·한도 변경은 하지 않았다.

이 결과는 작은 독립 표본의 한 번씩 점검이며 전체 표본·반복 정확도·실제 순위 판단 품질·매수 추천 제품 인수를 입증하지 않는다. 기존 #260 정답과 입력 8개는 바꾸지 않았다. 코드 수정이 없어 새 TDD 회귀나 소스 변이는 추가하지 않으며 기존 공개 CLI·외부 HTTP 회귀 검사와 최종 검증 결과는 후속 검증 기록으로 구분한다. 원격 이슈의 체크 상태나 종료는 이 로컬 기록으로 자동 변경하지 않는다.

## 확인 범위와 시점

확인일은 2026-10-22다. 현재 상장은 [Nasdaq 상장 디렉터리](https://www.nasdaqtrader.com/dynamic/SymDir/nasdaqlisted.txt)와 [다른 거래소 상장 디렉터리](https://www.nasdaqtrader.com/dynamic/SymDir/otherlisted.txt)의 생성 시각 `1021202621:31`을 확인했다. 생성 시각은 Nasdaq의 [필드 정의](https://www.nasdaqtrader.com/Trader.aspx?id=SymbolDirDefs)에 따라 자료 생성 시각으로 해석하며, 별도 근거 없이 시간대를 단정하지 않는다. 비시험 종목 표시와 개별 증권명·종류·거래소 필드를 대조했다. 디렉터리 이후의 모든 기업행동이나 실시간 거래 가능성을 보장하지 않는다.

KIS 입력 연결은 같은 날 05:30:49 UTC에 받은 NAS·NYS·AMS 공개 마스터로 재확인했다. [선별 관측](evidence/issue-260/kis-identity-observations.json)은 원본 ZIP의 해시와 식별·유형 필드만 담는다. 24열 cp949 자료를 [기존 공식 고정 버전의 열 정의](https://github.com/koreainvestment/open-trading-api/blob/2077773a69a428daf63e148182511f068cc45de3/stocks_info/overseas_stock_code.py)와 대조했다. 공식 예제 코드는 실행하지 않았으며 TLS 검증을 유지한 익명 GET과 표준 ZIP 읽기만 사용했다.

KIS 마스터에는 별도 기준일이 없으므로 수신일을 자료 기준일로 바꾸지 않았다. 현재 공식 디렉터리·발행사 자료와 일치하는 증권 연결을 확인하는 데 사용했으며, 현재 KIS 인증 조회·순위 소속·데이터 기준 세션·거래 가능 여부의 검증은 아니다. 특히 `AMS/SPY`와 `AMS/VXX`는 KIS 입력 코드이며 각각의 외부 상장 시장인 NYSE Arca·Cboe와 구분한다.

## 자료 부족·충돌의 검증 범위

자료 부족으로 제외할 실제 표본과, 같은 증권에 적용되는 구체적인 유형 주장들이 해결되지 않은 채 모순되어 제외할 실제 표본은 확보하지 못했다. 기존 CLI는 종목 식별자만 받으며 출처나 조회 실패를 주입하지 않는다. 평가자가 일부 자료를 못 찾았다는 사실만으로 모델도 적격성을 입증할 수 없다고 단정할 수 없다.

KIS `01=주식`과 공식 보통주 표시는 [ADR 0005](adr/0005-official-security-type-sources.md)에 따라 그 자체로 모순이 아니다. BBD/BBDO의 같은 분류값은 권리 구분의 반례다. SPY·VXX의 과거 KIS 상품 정보와 마스터 차이는 [기존 관측](kis-security-identification.md)으로 보존하지만, 외부 공식 근거로 유형을 확인한 현재 두 종목을 미해결 충돌에 따른 `unknown` 정답으로 재분류하지 않는다.

현재 개인용 CLI의 범위에서는 이 두 종류를 실제 시장에서 찾아야만 평가를 시작하도록 하지 않는다. 자료 부족·미해결 충돌로 유형을 확정하지 못한 결과의 제외, 분석 범위 축소와 모든 유형 확인 실패의 분석 불충분은 통제된 HTTP·모델 응답을 사용하는 공개 CLI 경계에서 검증한다. 기존 `unknown`·개별 조회 실패·현재성 불확실 시나리오는 결과 처리의 회귀 검사이며 모델이 실제 자료의 모순을 스스로 인식한다는 증거는 아니다. 보통주·적격 ADR·제외 유형·증권 구분·후속 변경은 위 고정 표본의 실제 모델 평가로 확인한다.

운영이나 후속 평가에서 실제 자료 부족·미해결 충돌을 발견하면 허용 범위에서 입력·출처·확인 시점·실패 결과를 보존하고 회귀 사례로 추가한다. 실제 표본에 편입할 때는 모델 출력과 독립적으로 정답·근거를 확인하여 새 버전으로 고정한다. 진행 중인 평가의 실패를 없애기 위해 표본을 교체하지 않는다. 실제 사례는 현재 미확보이며 이를 모의 검사 통과나 실제 평가 성공으로 표시하지 않는다.

## 평가 절차와 근거 심사

1. 실행 전에 점검 목적에 필요한 작은 표본을 기존 사례에서 선택하고 선택한 입력·정답·근거와 입력 해시를 기록한다. 표본의 적용 가능성이 바뀌었다면 모델 실행 전에 독립 근거로 재확인하고 새 버전을 기록한다. 모델·구현 커밋·설정도 실행 기록에 고정한다. 이후 표본 변경은 새 평가 버전이며 진행 중인 회차의 실패 사례를 교체하지 않는다.
2. 기존 [평가 CLI 사용법](llm-security-probe.md#고정-표본을-같은-판단-경로로-평가하기)에 따라 `--evaluation-input`에는 `inputs/` 아래의 사례별 JSON 하나만 전달한다. `answers.json`, 이 문서, 조사 기록이나 근거 URL을 모델 프롬프트·추가 입력으로 보내지 않는다. CLI는 입력 JSON만 읽으며 정답 파일을 자동 탐색하지 않는다. 파일명은 요청 본문에 담지 않지만 실제 실행의 외부 HTTP 요청도 확인한다.
3. 02·03·04는 같은 회사의 별도 증권을 함께 입력한다. 나머지는 사례별로 실행한다. 선택한 사례의 실제 결과를 각각 기록한다. 자료 부족·충돌의 모의 회귀 검사를 실제 평가로 계산하지 않는다. 사례마다 기존 호출·시간 한도를 유지하며 전체 표본 3회 통과는 요구하지 않는다. 실제 KIS 순위에서 여러 종목을 처리하는 검증은 별도로 남긴다.
4. 각 실행의 입력 해시·소스 커밋·모델·설정, 시작·종료 시각, stdout·stderr·종료 코드, 실제 외부 요청과 근거 기록을 비밀 값 없이 보존한다. 실행 오류·잘못된 포함·근거 없는 유형 확정이 있으면 원인을 확인하고 남은 사례는 미수행으로 기록한다. 수정 후에는 영향받는 회귀 검사와 사례를 다시 확인하며 전체 3회 재시작은 요구하지 않는다.
5. 평가자는 각 원본 거래소·심볼과 제출한 근거 ID가 같은 증권에 연결되는지, 실제 열린 페이지·읽은 발췌문이 해당 종류·권리를 명시하는지 확인한다. 회사 단위 CIK·회사명·검색 요약·티커 접미사만으로 통과시키지 않는다. 모델 추출 발췌문은 원문 자체와 구분한다.
6. 자료 기준일·적용 범위·확인 시점을 구분하고 확인 가능한 최신 자료와 알려진 후속 변경을 검토한다. 모든 기업행동과 무변경의 전수 입증을 요구하지 않는다. 구체적인 모순을 확인하면 해소 근거를 요구하고, 포괄 분류와 구체 유형의 차이는 구분한다. 오래된 자료뿐이거나 적용 여부의 불확실성이 남으면 제외하며 날짜 없는 페이지는 다른 현재성 근거와 연결한다. 자료를 확인한 시각만으로 현재성을 인정하지 않는다.
7. ADR은 미국 상장 예탁증서와 기초 주식 종류를 각각 확인한다. BBD·BBDO는 같은 발행사라는 이유로 합치지 않고 보통주·우선주 권리를 바꿔 적용하지 않는다. BAC 예탁주식도 기초 우선주 권리로 제외한다.
8. 정답과 모델 근거가 같은 출처여도 허용한다. 출처 공유는 모델 출력과 독립적으로 정답을 확정했다는 조건을 대신하지 않는다. 최종 유형·포함 여부가 맞아도 다른 증권·과거 권리·해결되지 않은 반대 근거를 사용했으면 통과하지 않는다. 선택한 비적격 표본을 잘못 포함하거나 근거 없이 유형을 확정하면 해당 점검은 실패다. 적격 표본의 누락은 사유와 함께 개선 대상으로 기록한다. 원래 정답 목록의 포함·제외 기대값은 유지하며 누락을 정답에 맞춰 고치지 않는다.

## 보관·공개와 한계

공유 파일에는 입력 식별자, 평가자의 짧은 사실 요약·판단, 출처·시점과 파일 해시만 남긴다. 외부 페이지 전체·PDF·가격·보유 종목 표나 모델 응답은 커밋하지 않는다. Nasdaq의 [Symbol Lookup 안내](https://nasdaqtrader.com/trader.aspx?id=symbollookup)는 데이터 범주별 이용 범위를 구분하므로 한 범주의 허용 문구를 모든 외부 자료의 무제한 재배포 허가로 확대하지 않는다. 직접 수집한 원자료는 비동기화 임시 경로에 소유자 전용으로 보관하며 원문 전체의 공개·영구 보관 권한을 확보했다는 주장은 하지 않는다.

직접 익명 수집은 공개 KIS 마스터·Nasdaq 디렉터리·State Street·Bank of America·MIAX에서 성공했다. Apple FAQ와 Alphabet FAQ 및 SEC 세 문서의 직접 수집은 HTTP 403, Bradesco 세 페이지는 네트워크 오류였다. 웹 도구의 페이지 열람과 원문 전체 보관을 구분하며, SEC·Bradesco의 재검토 한계는 [조사 기록](security-evaluation-adr-warrant-research.md#출처-위치와-확인-한계)에 남겼다.
