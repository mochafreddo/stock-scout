# 종목 유형 판단의 실제 평가 재개 설계

[#250](https://github.com/mochafreddo/stock-scout/issues/250)의 2026-10-21 후속 설계 인터뷰 기록이다. Q12에서 설계와 문서·명세 반영 범위를 확정했으며 구현·실연동 착수를 뜻하지 않는다. 기존 판단 방식과 평가 기준은 [ADR 0007](adr/0007-llm-security-type-judgment.md)을 따른다.

## 확정한 범위

Q1에서 원인 진단·최소 수정, 실제 KIS 순위의 여러 종목 처리 확인, 독립 정답 고정 표본의 3회 평가까지 이번 작업에 포함하기로 합의했다. 진단과 수정만으로 완료하지 않는다.

진단, 최소 수정, 실제 평가 순서로 진행한다. 기존 근거 검사와 실행 한도 및 평가 통과 기준을 유지한다. 변경이 필요하면 관측한 근거를 확인한 뒤 별도로 결정한다. 실패한 평가도 기록하며 통과 기준을 충족하기 전에는 #250을 완료 처리하지 않는다. 다른 장전 데이터·일정·운영값의 미검증 조건은 유지한다.

## 진단 출력

Q2에서 기존 오류 코드와 종료 코드를 유지하면서 stderr JSON에 실패 단계·거부 조건·관련 항목 번호를 추가하기로 합의했다. 미열람 출처·필수 필드 누락·다른 증권의 근거 참조 등을 구분한다. 모델 응답 원문·인증 값·개인 경로는 출력하지 않는다. 시간 제한 실패에는 단계별 소요 시간과 호출 횟수를 남긴다.

## 평가 표본의 현재성

Q3에서 기존 표본의 상장 상태나 권리를 독립적으로 확인하지 못하면 평가 전에 같은 검증 목적을 충족하는 다른 표본으로 교체할 수 있도록 합의했다. 교체 이유와 독립 근거를 기록하고 필수 유형·반례를 모두 확보한 뒤 표본을 고정한다. 평가 도중 실패한 사례를 교체하지 않는다.

## 실제 실행과 평가 중단

Q4에서 원인 확인을 위한 실제 CLI 실행을 우선 최대 3회로 제한하기로 합의했다. 기존 실패 사례와 여러 종목 실행을 대상으로 매회 다른 가설을 확인한다. 근거 없이 같은 실행을 반복하지 않으며 3회 안에 원인을 좁히지 못하면 확인한 사실과 다음 선택을 보고한다. 이후 정식 평가 실행은 이 진단 횟수와 구분한다.

Q5에서 우선 기존 실패 기록이 있는 `gpt-6.1-sol`로 진단하고 평가하기로 합의했다. 모델 변경이 필요하면 근거를 검토해 별도 결정한다. 정식 평가는 확정한 모델·설정·구현으로 3회를 진행한다.

Q6에서 평가 중 실행 오류나 명백한 오분류를 발견하면 중단하고 원인 확인·수정으로 돌아가기로 합의했다. 실패 결과를 보존하고 남은 사례·회차는 미수행으로 표시한다. 수정 후에는 전체 3회를 처음부터 다시 시작하며 통과한 실행만 골라 합치지 않는다.

## 확인한 사실과 미확정 사항

기존 [실행 보고서](llm-security-probe.md#현재-검증-상태)는 실제 순위 및 고정 AAPL 실행의 `MODEL_OUTPUT`, 여러 종목 실행의 조회 시간 제한 도달과 전체 표본 3회 평가 미완료를 기록한다. 조회 근거 검증의 정확한 거부 조건과 여러 종목의 조회 부담이 발생한 세부 원인은 확정되지 않았다.

Q12에서 작업 범위·공개 검증 경계·리뷰 기준점을 확정했다. 공개 검증 경계는 CLI 인수·stdout·stderr·종료 코드와 외부 HTTP 요청이다. 리뷰 기준은 로컬 `41a4188e0413a95dc6757658c1e4d99a492f8859`와 각 이슈의 갱신 전 원문이다. 이번 반영은 문서·명세까지이며 구현·실연동·커밋·푸시·이슈 종료는 포함하지 않는다.

## 최종 확인 전 추가된 이용 조건

사용자는 현재 토스증권에서 소수점 거래로 매수·매도하며 조건부·전략적 주문을 예약할 수 없다고 설명했다. 이번 제품 범위는 한국 낮에 직전 완료 정규장의 종가 기준 데이터로 매수 후보 판단을 확인한 뒤 단순 소수점 매수를 직접 예약하는 흐름으로 한정한다. 이는 사용자가 제공한 이용 조건이며 토스증권의 주문 기능·체결 방식·대상 종목을 독립적으로 확인한 결과는 아니다.

사용자는 매도 판단에 필요한 토스증권 API 연동을 후속으로 미루고 현재는 매수 후보 판단만 고려하기로 정정했다. 이번 작업에는 매도·유지 판단, 보유 종목 입력·분석, 토스증권 API 연동을 추가하지 않는다. 기존 매수 후보 범위를 유지한다.

상위 #237 및 관련 이슈의 실행 가능 시간, 데이터 기준 세션과 판단 대상 세션, 소수점 거래 가능 여부 및 매수 보고서 계약을 Q8~Q11에서 재검토했다. 추가 이용 조건으로 Q7의 최종 확인을 보류했으며 Q12에서 Q1~Q6과 상위 설계를 함께 확정했다.

Q8~Q11에서 [한국 낮 매수 후보 설계](daytime-buy-candidate-design.md)의 실행 시간·완료 세션 데이터·소수점 거래 확인·보고서 범위에 합의했다. 이 설계는 #250의 증권 유형 검증을 토스증권 거래 가능 판정으로 확대하지 않는다. Q12의 최종 확인으로 열린 이슈 11개 본문에 함께 반영하도록 승인받았다.

## 후속 인터뷰: 고정 표본의 적격 종목 누락

후속 인터뷰 Q1에서 독립 근거로 적격성과 현재 적용 가능성을 확정한 고정 표본의 종목은 매회 모두 포함해야 평가를 통과하도록 합의했다. 매회 보통주 한 종목과 적격 ADR 한 종목을 포함하는 것만으로 통과하지 않는다. 적격 종목을 자료 부족 등의 사유로 제외해도 해당 평가는 실패로 기록한다. 자료 부족·충돌로 제외해야 하는 사례는 별도 평가 사례로 구분한다.

이 결정은 기존의 보통주·적격 ADR 실제 포함 조건을 강화하며 ADR 0007에도 반영했다. 실제 순위 실행에서는 기존의 보수적 개별 제외 정책을 유지한다. 이번 합의는 문서에 기록하며 원격 명세 갱신·구현·실연동 착수를 뜻하지 않는다.

## 후속 인터뷰: 독립 정답과 출처 공유

후속 인터뷰 Q2에서 독립 정답과 모델이 제출하는 근거에 같은 출처를 허용하기로 합의했다. 독립성은 출처가 서로 다르다는 뜻이 아니라 모델의 출력에 의존하지 않고 정답을 확정한다는 뜻이다. 정답과 판단 근거는 실행 전에 확정하며 모델에 제공하지 않는다. 모델은 직접 조회한 자료로 판단한다.

평가는 최종 포함·제외 결과뿐 아니라 모델이 제출한 근거가 해당 증권의 유형과 현재 적용 가능성을 뒷받침하는지도 확인한다. 정답과 출처가 같다는 사실만으로 근거의 타당성을 인정하지 않으며 기존의 증권 연결·반대 근거·ADR 기초 권리 확인 조건을 유지한다.

## 후속 인터뷰의 최종 확정

후속 인터뷰 Q3에서 Q1·Q2와 기존 진단·시간·호출 한도, 실패 시 중단·수정 후 전체 3회 재평가 조건을 함께 확정했다. 이번 작업은 이 설계 문서와 ADR 0007에 합의를 반영하는 범위이며 구현·실연동·원격 이슈 수정·커밋·푸시는 포함하지 않는다. 향후 구현의 공개 검증 경계는 CLI 입력·stdout·stderr·종료 코드와 외부 HTTP 요청이다. 이번 문서 검토 기준은 `41a4188e0413a95dc6757658c1e4d99a492f8859`와 후속 인터뷰 시작 당시 파일이다. 기존 미커밋 설계 변경은 이번 인터뷰의 추가 변경과 구분한다.
