# 공식 공지의 일정 영향 판단 설계

2026-10-28 #244의 설계 인터뷰 Q1~Q10에서 합의하고 후속 `$implement` 요청으로 구현하는 계약이다. [ADR 0013](adr/0013-llm-calendar-notice-assessment.md)은 선택의 이유를 기록한다. 이 문서는 설계 계약이며 실제 구현·모델 평가의 완료 증거는 [검증 기록](market-calendar-validation.md)과 구분한다.

## 자료와 판단 책임

[ADR 0012](adr/0012-bounded-official-calendar-notices.md)의 수집 범위를 유지한다. NYSE Market Status·Trader Updates는 각각 게시일 내림차순 첫 페이지의 부모 최대 100건과 포함된 자식 전체, Nasdaq은 현재 Equity RSS와 연결 기사 본문을 수집한다. 명시적인 비대상 시장은 공식 메타데이터로 제외한다. 나머지 대상 공지는 정규식의 단문 성공 경로를 거치지 않고 모두 같은 LLM 판단 경로에 넣는다. 목록 밖 공지·과거 부모의 새 변경·미수집 정정 누락 위험은 계속 미검증으로 표시한다.

모델에는 실제 수집한 본문 전체, 공지·본문 식별자, 출처·게시 시각·대상 시장 메타데이터를 제공한다. 부모·자식과 다른 공지의 정정 관계를 함께 보도록 전체를 한 요청에 전달한다. KIS·웹 검색·추가 링크 조회·명령 실행 도구를 제공하지 않으며 공지 속 명령은 신뢰하지 않는 자료로 다룬다. 모델 기억이나 링크의 미수집 내용을 근거로 확정하지 않는다.

본문은 코드가 문장 경계와 최대 240개 유니코드 코드 포인트를 기준으로 나눈 순서 있는 구간으로 전달한다. 모든 구간을 연결하면 입력 본문이 그대로 복원되며 요약·생략은 하지 않는다. 모델은 코드가 부여한 단일 구간 ID를 선택하고, 코드는 입력 소속과 자식별 근거 충족을 검사한 뒤 해당 본문 ID·원문 인용을 복원한다. 이는 모델이 문자열을 복사하며 공백을 바꾸거나 본문 ID와 인용을 다르게 조합하는 문제를 줄이는 기계적 처리다. 의미상 부적절한 유효 구간을 고르는 위험은 남는다.

구간 ID는 요청 안에서만 유효한 짧은 십진 문자열이며 본문·구간 순서대로 부여한다. 원래 본문 ID·공지 소속·원문은 별도 맵에 유지하므로 구간 ID에 긴 원래 식별자를 반복하지 않는다. 공개 결과는 계속 원래 본문 ID와 인용을 사용하며, 요청 사이에 구간 ID를 재사용하는 계약은 없다.

테스트 안내에 실제 운영 개시일이 함께 있으면 이를 놓치지 않고 판단한다. 실제 정규장 변경을 알리지 않는 테스트 전용 안내와 구분하며, 테스트라는 제목이나 단어만으로 모든 공지를 영향 없음 또는 판단 불가로 처리하지 않는다.

모델 판단은 일정 영향 없음, 일정 변경, 미래 적용, 판단 불가로 구분한다. 각 공지의 ID·출처·결과·짧은 이유·본문 근거를 출력하고 본문 전체는 기본 결과에 복사하지 않는다. 부모·자식의 내용이 빠지거나 공지 결과가 누락·중복되면 실패한다. 코드가 근거 ID와 발췌의 실제 입력 소속을 검사하지만 인용의 존재가 결론의 타당성을 입증하지는 않는다. 의미적 오판 위험은 승인된 운영 가정이며 자신감 점수만으로 통과시키지 않는다.

날짜·시간의 의미 추출과 원문 모순의 정정 여부는 LLM이 판단한다. 코드는 정규화된 ISO 날짜의 실재 여부·시간 범위·일정의 개폐장 순서와 근거 연결을 검사하며 모든 원문 표기를 다시 파싱하지 않는다. 따라서 정확한 인용을 붙인 잘못된 날짜·시간도 통과할 수 있고 이 위험은 독립 표본의 의미 검증 대상이다. `Oct. 26`이나 `1 p.m.`처럼 유효한 원문 표현을 고정 형식과 다르다는 이유만으로 거부하지 않는다. 연간 공식 일정 파서의 날짜·요일 일치 검사는 별도로 유지한다.

코드는 휴장·개장 지연·조기 폐장, 적용일과 시간을 확정한 정정·철회를 반영한다. 정정 이전과 이후를 서로 다른 추가 휴장으로 합치지 않는다. 입력에 없는 정정 참조·순환·상충·미해결 관계는 실패한다. 지원하지 않는 미래 정규장 범위 변경은 적용일과 근거를 남기며 필요한 세션이 적용일에 도달하면 실패한다. 본문 내용에서 일정 영향을 확정할 수 없는 공지는 전체 실패이고 일부 공지만으로 성공시키지 않는다.

정정 계보는 직접 참조뿐 아니라 간접적으로 대체한 조상까지 확인한다. 같은 원문을 서로 다르게 고친 결과가 둘 이상 남으면 실패하며, 나중 공지가 경쟁 결과를 모두 명시적으로 대체한 경우에만 해결된 계보로 처리한다. 거래소 비교는 내부 override 항목의 유무가 아니라 연간 일정과 변경을 합친 날짜별 실제 개폐장 시간을 기준으로 한다.

연간 일정 파싱·시간대 변환·세션 계산·정정 참조 검사·출력 형식·완료 판정·호출 제한은 코드가 담당한다. 모델 처리 후에도 출력 직전 시각으로 전체 일정을 다시 판정하며, 이전 대상 세션을 그대로 재사용하지 않는다. 현재 시각 실행의 장중은 `analysisEligible: false`인 정상 결과이고 일정 확인 실패는 빈 stdout·안전한 stderr·비정상 종료다. 후보군 CLI의 장중 거부와 구분한다. `--at`은 기존과 같이 시간대가 있는 고정 시각과 현재 확보 자료를 사용한다.

## 인증과 한도

기존 Stock Scout 전용 SIWC 인증을 재사용하고 모델명을 명시적으로 입력한다. 첫 실제 검증 후보는 `gpt-6-luna`다. 사용할 수 없으면 실패하며 다른 모델이나 유료 API로 자동 전환하지 않는다. 기존 보호된 인증 보관소 정책을 유지하고 인증 파일·토큰·계정 식별자를 공유 기록에 넣지 않는다. 모델 응답은 스트리밍·저장 비활성화를 사용하고 `response.completed`를 확인한다. JSON 파싱 성공이나 스트림 종료만으로 완료시키지 않는다.

Luna의 실제 전체 입력에서 근거 누락과 미래 공지 판단 불일치를 확인한 뒤, 사용자는 후속 검증 후보로 `gpt-6.1-sol`을 명시적으로 선택했다. 동일한 소스·프롬프트·한도로 표본 세 건과 전체 CLI를 검증하며 결과는 검증 기록에 남긴다. 모델명은 계속 실행 시 명시하고 자동 선택·대체하지 않는다.

| 항목 | 승인한 상한 |
| --- | --- |
| 모델 입력 | 지침·스키마·공지 데이터를 포함한 직렬화 입력 256KiB |
| 모델 요청 | 한 번, 자동 재시도·복구 호출 없음 |
| 전체 실행 | 인증을 포함해 최대 300초 |
| 공식 자료 수집 | 최대 120초, 개별 HTTP 최대 15초 |
| 모델 판단 | 전체 남은 시간 안에서 최대 180초 |

기존 수집의 요청 100회·응답당 2,000,000바이트·합계 16,000,000바이트·RSS 90건 상한도 유지한다. 한도 때문에 본문을 자르거나 요약·분할·일부 처리·캐시 재사용으로 성공시키지 않는다. 입력 초과·모델 실패·중단·출력 누락·판단 불가·시간 초과는 전체 실패다. 한도 안의 실행 가능성은 실측할 가정이며 실패 시 원인과 측정을 확인한 뒤 재결정한다.

## 수집량 실측

2026-10-28의 일회 수집에서 NYSE 두 채널은 각각 부모 100건과 자식 163·3건, Nasdaq RSS는 45건이었다. 명시적인 비대상 NYSE 시장을 제외한 대상은 NYSE 부모 묶음 41개와 Nasdaq 기사 45개, 자식을 포함한 본문 113개다. 추출 본문·메타데이터를 포함한 압축 JSON은 101,126바이트이고 가장 큰 묶음은 5,681바이트였다. 지침·스키마·최종 요청 형식은 이 측정에 포함하지 않았다. 현재 코드로 얻을 입력 크기나 모델 토큰 수를 측정한 결과가 아니다.

제한된 공개 수집 도구에서는 Nasdaq 25건이 기사 대신 212바이트의 빈 본문·스크립트 응답을 반환했다. 대표 한 건을 실제 CLI와 같은 Node.js·User-Agent·15초 제한으로 조회해 본문을 확보한 뒤 나머지 24건도 같은 설정으로 수집했다. 이미 성공한 자료와 대표 응답은 재사용했고 전 기사의 본문 컨테이너·표 셀 구조를 검사했다. 클라이언트와 요청 설정을 동시에 바꿨으므로 어느 차이가 원인인지는 분리하지 못했다. 이를 실제 CLI의 지속적인 통신 결함이나 공급자 차단 정책으로 단정하지 않는다. 원문과 비밀 없는 측정 증거는 저장소 밖의 비공개 임시 보관소에 남겼다.

## 검증과 완료 조건

공개 검증 경계는 CLI 인수·stdout·stderr·종료 코드와 외부 HTTP·모델 응답이다. 소스 파서·AI SDK는 실제로 실행하고 외부 HTTP와 시각을 통제한다. 실제 정상 결과는 성공 JSON 하나와 종료 코드 0, 실패는 빈 stdout과 안전한 stderr·종료 코드 1로 검사한다. 모델 요청 인수·본문·도구 부재·한 번의 요청·완료 이벤트·비밀 출력 방지도 이 경계에서 검사한다.

기존 개폐장·서머타임·주말·휴장·조기 폐장·인접 연도·공통 세션·출력 직전 시각 검사를 유지한다. 공지별 누락·중복·잘못된 근거·미해결 정정·모호함·초과·모델 중단을 회귀 검사하며 위험한 로직에는 정상 기준과 공용 소스 변이 도구의 음성 대조를 함께 남긴다. 새 계약이 대체하는 정규식 지원 형식 기대값은 변경 근거를 기록한다. 문서의 특정 문구나 내부 함수 배치를 검사하지 않는다.

첫 실제 인수는 공식 자료를 수집한 전체 CLI의 정상 JSON과, 실행 전에 모델 출력과 독립적으로 정답을 확정한 작은 실제 공지 표본의 판단·근거 평가를 함께 요구한다. 표본은 기술·시세 장애, 미래 거래시간 변경, 휴장을 포함하고 각 표본을 한 번씩 평가한다. 모두 판단 불가인 결과는 통과가 아니다. 개장 지연·조기 폐장·정정·철회·모호함은 통제된 입력의 회귀 검사와 음성 대조로 확인하며 실제 모델의 의미 판단 검증과 구분한다. 실패 입력과 결과를 보존하고 수정 없는 반복 호출로 성공만 선택하지 않는다.

#244의 완료는 KIS 데이터 준비·후보군 연결·유형 판단·매수 추천 제품 인수의 완료가 아니다. Actions는 비활성 상태를 유지한다. 이번 `$implement`는 로컬 구현·검증·코드 리뷰·커밋 범위이며 푸시·원격 이슈 수정·종료는 수행하지 않는다.
