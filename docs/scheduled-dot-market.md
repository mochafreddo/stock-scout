# 21시 예약 Dot 시장 조회 운영

기존 21:00 KST 예약 Dot에 시장 조회를 제공하려면 Mac의 사용자 LaunchAgent가 선택형 MCP 어댑터를 시작합니다. Dot은 OpenAI Secure MCP Tunnel을 통해 Mac의 루프백 서버에 연결하고, 같은 회차에 받은 결과를 보고 다음 조회를 선택해 보고서를 작성합니다. 직접 CLI를 사용하는 경우 이 설정은 필요 없습니다. [연결 방식과 운영 범위](adr/0024-private-mcp-for-scheduled-dot.md)

## Mac 설정과 예약 전 확인

1. **설치, 키 사용, 작업 등록, 토스 실조회, 예약 Dot에 실제 자료 전달**은 각각 승인된 범위 안에서 진행하세요. 기존 승인이 해당 작업을 포괄하지 않으면 수행 전에 별도 승인을 받으세요. 이번 보고서의 범위는 시장 자료입니다. 계좌·보유·주문 접근과 금융 원문 보관은 제외합니다. [실제 조회 접근 조건](toss-access-readiness.md)
2. Mac에서 승인받은 기존 CLI 실행기와 비공개 터널 구성을 확인하세요. 터널 래퍼는 유일한 인수로 받은 `http://127.0.0.1:<port>/mcp`를 기존 터널의 로컬 대상으로 지정하고, `exec`으로 터널 클라이언트를 포그라운드에서 실행해야 합니다. 서버는 실제 로컬 포트에 해당하는 `Host`를 요구합니다. `Origin`을 전달한다면 같은 로컬 origin을 사용하세요. 터널 키·설정은 Mac의 승인된 위치에서만 사용하세요.
3. Mac 전용 시작 래퍼에서 아래 순서대로 실행하세요. 예약 실행기에는 Node.js 24.2 이상이 필요합니다. 직접 조회 CLI는 Node.js 24 이상에서 실행할 수 있습니다. 꺾쇠 부분은 해당 Mac의 값으로 바꾸고 각 실행 파일의 절대 경로를 사용하세요. CLI 실행기는 `readiness`와 시장 조회 인수를 모두 받아 기존 CLI의 JSON과 종료 코드를 전달해야 합니다.

   ```sh
   #!/bin/sh
   exec "<Node 절대 경로>" "<저장소 절대 경로>/scripts/run-dot-mcp.ts" \
     "<승인 CLI 실행기 절대 경로>" "<터널 래퍼 절대 경로>" \
     "<회차 상태 디렉터리 절대 경로>" "<루프백 포트>"
   ```

4. 회차 상태 디렉터리는 재부팅 후에도 유지되는 사용자 전용 위치에 두세요. 실행기는 이 디렉터리가 실제 디렉터리인지, 실행 사용자 소유인지, 그룹과 다른 사용자에게 권한이 없는지 검사합니다. 실패하면 `SESSION_STORAGE_UNSAFE`로 중단합니다. 검사를 통과하면 터널을 열기 전에 KST 날짜별 디렉터리를 만듭니다. 같은 날짜가 이미 있으면 `SESSION_CLAIMED`로 건너뜁니다. 터널 시작 실패나 비정상 종료 후에도 해당 항목을 보존하고 다음 회차를 기다리세요. 운영 시간 중 실행기를 시험 삼아 시작해도 그날 회차를 차지합니다.
5. 등록 전에 로그인 사용자 계정으로 로그 디렉터리와 파일 두 개를 준비하세요. 아래 명령은 기존 로그 내용을 보존합니다. 사용자 소유의 실제 디렉터리와 일반 파일을 사용하고, `ls -ld` 결과에서 소유자가 현재 사용자이고 권한이 디렉터리 `700`, 파일 `600`인지 확인하세요.

   ```sh
   (
     set -e
     umask 077
     log_dir="$HOME/Library/Logs/stock-scout-dot"
     mkdir -p "$log_dir"
     chmod 700 "$log_dir"
     touch "$log_dir/stdout.log" "$log_dir/stderr.log"
     chmod 600 "$log_dir/stdout.log" "$log_dir/stderr.log"
     ls -ld "$log_dir" "$log_dir/stdout.log" "$log_dir/stderr.log"
   )
   ```

6. [LaunchAgent 예시](../examples/stock-scout-dot.launchagent.plist)를 사용자의 `~/Library/LaunchAgents/`에 복사하고 `ProgramArguments`를 시작 래퍼의 절대 경로로 바꾸세요. 사본의 `StandardOutPath`와 `StandardErrorPath`에는 위에서 준비한 `stdout.log`와 `stderr.log`의 절대 경로를 각각 입력하세요. plist에 `~`나 `$HOME`을 그대로 쓰면 경로가 확장되지 않습니다. 예시는 Mac **현지 시각 20:55**에 실행되므로 Mac 시간대가 `Asia/Seoul`인지 확인하세요. 등록 전에 래퍼의 실행 권한을 확인하고, 사본의 절대 경로를 셸 변수 `plist`에 지정한 뒤 `plutil -lint "$plist"`로 검사하세요. 승인된 실행기의 `readiness`는 공급자 호출 없이 로컬 차단 사유를 점검합니다. JSON의 `data[0].readiness`가 `ready`이고 종료 코드가 0인지 확인하세요.
7. 등록 승인 후 로그인한 사용자 세션에서 `launchctl bootstrap "gui/$(id -u)" "$plist"`로 등록하세요. `launchctl print "gui/$(id -u)/local.stock-scout.dot"`로 예시 레이블의 등록을 확인하세요. 등록 정보는 예약 실행의 증거와 다릅니다. 기존 21:00 KST Dot 예약이 승인된 비공개 연결을 사용하도록 확인하세요.

첫 시작이 실패하면 두 로그를 확인하세요. 예를 들어 터널을 시작하지 못하면 표준 출력에 `session`(KST 회차 날짜), `time`(UTC 시각), `status=error`, `code=TUNNEL_START_FAILED`가 남습니다. 실행기가 예기치 않은 시작 예외를 처리하면 표준 오류에 `time`, `status=error`, `code=START_FAILED`가 남습니다. 시작 래퍼도 이 범위의 메타데이터만 기록하도록 하세요. 셸 실행 추적이나 조회 인수·금융 응답·터널 설정 덤프는 꺼 두세요.

## 조회와 종료

새 시장 조회는 KST 20:55 이상 21:20 미만에 한 번에 한 건씩 시작합니다. 어댑터는 대기 순서가 돌아오면 회차 시간과 예산을 확인하고 승인 실행기로 로컬 조회 준비 점검을 수행한 뒤, 시장 조회를 시작하기 직전에 한도를 다시 확인합니다. 준비 점검은 예산에서 제외하며, 실제로 시작한 실패·부분 결과·후속 페이지를 포함해 회차당 최대 16건입니다. 공급자 대기와 재시도는 기존 CLI가 처리합니다.

준비 점검과 시장 조회는 각각 시작 후 70초에 종료 신호를 받습니다. 시간 초과는 해당 단계의 `CLI_RESULT_UNAVAILABLE`로 처리합니다. 이후 5초 안에 실행기와 출력 파이프가 닫히면 후속 요청은 기존 시작 조건을 다시 확인합니다. 75초까지 정리되지 않으면 실행기를 강제 종료하고 새 조회를 차단한 채 회차를 닫습니다.

| 도구 | Dot이 확인할 내용 |
| --- | --- |
| `rankings` | 미국 시장 순위의 집계 기준과 반환 종목을 확인하고 후속 조회 대상을 선택합니다. |
| `stock` | 심볼이 겹치면 상장 시장과 확인 가능한 ISIN으로 종목을 구별합니다. |
| `candles` | 일봉 한 페이지의 실제 거래일 범위와 누락을 확인합니다. 다음 페이지가 필요하면 같은 종목·수량·조정 조건에서 `page.nextBefore`를 그대로 `before`에 넣고 `date`는 생략합니다. |
| `prices` | 심볼별 가격의 소수 문자열과 통화를 보존합니다. 같은 심볼에 여러 상장 종목이 있다면 가격을 특정 상장 종목에 귀속할 별도 근거가 필요합니다. |
| `sessions` | 조회 시각의 뉴욕 현지 날짜에 반환된 `today.regularMarket.startTime`과 조회 시각을 비교해 정규장 개장 전인지 판단합니다. 개장 시각이 없으면 판단을 보류합니다. |

인수는 `tools/list`의 구조화된 스키마를 따릅니다. 21:20 KST부터는 이미 대기 중이거나 준비 점검을 통과한 요청도 새 시장 조회를 시작할 수 없습니다. 실행기는 별도로 1초 간격으로 마감을 확인합니다. 마감을 감지해 종료 절차를 시작할 때 서버가 새 연결을 차단합니다. 마감 전 시작한 조회의 응답 처리가 끝나면 터널 종료를 시작합니다. 종료 시작 75초에 남은 연결을 닫고 실행기와 터널에 종료 신호를 보냅니다. 필요하면 80초에 강제 종료합니다. 실행기가 종료를 요청하기 전에 터널이 먼저 끝나면 `TUNNEL_EXIT`를 기록하고 종료 코드 1을 반환합니다. 회차 점유는 보존합니다. Mac이 마감 후 깨어나면 그 회차는 건너뜁니다. 예약을 중지하려면 실행 중인 회차의 종료를 확인한 뒤 `launchctl bootout "gui/$(id -u)" "$plist"`로 등록을 해제하고, 다음 로그인 때도 중지하려면 해당 사본을 LaunchAgents 밖으로 옮기세요.

## 보고서에서 결과 구분하기

| 이번 회차의 관측 | 보고 방법 |
| --- | --- |
| `stage=admission` 또는 `stage=readiness`에서 차단 | 마감·예산 또는 준비 점검 사유와 함께 해당 시장 조회가 시작되지 않았음을 표시합니다. |
| `stage=readiness`에서 `WAIT_REQUIRED` | 직전 조회 직후처럼 공유 대기 시간이 남아 있으면 ‘대기 중으로 시장 조회 미시작’으로 보고합니다. 어댑터는 이 호출을 자동 재시도하지 않습니다. 대기가 끝난 뒤 별도로 요청하면 다시 준비 점검을 거쳐 조회할 수 있습니다. |
| `stage=query`, `error`, 종료 코드 1 | 실제 조회 오류로 표시하고 응답의 안전한 오류 코드를 사용합니다. |
| `stage=query`, `partial`, 종료 코드 2 | 받은 자료, 누락, 남은 페이지를 구분합니다. 회차 전체에서 일부 조회만 성공한 경우에도 확보한 범위만 설명합니다. |
| `CLI_RESULT_UNAVAILABLE` 또는 Dot에 응답이 도달했는지 확인 불가 | 결과 확인 불가로 표시합니다. 준비 점검 단계에서 멈췄다면 시장 조회 미시작도 함께 표시합니다. 관측하지 못한 결과를 빈 목록이나 공급자 실패로 단정하지 마세요. |

같은 회차에서 `success`와 종료 코드 0으로 확인한 빈 목록은 조회 범위 안의 빈 결과로 보고하세요. 가격에는 CLI 조회 시각(`retrievedAt`)과 공급자 가격 시각(`timestamp`)을 구분해 표시하세요. 공급자 시각이 누락되거나 null이면 그 상태를 보존하고 시점 미확인 가격으로 표시하세요. 보고서 기준 시각과 실제 자료 범위, 판단을 보류한 부분을 명시하고 지난 회차의 가격이나 일봉으로 공백을 채우지 마세요. [가격 시점 판정 지침](toss-agent-usage.md#classify-prices-at-report-time)

## 검증 상태와 실제 인수

리비전 `8e32398`에서 Dot MCP 합성 검사 18건이 통과했습니다. 공개 MCP 요청에서 CLI 인수·JSON·종료 코드까지, 순위에 따른 일봉 후속 조회, 마감·예산과 회차 재시작 차단을 검사했습니다. 종료는 로컬 서버의 응답과 모의 터널 프로세스까지 확인했습니다. 초기 시범에서 합성 순위에 따른 후속 조회와 실제 시세 한 건 수신은 서로 다른 예약 회차에서 관측했습니다. [검증 경계와 시범 기록](adr/0024-private-mcp-for-scheduled-dot.md)

[운영 인수 기록 #360](https://github.com/mochafreddo/stock-scout/issues/360)에는 다음 두 관측이 남아 있습니다.

- **2026년 11월 24일, 실제 터널의 마감 동작.** 제어된 시각에서 마감 전에 시작한 조회의 합성 응답이 실제 비공개 터널을 통해 전달됐습니다. 대기 중인 요청은 차단됐고 터널은 종료됐습니다.
- **2026년 11월 25일, 실제 예약 보고서.** Mac 사용자 LaunchAgent가 연 비공개 연결에서 21:00 KST 예약 Dot이 미국 시장 순위를 조회하고, 그 결과로 종목을 선택해 같은 회차에서 가격을 조회했습니다. 두 조회 모두 성공했고 누락은 없었습니다. Dot은 공급자 가격 시각과 CLI 조회 시각을 구분하고 거래 세션을 미확인으로 표시해 보고서를 완성했습니다.

준비 점검 차단·조회 오류·부분 결과·결과 확인 불가의 구분은 합성 검사에서 확인했습니다. **실행기가 비정상 종료한 뒤 실제 터널 프로세스도 종료되는지는 미확인입니다.** 운영 로그에는 회차·시각·상태·오류 코드만 남기세요. 조회 인수, 금융 응답 원문, 키나 터널 설정을 기록하지 마세요.
