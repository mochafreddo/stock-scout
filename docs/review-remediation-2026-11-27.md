# 공유 대기 후 조회와 로컬 검사 후속 결정

2026-11-27에 Q1~Q7의 설계와 Q8의 변경 범위·공개 검증 경계를 확정했다. 기준 커밋은 원격 `main`의 [`cc5b5e4`](https://github.com/mochafreddo/stock-scout/commit/cc5b5e46ec4e11f8fa1b0d0914d8e24943cb11ab)다. Astra 교차검토에서 확인한 보완을 포함한다.

## 변경 범위와 공개 검증 경계

| 결정 | 반영 방향 | 검증 |
| --- | --- | --- |
| Q1 공유 대기 후 토큰 확인 | 공유 대기가 끝나면 잠금 안에서 슬롯을 예약하기 직전에 선택한 토큰이 현재 토큰과 같고 만료 전인지 확인한다. 예약 저장의 마지막 동기 I/O 뒤 실제 GET 직전에도 만료 여부를 확인한다. 확인에 실패하면 잠금 밖에서 기존 발급 경로를 통해 논리적 조회당 한 번 재선택하고, 다른 프로세스가 갱신한 유효 토큰을 우선 사용한다. 최초 캐시 재사용의 15초 여유와 기존 `401 expired-token` 복구 및 일시 오류 재시도를 유지한다. | 실제 CLI와 합성 HTTP·시계에서 대기 중 만료, 예약 저장 중 만료, 다른 프로세스의 갱신, 수명이 짧은 새 토큰을 대조한다. 미전송 GET, 실제 POST·GET 순서와 횟수, 오류 코드·종료 상태를 확인한다. |
| Q2 Git 훅 실행 권한 | 설치기가 기존 기본 훅과 `pre-push.local`에 대해 일반 파일인지와 현재 사용자의 실행 권한을 확인한다. 새 훅도 목적지에 놓기 전에 임시 파일의 실행 권한을 확인한다. 기존 파일의 권한은 설치기가 자동으로 변경하지 않는다. | 임시 Git 저장소에서 `0655`인 사용자 소유 훅의 거부와 보존, `0700` 훅의 실제 Git 실행, 실행 비트를 제거하는 `umask`에서 설치 실패와 목적지 미생성을 대조한다. |
| Q3 예약 Dot 응답의 요청 일치 | 순위의 국가와 집계 범위를 기존 CLI 요청 정의에 대조한다. 종목 선택지는 `stock`과 날짜 지정 `candles`에서만 허용한다. 날짜 지정 일봉은 모든 선택지의 심볼을 대조하고, `stock`은 지정한 시장과 ISIN도 대조한다. 불일치나 준비 점검에서 받은 선택지는 `CLI_RESULT_UNAVAILABLE`로 처리한다. 선택지 없이 출처를 가린 정상 오류는 전달한다. | 루프백 MCP에서 순위 국가와 집계 범위를 각각 틀리게 한 응답, 다른 심볼의 일봉 선택지, 준비 점검의 선택지를 거부하는지 확인한다. 정상 응답·선택지와 가려진 정상 오류를 대조한다. |
| Q4 인라인 링크의 괄호 제목 | 참조 링크에 쓰는 괄호 제목 규칙을 인라인 링크 검사에 재사용한다. | `--docs`·staged·push에서 정상과 누락 대상, 목적지 자체의 괄호, 같은 줄에 이어지는 링크를 대조한다. |
| Q5 강조가 들어간 제목 앵커 | ATX와 Setext의 공통 앵커 생성에서 실제 강조 표식을 제거한 뒤 중복 번호를 계산한다. 식별자, 이스케이프, 코드 스팬의 리터럴 밑줄은 보존한다. | `--docs`·staged·push에서 렌더링된 제목의 앵커와 중복 접미사, 리터럴 밑줄, 잘못된 앵커를 대조한다. |
| Q6 반복 종료 신호 | 기준 실행기에서 정리 도중 같은 신호를 다시 받아 정리가 중단되는 동작을 재현하면 수정한다. 종료 절차가 끝날 때까지 신호를 기존 `stop()`으로 전달한다. 반복 신호로 종료 시한을 연장하지 않는다. | 합성 터널과 실행기를 붙인 실제 진입점에서 첫 신호가 처리된 것을 관측한 뒤 같은 신호를 보낸다. 응답 전달, 관리 중인 자식·터널 정리와 종료 기록 한 건을 확인한다. |
| Q7 기본 계좌 선택 | 적용할 별칭과 조회 범위를 담은 성공 응답을 직렬화하고 가림 검사를 통과한 뒤 계좌를 저장한다. 저장 성공 후 검사한 응답을 출력한다. [ADR 0020](adr/0020-account-selection-commit-result.md)을 따른다. | 실제 CLI에서 가림 실패 시 기존 파일 바이트 보존, 정상 저장 후 마감 경과, 저장 실패와 HTTP 0건을 대조한다. |

Q1에서 로컬 재선택 후에도 전송 가능한 토큰을 확보하지 못하면 `AUTH_TOKEN_UNAVAILABLE`로 종료하고 일봉 묶음의 후속 조회를 중단한다. 보내지 않은 GET은 전송 횟수에 넣지 않는다. 실행 시간·전송 상한이나 발급 실패가 먼저 발생하면 해당 기존 오류를 반환한다. 최초 발급, 로컬 재발급, 공급자 만료 응답 뒤 재발급이 모두 발생하면 `prices` 한 번에 최대 6회(POST 3회와 GET 3회) 전송할 수 있다. 이 조합을 합성 HTTP로 확인한다. 단일 실행 60초·10회, 일봉 묶음 120초·40회 예산과 공유 최소 전송 간격은 유지한다.

Q8에서 위 범위의 코드·회귀 검사·관련 문서를 확정했다. 기준 커밋부터 설계 기록과 후속 변경을 함께 검토한다. 각 회귀는 수정 전 실패와 수정 후 통과를 같은 공개 경계에서 대조한다. 최종 변경분에서 전체 합성 테스트, 린트, 타입, 문서 검사를 실행한다. 실제 토스·계좌·터널·예약 Dot 운영은 별도 범위다.

## 토큰 수명과 조회 결과 검사 후속 결정

2026-11-27 전체 코드베이스 검토에서 확인한 여섯 항목의 설계와 변경 범위를 합의했다. 이 절의 Q1~Q6은 이번 검토의 결정 번호다. 로컬 HEAD와 원격 `main`이 일치한 [`72e918e`](https://github.com/mochafreddo/stock-scout/commit/72e918e65fc37b72a2c043f26a696feba9418a8a)를 리뷰 기준으로 삼는다. 설계와 최종 검증 범위를 독립 Codex 검토자 `gpt-6.2-astra` `high`로 교차검토했다.

| 결정 | 반영 방향 | 공개 검증 경계 |
| --- | --- | --- |
| Q1 보호 상태 권한 | 상속한 `umask`를 적용한다. 새 잠금은 사용 전에 `0700`, 임시 보호 파일은 원자 교체 전 열린 파일 설명자로 `0600`인지 확인한다. 실패 시 이번 실행이 만든 항목을 정리하고 `AUTH_STORAGE`를 반환한다. 기존 선택은 보존하고 요청 예약을 게시할 수 없으면 HTTP를 시작하지 않는다. | 기존 CLI에서 새 잠금과 임시 파일의 권한 실패를 각각 유발한다. 오류 코드, HTTP 0건, 이전 계좌 선택 파일의 바이트, 잠금 정리와 이후 정상 호출 성공을 확인한다. |
| Q2 토큰 만료 | 실제 토큰 POST 시작을 기준으로 계산한 벽시계 만료와 공유 단조 시계 만료를 토큰과 함께 저장하고 먼저 도달한 만료를 적용한다. 준비 점검, 최초 캐시 재사용의 15초 여유, 재선택, 예약 전과 예약 저장 후 GET 직전 확인에 같은 만료 기준을 쓴다. 기존 v2의 단조 만료 누락은 일반 조회가 기존 잠금·예산 안에서 갱신한다. 아직 벽시계상 유효하면 준비 점검은 `refresh_required`로 표시한다. 필드가 있으나 손상된 상태는 `AUTH_STORAGE`로 처리한다. 승인된 시계 기준 변경은 같은 원자 저장에서 이전 단조 만료를 제거하고 토큰 값·벽시계 만료·`pending`을 보존한다. | 실제 CLI와 합성 HTTP·시계로 벽시계 보정, 예약 저장 중 만료, 다른 프로세스의 갱신을 대조한다. 만료 토큰 GET 0건과 교체 토큰 GET을 확인한다. 기존 v2의 단조 만료 누락과 손상, 부팅 기준 불일치, 발급 결과 미확인 상태를 대조하고 차단된 경우 HTTP 0건을 확인한다. |
| Q3 예약 일봉 응답 | 성공·부분 결과에는 `page` 객체를 요구한다. `nextBefore=null`은 마지막 페이지이며 다른 누락으로 부분 결과가 될 수 있다. 유효한 다음 경계는 요청 상한 이하여야 하며 `next_page`인 부분 결과에 대응한다. 경계 필드 생략은 `pagination_unknown`인 부분 결과에 대응한다. 날짜 지정 결과는 CLI가 확인한 미국 시장을 요구한다. 잘못된 응답은 `CLI_RESULT_UNAVAILABLE`로 처리하고 출처가 가려진 정상 오류는 전달한다. | 실제 CLI의 합성 출력을 루프백 MCP에 전달한다. 마지막 페이지, 다음 페이지, 페이지 정보 미확인, 가려진 오류와 필수 페이지·시장 필드를 각각 뺀 응답을 대조한다. 상태와 종료 코드도 확인한다. |
| Q4 일봉 소비 예제 | 분석 전에 묶음의 각 행이 `success`, `partial`, `error`, `not_queried` 중 하나인지와 행 상태의 집계가 최상위 상태와 일치하는지 확인한다. 정상 빈 페이지와 데이터 없이 반환된 초기 오류는 기존대로 처리한다. | 실제 CLI의 합성 stdout을 예제에 전달한다. 행 상태 누락·잘못된 값·최상위 상태 불일치를 오류로 처리하고 정상 빈 페이지와 초기 오류를 처리하는지 확인한다. |
| Q5 Markdown 링크 | 공통 링크 인식에서 한 문단의 여러 줄 작은따옴표·큰따옴표 제목을 지원하고 여는 대괄호가 이스케이프된 일반 텍스트를 건너뛴다. | 같은 합성 문서로 `--docs`·staged·pre-push의 정상·깨진 링크, 여러 줄 제목, 이스케이프, 인접 링크와 제목 앵커를 대조한다. |
| Q6 반복 신호 테스트 | 종료를 확인하는 GET에서만 `EPIPE`를 `ECONNRESET`처럼 기존 시한 안에서 재시도하고, `ECONNREFUSED`에서 새 연결 차단을 확인한다. 원래 POST와 두 번째 신호·자식·터널 종료 단언을 유지한다. 첫 실행에서 `EPIPE`가 발생한 요청은 당시 로그로 특정할 수 없다. | 관측 GET에 `EPIPE`를 주입해 재시도를 확인하고, 원래 POST의 실패는 테스트 실패로 이어지는지 대조한다. 정상 경로에서 두 번째 신호 이후 응답 전달, 자식·터널 정리와 종료 기록을 확인한다. |

Q2의 만료 기준은 변경된 CLI끼리 같은 부팅·시계 기준을 공유하는 경우에 적용한다. 시계 기준 불일치는 기존 `CLOCK_UNCERTAIN` 정책을 따른다. Linux에서 단조 시계가 절전 시간을 세지 않는 동안 벽시계 후퇴까지 겹치면 두 시계가 모두 실제 경과를 놓칠 수 있다. 기존 발급 결과 미확인 처리, 상태 크기·요청 예산·재시도 한도를 유지한다. [CLI 시계와 복구 계약](toss-cli.md#예약-상태와-복구)

Q7에서 위 여섯 항목의 코드·회귀 검사·관련 문서 범위와 공개 검증 경계, 리뷰 기준을 승인했다. Q6의 변경 범위는 테스트다. 수정 전 실패와 수정 후 통과를 각 공개 경계에서 대조하고, 고정한 최종 변경분에서 기준 커밋부터의 Standards·Spec 리뷰와 전체 합성 테스트, 타입·린트·문서 검사를 수행한다. 실제 토스·계좌·터널·예약 Dot 인수는 별도 운영 범위다.
