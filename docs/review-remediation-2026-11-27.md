# 공유 대기 후 조회와 로컬 검사 후속 결정

2026-11-27에 Q1~Q7의 설계와 Q8의 변경 범위·공개 검증 경계를 확정했다. 기준 커밋은 원격 `main`의 [`cc5b5e4`](https://github.com/mochafreddo/stock-scout/commit/cc5b5e46ec4e11f8fa1b0d0914d8e24943cb11ab)다. Astra 교차검토에서 확인한 보완을 포함한다.

| Q6 반복 종료 신호 | 기준 실행기에서 정리 도중 같은 신호를 다시 받아 정리가 중단되는 동작을 재현하면 수정한다. 종료 절차가 끝날 때까지 신호를 기존 `stop()`으로 전달한다. 반복 신호로 종료 시한을 연장하지 않는다. | 합성 터널과 실행기를 붙인 실제 진입점에서 첫 신호가 처리된 것을 관측한 뒤 같은 신호를 보낸다. 응답 전달, 관리 중인 자식·터널 정리와 종료 기록 한 건을 확인한다. |
| Q7 기본 계좌 선택 | 적용할 별칭과 조회 범위를 담은 성공 응답을 직렬화하고 가림 검사를 통과한 뒤 계좌를 저장한다. 저장 성공 후 검사한 응답을 출력한다. [ADR 0020](adr/0020-account-selection-commit-result.md)을 따른다. | 실제 CLI에서 가림 실패 시 기존 파일 바이트 보존, 정상 저장 후 마감 경과, 저장 실패와 HTTP 0건을 대조한다. |

Q1에서 로컬 재선택 후에도 전송 가능한 토큰을 확보하지 못하면 `AUTH_TOKEN_UNAVAILABLE`로 종료하고 일봉 묶음의 후속 조회를 중단한다. 보내지 않은 GET은 전송 횟수에 넣지 않는다. 실행 시간·전송 상한이나 발급 실패가 먼저 발생하면 해당 기존 오류를 반환한다. 최초 발급, 로컬 재발급, 공급자 만료 응답 뒤 재발급이 모두 발생하면 `prices` 한 번에 최대 6회(POST 3회와 GET 3회) 전송할 수 있다. 이 조합을 합성 HTTP로 확인한다. 단일 실행 60초·10회, 일봉 묶음 120초·40회 예산과 공유 최소 전송 간격은 유지한다.

Q8에서 위 범위의 코드·회귀 검사·관련 문서를 확정했다. 기준 커밋부터 설계 기록과 후속 변경을 함께 검토한다. 각 회귀는 수정 전 실패와 수정 후 통과를 같은 공개 경계에서 대조한다. 최종 변경분에서 전체 합성 테스트, 린트, 타입, 문서 검사를 실행한다. 실제 토스·계좌·터널·예약 Dot 운영은 별도 범위다.

## 토큰 수명과 조회 결과 검사 후속 결정

2026-11-27 전체 코드베이스 검토에서 확인한 여섯 항목의 설계와 변경 범위를 합의했다. 이 절의 Q1~Q6은 이번 검토의 결정 번호다. 로컬 HEAD와 원격 `main`이 일치한 [`72e918e`](https://github.com/mochafreddo/stock-scout/commit/72e918e65fc37b72a2c043f26a696feba9418a8a)를 리뷰 기준으로 삼는다. 설계와 최종 검증 범위를 독립 Codex 검토자 `gpt-6.2-astra` `high`로 교차검토했다.

| --- | --- | --- |
| Q1 보호 상태 권한 | 상속한 `umask`를 적용한다. 새 잠금은 사용 전에 `0700`, 임시 보호 파일은 원자 교체 전 열린 파일 설명자로 `0600`인지 확인한다. 실패 시 이번 실행이 만든 항목을 정리하고 `AUTH_STORAGE`를 반환한다. 기존 선택은 보존하고 요청 예약을 게시할 수 없으면 HTTP를 시작하지 않는다. | 기존 CLI에서 새 잠금과 임시 파일의 권한 실패를 각각 유발한다. 오류 코드, HTTP 0건, 이전 계좌 선택 파일의 바이트, 잠금 정리와 이후 정상 호출 성공을 확인한다. |

| Q5 Markdown 링크 | 공통 링크 인식에서 한 문단의 여러 줄 작은따옴표·큰따옴표 제목을 지원하고 여는 대괄호가 이스케이프된 일반 텍스트를 건너뛴다. | 같은 합성 문서로 `--docs`·staged·pre-push의 정상·깨진 링크, 여러 줄 제목, 이스케이프, 인접 링크와 제목 앵커를 대조한다. |

## 전송 제한과 조회·소비 경계 후속 결정

2026-11-27 전체 코드베이스 검토에서 확인한 여덟 항목을 Q1~Q9로 나눠 설계를 합의하고, Q10에서 변경 범위·공개 검증 경계·리뷰 기준을 승인했다. 이 절의 번호는 이번 검토에 한정한다. 로컬 `HEAD`와 원격 `main`이 일치한 [`55cf69b`](https://github.com/mochafreddo/stock-scout/commit/55cf69bd9dedf72a9fc7c33033f21d9ed2559e66)를 리뷰 기준으로 삼는다. 독립 Codex 검토자 `gpt-6.2-astra` `high`로 설계와 최종 범위를 교차검토했다.

| 결정 | 반영 방향 | 공개 검증 경계 |
| --- | --- | --- |
| Q1 전송 후 예약 저장 실패 | GET 또는 POST를 시작한 뒤 실제 전송 시작 시각을 반영하는 예약 저장에 실패해 내구성을 확인할 수 없으면 `client.lock`을 남기고 `AUTH_STORAGE`를 반환한다. 복구 문서에는 같은 상태 디렉터리를 쓰는 프로세스가 모두 끝난 뒤 최소 1초와 확인된 공급자 대기를 충족하고 별도 승인을 받아 잠금을 해제하는 절차를 명시한다. 토큰 발급 결과 미확인은 기존 절차를 따른다. | 두 실제 CLI 프로세스에서 합성 HTTP·시계·저장 오류로 대조한다. 전송 전 저장 실패는 HTTP 0회와 해당 호출이 획득한 잠금 해제를 확인한다. 전송 후 저장 실패는 최초 CLI의 `AUTH_STORAGE`, 준비 점검의 잠금 관측, 후속 CLI의 추가 HTTP 0회를 함께 확인한다. 정상 저장에서는 공유 전송 간격을 확인한다. |
| Q2 공급자 대기 헤더 | 각 헤더의 초 값을 독립적으로 검사한다. 안전하게 표현할 수 있는 양수 값 중 가장 긴 대기를 먼저 공유 상태에 게시한다. 표현 범위를 넘은 값에 대한 오류와 `401`·`403`·대기 기록 저장 실패의 기존 우선순위를 유지한다. | 합성 HTTP 응답에서 어느 쪽 헤더가 범위를 넘든 유효한 다른 값이 다음 CLI에 적용되는지 확인한다. 유효 값 두 개, 범위 초과 값 하나만 있는 경우, 인증·권한 오류와 저장 실패를 대조한다. |
| Q3 Markdown 블록과 링크 경로 | 고정된 단일 파일 검사기를 유지한다. 제목과 링크가 단락·들여쓴 코드·HTML 블록·참조 정의의 경계를 공유하도록 하고 링크 목적지의 Markdown 이스케이프를 경로·앵커 검사 전에 해석한다. | 동일한 합성 문서로 `--docs`, staged, pre-push를 실행한다. 문단에 이어지는 들여쓴 깨진 링크, 빈 줄 뒤의 코드 예시, HTML 블록과 문단 안의 참조 정의처럼 보이는 텍스트, 괄호를 이스케이프한 정상·깨진 경로를 대조한다. 이전 여러 줄 제목과 앵커 검사도 확인한다. |
| Q4 토큰 발급 미확인 복구 | POST 전 상태 파일 교체 이후 디렉터리 동기화가 실패하면 `pending`이 남을 수 있음을 복구 문서에 기록한다. 다음 실행이 그 상태만으로 전송 여부를 판단할 수 있으리라 가정하지 않는다. 자동 복구와 재발급의 동작 변경을 보류한다. | 복구 문서를 상태 저장 순서와 기존 운영 절차에 대조한다. Q1의 미전송 대조에서 `pending`까지 원복됐다고 가정하지 않는다. |
| Q5 분봉 OHLC | 일봉의 정확한 십진수 비교를 분봉에도 적용한다. 시가 또는 종가가 저가~고가 범위를 벗어난 봉은 기존 행 검증에 따라 제외한다. 유효한 봉이 남으면 `partial`, 받은 봉이 모두 무효면 `RESPONSE_INVALID`를 반환한다. | 실제 CLI에서 일봉·분봉의 정상 경계값, 정상·무효 혼합, 전부 무효인 합성 응답을 대조한다. JSON의 누락 사유와 종료 코드를 확인한다. |
| Q6 세션 간 관계 | 개별 세션의 날짜·시각 구간 검증을 유지한다. 세션 간 순서와 비중첩은 검증 범위 밖이라고 문서에 명시한다. 공급자 계약에서 관계를 확인할 때까지 중첩을 일괄 거부하는 변경을 보류한다. | 현재 검증과 합성 검사 기대값에 문서를 대조한다. |
| Q7 전달 불가능한 계좌 커서 | 거래내역과 일반 종료 주문에서 NUL 또는 짝 없는 서로게이트가 포함돼 CLI 인수로 원문을 다시 전달할 수 없는 커서의 경우, 현재 페이지의 유효 행과 `hasNext: true`를 보존한다. `partial`과 별도 누락 사유를 반환하며 사용할 수 없는 커서와 문맥은 생략한다. 정상 불투명 커서의 원문과 기존 조건 주문의 커서 형식을 유지한다. | 실제 CLI에서 전달 불가능한 커서의 유효 행과 빈 페이지를 대조한다. 상태, `hasNext`, 누락 사유, 커서·문맥 생략을 확인한다. 정상 구두점과 유니코드가 있는 커서는 다음 CLI를 거쳐 모의 HTTP에 원문 그대로 전달하는지 확인한다. |
| Q8 일봉 소비 예제 | `error` 행에 안전한 오류 객체를, `not_queried` 행에 중단 사유를, 두 상태 모두에 빈 봉 배열을 요구한다. 출력에 포함하는 최상위·행별 오류에 같은 안전 검사를 적용한다. 정상 빈 결과와 가려진 정상 오류를 보존한다. | 실제 CLI의 합성 출력을 예제 stdin으로 전달한다. 정상 결과와 실패 사유 누락·예상 밖 오류 필드가 있는 결과의 stdout과 종료 코드를 대조한다. |
| Q9 예약 Dot 페이지 종료 | `candles` 도구 설명과 운영 안내에 기존 소비 지침을 반영한다. 첫 날짜 조회의 `source.before`를 포함해 같은 조회에서 이미 요청한 모든 경계를 오프셋과 전체 소수초를 반영한 실제 시각으로 비교한다. 같은 경계가 다시 나오면 후속 페이지 조회를 멈추고 확보 범위를 보고한다. | 루프백의 공개 `tools/list`와 기존 조회 동작을 확인한다. 설명 문구를 고정하는 테스트는 두지 않는다. [기존 후속 페이지 지침](toss-agent-usage.md#follow-up-pages) |

Q10의 변경 범위는 위 코드·회귀 검사·관련 문서다. Q4와 Q6은 문서 변경으로 한정한다. 코드 회귀는 수정 전 실패와 수정 후 통과를 같은 공개 경계에서 대조한다. 최종 변경분을 고정하고 기준 커밋부터 Standards·Spec 리뷰와 전체 합성 테스트, 타입·린트·문서·공백 검사를 수행한다. 실제 토스·계좌·비공개 터널·예약 Dot 운영, 사용자 훅 설치와 배포는 별도 범위다.
