고정한 실제 원문 세 건을 운영 코드의 공지 판단 함수에 각각 넣어 동일한 모델·설정으로 한 번씩 평가했다. 이 검사는 실제 구독 모델과 동일한 결과 검증 경로를 사용하지만 전체 일정 CLI 실행과는 별도다. 정답은 모델 호출 전에 별도 파일로 고정했고 모델에는 제공하지 않았다. 세 결과의 분류·적용일·변경 내용을 독립 정답과 비교하고 인용과 이유를 원문에서 직접 확인했다.

### 실제 전체 실행의 근거 연결 실패와 후속 변경

문자열 인용 방식의 첫 실제 전체 CLI는 62.844초에 `MODEL_OUTPUT`·빈 stdout·종료 코드 1로 끝났다. 모델 요청은 한 번, 실제 직렬화 요청은 115,519바이트였고 HTTP 200이었다. 관측 도구는 수신 SSE가 2MB를 넘으면 결과를 남기지 않는 경로와 읽기 오류를 숨기는 경로가 있어 첫 모델 제출값은 확보하지 못했다. 첫 실패의 구체적인 검증 조건을 소급 확정하지 않는다.

비공개 관측 도구만 수정하기 전에 2MB를 넘는 모의 SSE에서 기록 누락을 재현했고, 수정 후에는 같은 검사와 읽기 실패 뒤의 부분 결과·상태 보존을 확인했다. 제품의 모델·프롬프트·한도·근거 검증 조건은 바꾸지 않은 상태로 제출값 확보 목적의 진단 실행을 한 번 추가했다. 이 실행도 65.805초에 `MODEL_OUTPUT`·빈 stdout·종료 코드 1로 끝났다. 두 실행의 요청 SHA-256은 같았다. 진단 SSE는 2,046,840바이트, 출력 텍스트는 26,263바이트였으며 명시적 완료 뒤 제출값을 보존했다. 이는 관측 도구의 이전 상한이 이 크기의 응답을 남기지 못했음을 보여주며 첫 응답의 실제 크기를 측정한 결과는 아니다.

진단 제출값은 86개 묶음 전체를 포함했다. NYSE `110000956025`에서는 자식 `:3`에 있는 인용을 자식 `:4`에 연결했고, `110000942014:4`의 인용에서는 원문의 NBSP·연속 공백을 바꿨다. 정확한 근거 검사가 두 불일치를 거부한 것은 올바르며 검증 조건을 완화하지 않는다. 별도로 Nasdaq `ETA2026-60`·`ETA2026-59`는 테스트 전용 운영 안내를 정규장 범위 미확인으로 분류했다. 미래 실제 운영 개시일을 놓치지 말라는 지침을 모든 테스트 공지에 일반화했을 가능성이 있으며, 이는 제출 이유에 근거한 강한 정황이지 모델 내부 원인의 측정은 아니다.

이 사례를 근거로 문자열 복사를 코드의 구간 ID·원문 복원으로 옮기고, 실제 운영 개시와 테스트 전용 안내를 구분하도록 지침을 한정한다. 공개 출력·정확한 근거·전체 입력·한도·실패 계약은 유지한다. 유효하지만 의미상 부적절한 구간 선택은 여전히 실제 평가 대상이다. 앞선 표본 3/3과 로컬 검사 통과를 변경된 프로토콜의 검증으로 재사용하지 않는다.

### 구간 ID 방식의 Luna 평가와 다음 후보 선택

변경한 프로토콜의 고정 소스로 같은 실제 표본을 `gpt-6-luna`에서 각각 한 번 다시 평가했다. 기술·시세 장애, 미래 거래 확대, 추모 휴장의 판단과 적용일은 모두 독립 정답에 맞았고 코드가 복원한 인용을 원문에서 확인했다. 판단 함수 경과 시간은 각각 3.671초·3.051초·3.343초다. 이는 작은 표본 3/3의 단회 평가다.

같은 소스의 실제 전체 CLI는 64.426초에 `MODEL_OUTPUT`·빈 stdout·종료 코드 1로 끝났다. 모델 요청은 한 번, 실제 요청은 146,517바이트, HTTP 200·명시적 완료였다. 86개 결과는 모두 반환했지만 NYSE 5개 묶음에서 부모·자식 본문 15개의 근거를 빠뜨렸다. 따라서 근거 누락 검사의 거부는 올바르다. `ETA2026-56`도 작은 표본에서는 `future_effective`였으나 전체 입력에서는 실제 운영 변경을 알리지 않는 테스트 안내로 분류했다. 실제 본문에 명시된 운영 개시와 독립 정답에 맞지 않는 전체 입력의 판단이며 표본 통과를 전체 처리 품질로 확대할 수 없다.

사용자는 이 결과를 확인한 뒤 기존 SIWC 모델 목록에 있는 `gpt-6.1-sol`을 다음 검증 후보로 명시적으로 선택했다. 코드·프롬프트·근거 검사·한도는 바꾸지 않고 같은 실제 표본 세 건을 각각 한 번, 실제 전체 CLI를 한 번 검증한다. 이는 사용자가 선택한 별도 검증이며 런타임 자동 모델 대체가 아니다. 유료 API 전환은 추가하지 않는다.

### Sol의 독립 표본과 수집 단계 실패

이 조회는 연도 경계를 넘는 실제 돌발 휴장 공지를 아카이브에서 회수한 양성 대조다. 원문 HTML이나 단독 RPC 요청이 비어 있다는 이유로 아카이브 조회 불가능이라고 결론 내리지 않는다. 다만 모든 관련 카테고리·연도의 전수 수집, 갱신·철회 반영과 수집 종료 조건은 검증하지 않았다. 표시된 행 수만으로 누락이 없다고 판정하지 않는다.

[현재 상태](https://www.nasdaqtrader.com/Trader.aspx?id=MarketSystemStatus)는 조회 당일인 일요일에도 시스템 정상으로 표시됐다. [상태 검색](https://www.nasdaqtrader.com/Trader.aspx?id=MarketSystemStatusSearch)은 데이터 시작일을 2000-12-29로 안내하며, 빈 검색 결과의 의미를 해당 날짜의 시스템 정상으로 설명한다. 브라우저에서 시작일 `10/16/2026`, 종료일 `10/19/2026`, subject `All`, 시장 `The Nasdaq Stock Market`으로 실제 검색했을 때 10월 16일의 결과 9행을 받았다. 현재 상태나 이 검색 결과는 다음 월요일의 정규장 개장 시각을 검증한 결과가 아니다.

Nasdaq은 공개 RSS·아카이브·상태 검색을 수집 경로의 후보로 사용할 수 있다. 독립 HTTP RPC 구현이나 특정 SLA가 없다는 이유만으로 배제하지 않는다. 남은 조건은 필요한 공지 범위를 실제로 끝까지 수집하고, 별도 시간 변경 공지의 적용 날짜·시각과 후속 정정을 해석하여 연간 일정에 반영하는 검증이다. 이번 조사는 그 전체 경로의 성공을 입증하지 못했다.

## 재개 조건

1. 거래소별로 직전 완료 세션부터 현재 날짜와 다음 개장까지 필요한 변경 공지의 조회 범위를 정하고, 오래된 공지의 새 수정·철회와 미래 적용 공지도 그 범위에 포함되는지 확인한다.
2. NYSE 페이지 전수 조회 중 변경이 생길 때 누락·중복을 탐지할 수 있는지, 날짜 필터가 자식 공지 갱신을 어떻게 처리하는지 실제 응답으로 검증한다. Nasdaq의 공지 보존·검색 범위도 필요한 구간을 덮는지 확인한다.
3. 정상 시스템 상태와 일정 변경 없음의 의미를 구분하고, 조회 시점까지 필요한 공지가 반영됐다고 판단할 수 있는 공식 근거와 통신·해석 실패 조건을 기록한다. 반드시 특정 형식의 SLA가 있어야 한다는 새 요구사항을 추가하는 것은 아니다.
4. 이 근거를 확보한 뒤 CLI의 작은 수직 기능부터 구현한다. 미확인 공지, 거래소 간 불일치, 인접 연도 누락은 실패로 처리한다. 합의한 시간 경계·실행 도중 개장·고정 `--at` 검사를 CLI에서 수행한다.

## 검증 범위

이번 변경은 선행 조사와 기존 설계 합의의 문서화다. KIS·LLM 호출, 인증 파일 접근, Actions 설정 변경은 수행하지 않았다. 일정 CLI가 없으므로 일정 경계 모의 테스트와 해당 로직의 음성 대조는 수행하지 않았다. 기존 인증 CLI의 모의 테스트 통과를 일정 수집이나 장전 실연동 검증으로 대체하지 않는다.
