# 인증 상태 전환의 복구 인계

`AUTH_STATE_TRANSITION_REQUIRED`는 새 CLI가 구형 호출 예약 상태를 발견해 조회를 중단했다는 뜻입니다. 공급자가 인증을 거부했다는 증거가 아닙니다. 같은 상태에서 시장·계좌 조회나 예약 재실행을 반복하지 말고, 아래 전제를 확인한 뒤 복구 작업을 별도로 승인받으세요. 상태 필드와 오류별 처리의 기준은 [CLI 레퍼런스의 예약 상태와 복구](toss-cli.md#예약-상태와-복구)입니다. 이 문서는 실제 상태를 읽거나 바꾸는 승인이나 전환 명령을 제공하지 않습니다.

## 복구 전 확인과 승인

1. 같은 클라이언트와 보호 상태를 사용하는 구형·신형 실행기가 모두 종료됐는지 확인하세요. 외부 예약 실행기도 포함하며, 이후에는 새 버전만 실행되도록 준비해야 합니다. 실행 종료를 확인할 수 없다면 전환을 보류하세요.
2. 공급자가 요구한 대기를 모두 마쳤는지 확인하세요. 남은 대기 기록도 포함합니다. 구형 벽시계 마감만으로 시계 보정 전의 잔여 시간을 복원할 수 없습니다. 남은 대기를 확인할 수 없으면 전환과 조회를 보류하세요.
3. 실제 보호 상태의 읽기 대상·범위와 변경안을 구체화하고 각각 필요한 승인을 받으세요. 토큰이나 자격 증명 값을 채팅·명령 인수·로그에 넣지 마세요. 잠금과 대기 기록의 정리는 실행 종료·대기 완료 확인에 더해 별도 승인이 필요합니다.

## 승인된 변경의 범위

승인된 복구는 기존 [예약 규약 v2](toss-cli.md#예약-상태와-복구)에 맞춰 호출 예약 필드만 최소한으로 원자적 전환하는 작업입니다. 토큰·자격 증명·지문·만료 시각·발급 결과 미확인 표시(`pending`)·기본 계좌와 나머지 필드는 보존해야 합니다. 전환 대상과 현재 부팅·시계 기준을 확인한 변경안을 승인받은 뒤 적용하세요. 상태 삭제나 토큰 재발급으로 우회하지 마세요. `pending:true`는 이 전환으로 해소되지 않습니다.

손상된 상태의 `AUTH_STORAGE`, 저장된 부팅·시계 기준 불일치의 `CLOCK_UNCERTAIN`, 운영체제 시계 정보를 읽을 수 없어 발생한 `CLOCK_UNCERTAIN`은 구분해야 합니다. 마지막 경우에는 지원 환경과 읽기 권한을 복구해야 하며 상태를 다시 쓰는 것만으로 해결되지 않습니다. 오류 이름만으로 구형 상태 전환을 일괄 적용하지 마세요.

## 복구 후 연결 확인과 보고

복구를 마친 뒤 실제 조회가 승인된 범위 안에서 검증된 종목의 시장 조회 한 건으로 연결을 확인하세요. 예를 들어 승인된 종목의 `prices` 조회를 사용할 수 있습니다. 일반 조회는 토큰 발급과 로컬 상태 저장을 일으킬 수 있으므로 읽기 전용 점검으로 취급하지 마세요. 실패하면 해당 오류와 미확인 범위를 보고하고 같은 복구를 자동 반복하지 마세요.

시장 조회 한 건의 성공은 그 요청의 관측 결과입니다. 보유·미체결 주문 조회, 공급자의 다른 권한·IP 조건, 향후 예약 실행이나 dots의 실제 사용까지 검증됐다는 뜻은 아닙니다. 계좌 조회는 해당 승인 범위와 별도 결과로 확인하세요.

자료를 확보하지 못했다면 기본 보고는 자료 부족에 따른 종목별 판단 보류입니다. 예: “DEMO는 현재가를 확보하지 못해 판단을 보류했습니다. 전환 필요 오류 이후 보유·미체결 주문 조회를 중단했으며 복구 전제 확인이 필요합니다.” 관망을 권고하려면 조회 실패와 별개의 투자 근거를 제시해야 합니다.

## 합성 확인과 실제 관측의 구분

[에이전트 합성 시나리오](toss-agent-usage.md#exercise-a-transition-required-stop)는 실제 CLI의 전환 필요 오류·JSON·stderr·종료 코드와 기존 보호 파일 보존·HTTP 전송 부재를 확인합니다. 실제 자격 증명이나 상태를 복사하지 않습니다. 일반 조회의 일시적 잠금 때문에 디렉터리 변경 시각은 보존 검사에서 제외하며, 읽기에 따른 접근 시각도 제외합니다.

이 시나리오 통과는 실제 복구·토스 조회·dots 실행의 완료가 아닙니다. 실제 검증을 하지 않은 경우에는 그 사실과 사유를 기록하고, 실행기 종료·대기 완료 확인 및 대상별 상태 열람·변경·조회 승인을 재개 조건으로 남기세요. 소비 에이전트가 모든 실제 실행에서 안내를 준수하는지도 별도 관측이 필요합니다.
