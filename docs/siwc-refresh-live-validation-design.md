# 실제 구독 인증 갱신·재사용 검증 설계

2026-10-21 시작한 `grill-with-docs` 인터뷰의 합의 기록이다. 대상은 [#253](https://github.com/mochafreddo/stock-scout/issues/253)이며 상위 요구사항은 [#237](https://github.com/mochafreddo/stock-scout/issues/237), 선행 구현은 [#252](https://github.com/mochafreddo/stock-scout/issues/252)다. 기존 [자동 갱신 설계](siwc-refresh-design.md)와 ADR 0008의 인증 정책을 유지한다. 인터뷰 시작 HEAD는 `bbaa157ecc66b7b8313c57aecbf29f8dc146cc34`이며 시작 시 Git 작업 트리에 변경은 없었다.

## 합의한 정책

사용자는 Q1에서 기존 공용 인증 경로를 사용하는 최소 구독 연결 확인 명령을 이번 범위에 추가하는 추천안을 수락했다. 실행 전 갱신을 거쳐 모델 목록을 읽는 명령으로 한정한다. 첫 프로세스의 갱신과 다음 별도 프로세스의 재사용을 확인하며, 추론·검색 성공은 별도 검증으로 남긴다. 별도 갱신 명령은 추가하지 않는다.

사용자는 Q2에서 인증 메타데이터로 자연스러운 갱신 가능 시점을 확인하고 아직 이르면 재개 시각을 기록한 뒤 중단하는 추천안을 수락했다. 만료 시각을 조작하지 않으며 장시간 대기·반복 조회·예약 실행은 추가하지 않는다. 실제 실행 중 오류가 발생하면 해당 시도의 증거와 재개 조건을 남긴다.

사용자는 Q3에서 HTTP 성공과 정상적인 모델 목록 응답을 연결 확인의 성공 기준으로 삼는 추천안을 수락했다. 표시 가능한 모델이 없는 정상 응답도 인증된 조회 성공으로 기록하되 사용 가능한 모델이 없음을 별도 표시한다. 목록 조회 성공은 추론 실행 가능성을 입증하지 않는다. [공식 모델·추론 문서](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)는 구독 액세스 토큰을 사용한 `GET /v1/models`와 `models` 배열, 표시 대상의 `visibility: "list"`를 안내한다.

사용자는 Q4에서 공용 인증 경로에 비밀 값 없는 관측을 추가해 실제 요청 횟수와 저장·재사용 결과를 기록하는 추천안을 수락했다. 첫 프로세스에서 갱신 요청 1회와 응답 검증·저장 성공을, 다음 별도 프로세스에서 갱신 요청 0회와 저장된 인증의 재사용을 확인한다. 토큰 비교는 메모리에서 수행하고 결과만 남긴다. 토큰 원문·해시·계정 식별자·개인 보관 경로는 공유 증거에 넣지 않는다.

사용자는 Q5에서 모델 목록 조회를 15초 제한으로 한 번만 요청하는 추천안을 수락했다. 조회에 실패해도 이미 저장한 갱신 인증은 유지한다. 자동 재시도·재로그인·유료 API 전환은 없으며 갱신·저장 성공과 목록 조회 실패를 각각 기록해 재개할 수 있게 한다.

## 최종 합의와 작업 상태

사용자는 Q6에서 최종 설계를 수락하고 `implement`를 요청했다. 기존 SIWC CLI에 `check <인증 보관 디렉터리>`를 추가한다. 공용 인증 경로와 모델 목록 조회를 사용하며 JSON으로 인증 갱신·재사용 결과와 표시 가능한 모델 목록을 출력한다. 정상 조회는 종료 코드 0, 오류는 1로 구분하고 실패 전 완료한 인증 단계도 남긴다.

자연스러운 갱신 시점에 첫 프로세스의 갱신·저장·조회 성공을 확인하고 곧바로 별도 프로세스에서 중복 갱신 없는 재사용·조회 성공을 확인한다. 아직 갱신할 수 없으면 재개 시각을 기록한다. 공용 테스트 경계는 CLI 입력·stdout·stderr·종료 코드, 인증 파일 상태, 외부 요청이다. 빈 모델 목록·잘못된 응답·시간 초과·갱신 후 조회 실패·별도 프로세스 재사용을 모의 검사하며 새 위험 로직에는 음성 대조를 남긴다.

리뷰는 기존 기준 `21a40607ac59638375bbca88c7b97505c4e48cd4`를 유지하고 #253에서 추가하는 변경과 증거를 Standards·Spec 두 축으로 검토한다. 실제 동시 회전·응답 유실 등 미수행 조건과 기존 제품 차단을 유지한다. 이번 실행 요청에는 구현·검증과 현재 브랜치 커밋이 포함된다. 원격 이슈 변경·푸시는 별도 요청 범위다. 실제 실행 결과와 미완료 조건은 검증 기록으로 구분한다.
