# KIS 인증과 복구

관측 CLI는 `KIS_APP_KEY`와 `KIS_APP_SECRET`을 프로세스 환경에서 읽습니다. `.env`를 자동으로 읽지 않으며 `KIS_ACCESS_TOKEN`은 사용하지 않습니다. 기존 환경 파일의 값은 수정하지 마세요. 조회 전 인증은 [#247](https://github.com/mochafreddo/stock-scout/issues/247), 조회 중 만료 복구는 [#248](https://github.com/mochafreddo/stock-scout/issues/248), 공식 자료 조사와 운영 가정은 [#246](https://github.com/mochafreddo/stock-scout/issues/246)에 있습니다.

## 실행과 저장

macOS의 `~/Library/Caches/stock-scout/`를 사용합니다. 캐시 경로를 동기화 영역이나 저장소로 연결하지 마세요. 디렉터리는 현재 사용자 소유의 700, 파일은 600이어야 합니다. 심볼릭 링크와 파일의 하드 링크는 거부합니다. 안전하지 않은 권한을 자동으로 완화하거나 수정하지 않습니다.

| 경로 | 내용 |
| --- | --- |
| `token.json` | 토큰 하나, 서버 만료 일시, 앱 키·시크릿 조합의 SHA-256 해시. 원문 앱 키·시크릿은 저장하지 않습니다. |
| `issuance.json` | `kind: initial` 또는 `attempt`와 밀리초 단위 시각 `at`. 초기 대기와 실제 발급 시도를 구분합니다. |
| `issuance.lock/` | 프로세스 간 발급 잠금. 충돌하면 기다리지 않고 실패합니다. |
| `*.json.tmp` | 파일 동기화 후 원자적 교체에 사용하는 임시 파일. 비정상 종료 뒤 남으면 수동 확인이 필요합니다. |

발급 기록이 없으면 현재 시각을 안전하게 저장하고 네트워크 요청 없이 `AUTH_COOLDOWN`으로 종료합니다. 최소 300초 뒤 같은 명령을 다시 실행하세요. 기록 삭제도 같은 초기 대기를 적용하므로 캐시를 비우는 방식으로 제한을 우회하지 마세요.

유효한 토큰은 실행 사이에 재사용합니다. 새 발급이 필요하면 잠금 획득 후 최신 캐시를 다시 확인하고, 발급 요청 전에 시각을 저장합니다. 발급 실패와 기존 토큰 재반환도 모두 시도로 계산합니다. 앱 키나 시크릿을 바꿔도 공통 잠금과 최소 300초 간격은 유지됩니다. 새 토큰 저장에 실패하면 메모리 토큰만으로 조회하지 않습니다.

서버의 `access_token_token_expired`는 KST(UTC+09:00)로 해석합니다. 이는 승인된 운영 가정이며 공식 시간대 계약을 입증한 사실이 아닙니다. 가정이 틀리면 만료 토큰 재사용이나 조기 발급이 생길 수 있으며 반대 근거가 확보되면 재검토합니다. `expires_in`은 사용하지 않습니다. 만료까지 60초 이하인 토큰은 발급 성공이나 재사용으로 인정하지 않습니다.

## 실패 뒤 복구

stderr의 JSON에는 고정 오류 코드가 있으며 일부 오류에 `retryAfterSeconds`와 `guidance`가 추가됩니다. stdout에는 성공 관측을 출력하지 않습니다. 원문 응답·예외·인증 헤더를 출력하거나 공유하지 마세요.

- `AUTH_COOLDOWN`: 남은 초 이상 지난 뒤 다시 실행하세요. 기록이 미래라면 시스템 시각을 확인하세요. 기록 시각에서 300초 뒤까지 발급을 차단하며 기록을 자동으로 초기화하지 않습니다.
- `AUTH_LOCKED`: 이 CLI의 모든 실행이 끝났는지 확인하세요. PID 부재만으로 종료를 확정하지 마세요. 종료 확인 뒤 `issuance.lock/`만 제거하세요. `token.json`과 `issuance.json`은 보존하세요.
- `AUTH_RECORD`: 모든 CLI 실행을 종료한 뒤 손상된 `issuance.json`만 제거하세요. 토큰은 보존하세요. 다음 실행은 새 초기 기록을 저장하고 다시 300초 대기합니다. 먼 미래 기록의 수동 복구도 같은 절차를 적용하세요.
- `AUTH_STORAGE`: 소유자·권한·링크·디스크 상태를 확인하세요. 남은 임시 파일이 있으면 모든 CLI 종료를 확인한 뒤 해당 임시 파일만 제거하세요. 토큰·발급 기록을 함께 지우지 마세요. 비밀 파일을 진단 자료로 복사하지 마세요.
- `AUTH_FAILED`: 기존 자격 증명과 서비스 상태를 확인하세요. 발급 실패를 자동 반복하지 않으며 다음 시도에도 공통 간격을 적용합니다.

## 조회 중 명시적 만료 복구

네 관측 모드 모두 조회 오류의 구조화된 코드가 정확히 `EGW00123`일 때 한 번만 인증 복구와 재조회를 시도합니다. HTTP 비정상 상태에서도 오류 본문을 확인하지만, HTTP 상태나 메시지의 ‘만료’라는 문구만으로 복구하지 않습니다. 오류 응답에 정상 형태의 데이터가 함께 있어도 성공으로 출력하지 않습니다. HTTP 200·`rt_cd: "0"`의 성공 표시와 명시적 만료 코드가 충돌하면 복구 없이 실패합니다.

복구 잠금 안에서 최신 캐시를 다시 확인하며, 거절된 토큰과 현재 자격 증명에 연결된 캐시 토큰이 일치할 때만 무효화합니다. 다른 실행이 저장한 현재 자격 증명의 유효한 토큰은 보존해 재조회에 사용합니다. 이 경우도 한 번의 복구 상한에 포함합니다. 새 발급이 필요하면 기존 300초 간격을 지키며 대기하거나 우회하지 않습니다. 제한에 걸려도 거절된 토큰의 무효화는 유지하고 발급 기록은 보존합니다.

복구 발급이 방금 거절된 것과 같은 토큰을 반환하면 미래 만료 일시가 있어도 저장·재조회하지 않고 실패합니다. 두 번째 조회도 명시적 만료라면 해당 토큰을 같은 일치 조건으로 무효화한 뒤 추가 발급 없이 실패합니다. 다른 인증·통신 오류에는 자동 발급이나 토큰 무효화를 수행하지 않습니다. 발급 API 자체의 실패도 조회 복구를 다시 시작하지 않습니다.

무효·미발견 토큰 `EGW00121`·`EGW00122`, 앱 키·시크릿 오류, Bearer 유형 오류 `EGW00205`, 인가 코드·세션 키 만료, 공급자 라우팅·시간 초과, 응답 없는 통신 실패는 복구 대상이 아닙니다. 코드 누락·미등록 코드·해석 불가능한 응답도 만료로 추정하지 않습니다. 잠금·무효화·발급·저장·재조회 중 실패하면 stdout에 부분 결과를 출력하지 않습니다.

인증 성공과 관측 JSON은 장전 데이터 기준 세션·정규장 범위·종목 유형 검증을 뜻하지 않습니다. 부모 [#243](https://github.com/mochafreddo/stock-scout/issues/243)과 [#239](https://github.com/mochafreddo/stock-scout/issues/239)의 미충족 조건은 유지합니다. 조건부 무효화의 설계 근거는 [ADR](adr/0002-kis-expired-token-invalidation.md)에 있습니다.

## 검증 범위

CLI 프로세스 테스트는 임시 홈·캐시와 통제된 시각을 사용하며 외부 HTTP를 대체합니다. 첫 실행, 300초·60초 경계, 시간대 독립성, 자격 증명 변경, 손상·권한·저장 실패, 동시 실행과 잠금 재확인을 검사합니다. 실제 KIS와 별개이며 운영 가정의 공식 입증을 대신하지 않습니다.

2026-10-18 #247의 로컬 검증에서 형식·린트·타입 검사와 전체 테스트 28개가 통과했습니다. mutation-probe로 캐시 만료 여유 제거, 공통 간격 우회, 발급 전 기록 제거, 잠금 제거, 조회 전 저장 제거, 비밀 출력, 보존 토큰의 초기 대기 우회 등 7개 변이를 각각 탐지했습니다. 비밀 출력의 첫 대조는 JSON 해석 오류로 실패해 의도한 실패 유형을 확인하지 못했습니다. 명시적 비밀 검사를 JSON 해석 전에 배치한 뒤 최종 전체 검사와 7개 대조를 다시 수행했습니다.

같은 날 19:53:56 KST의 실제 첫 실행은 요청 없이 초기 기록을 저장하고 종료 코드 1·300초 대기를 반환했습니다. 19:59:06 KST에 기존 자격 증명으로 실제 발급 1회·NAS 거래량 조회 1회를 수행했고 종료 코드 0·100행 관측을 받았습니다. 바로 다음 별도 프로세스는 발급 0회·조회 1회로 성공했으며 토큰·발급 기록의 바이트가 유지됐습니다. 실제 캐시의 디렉터리 700·파일 600과 원문 앱 키·시크릿 미저장도 확인했습니다. 인증 원문이나 헤더는 증거로 저장하지 않았습니다.

실제 서버 만료 일시를 KST로 해석한 결과는 발급 직후 약 86,399초의 여유였고 재사용 조회가 성공했습니다. 이는 이번 응답에 적용한 가정과 재사용의 확인이며 공식 시간대 계약의 입증이나 실제 만료 경계까지 기다린 검증은 아닙니다. 실제 조회는 NAS 거래량 한 모드만 수행했고 모든 모드의 공통 인증은 모의 검사로 확인했습니다. 의도적인 잘못된 자격 증명 요청·실제 동시 발급·실제 토큰 만료는 재현하지 않았습니다. 두 관측 모두 `validation: unverified`, `dataSession: null`을 유지했으며 장전 데이터 의미와 #248의 조회 중 만료 복구는 미검증 범위로 남습니다.

### #248의 로컬 복구 검증

2026-10-18 조회 중 만료 복구를 추가한 뒤 형식·린트·타입 검사와 전체 테스트 43개가 통과했습니다. 새 복구 검사 12개는 네 관측 모드, HTTP 비정상 상태의 구조화된 만료, 정상 형태의 데이터가 포함된 오류, 복구 금지 오류, 300초 경계, 두 번째 만료, 같은 토큰 재반환, 잠금·무효화·저장 실패와 비밀 비출력을 확인했습니다. 별도 CLI 프로세스가 먼저 갱신한 토큰을 다른 실행이 지우지 않고 발급 없이 재조회하는 경우도 모의 HTTP와 임시 캐시로 확인했습니다.

최초 복구 검사가 실패한 뒤 구현으로 통과하는 것을 확인했습니다. mutation-probe의 최종 대조에서는 만료 코드 부분 일치 허용, 비정상 HTTP 본문 확인 생략, 성공·만료 충돌 허용, 세 번째 조회 허용, 무효화 생략, 자격 증명 비교 생략, 토큰 값 비교 생략, 300초 제한 우회, 거절된 토큰 재반환 허용, 성공 JSON의 토큰 출력 등 10개 변이를 모두 탐지했습니다. 첫 대조의 자격 증명 비교 생략은 잘못 삭제된 파일을 읽다가 파일 없음 오류가 발생해 의도한 단언 실패로 인정하지 않았습니다. 파일 보존을 먼저 단언하도록 보강하고 전체 테스트와 10개 대조를 다시 수행했습니다.

이 검증은 외부 HTTP와 시각을 대체한 로컬 검사입니다. 이번 작업에서 실제 KIS 호출이나 실제 토큰 만료 복구는 수행하지 않았습니다. 실제 만료까지 기다려 서버의 오류·재발급·재조회 조합을 재현하지 못했으므로 실연동 복구는 미검증입니다. 앞선 #247의 실제 발급·재사용 성공을 이 복구의 실연동 근거로 확대하지 마세요. 합의한 완료 조건에 따라 이 한계를 공개하며 시장 데이터와 장전 지원 검증의 미충족 상태는 유지합니다.
